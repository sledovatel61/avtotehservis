# Агент 01 — пять концепций визитки «АвтоТехСервис»

Папка агента 01. Внутри — пять разных концепций визитки 90×50 мм, каждая с лицевой и
оборотной стороной, коллаж для быстрого просмотра, PDF на предварительный отбор и
скрипты, которыми всё это собрано.

Ничего не отправлено в печать и не передано в типографию: это материал для отбора.

## Что где лежит

```
concepts/
  01-nochnoy-ceh/     front.svg front.png front-300.png front.json  back.*  …
  02-smeta/
  03-mishen/
  04-svetlaya/
  05-dva-podyomnika/
collage/
  collage-01.png      3300×4050, фон #0B1410, пять пар «лицо / оборот»
  collage-01.jpg      то же, 706 КБ
print/
  card-01-nochnoy-ceh.pdf  … card-01-dva-podyomnika.pdf   по одной концепции
  card-01-all-concepts.pdf                                сводный, 10 страниц
notes.md              идеи концепций в трёх-четырёх строках
scripts/              сборка, проверки, PDF, коллаж
  report.md           вывод самопроверки последнего прогона
```

В каждой папке концепции:

* `front.svg` / `back.svg` — рабочий холст **96×56 мм** (готовая карточка 90×50 плюс
  вылеты по 3 мм), текст переведён в кривые;
* `front.png` / `back.png` — 600 dpi, **2268×1323 px** (96×56 мм, с вылетами);
* `front-300.png` / `back-300.png` — 300 dpi, 1134×662 px, для просмотра и для чата;
* `front.json` / `back.json` — паспорт макета: все строки с кеглем, цветом, координатами
  и контрастом, список QR и габариты графики. Из него работает вся автопроверка.

## Как пересобрать

```bash
cd scripts
npm install          # один раз
node build.mjs                 # все пять концепций
node build.mjs 03-mishen       # только одну
node check.mjs                 # гейт: безопасная зона, кегли, контраст, QR, пересечения
WARN=1 node check.mjs          # то же плюс предупреждения о слишком тесных зазорах
node verify.mjs                # факты, палитра, файлы, QR декодером → scripts/report.md
node pdf.mjs                   # print/*.pdf
node collage.mjs               # collage/collage-01.png и .jpg
```

Рендер — `@resvg/resvg-js` с локальными `site/public/fonts/*.woff2`, без сети и без
системных шрифтов. Никакого headless-браузера, никакой генерации картинки нейросетью:
всё, что видно на макетах, нарисовано кодом из текста и геометрии.

## Где задание расходится с сайтом

По правилу «расходится — прав код сайта» решал в пользу кода. Все расхождения
перечислены, чтобы решения можно было перепроверить.

1. **Телефоны.** В задании основной номер `928 906-57-00`, а `58-47` назван
   запрещённым. В `settings.ts` (и в `contacts.astro`) всё наоборот: основной —
   `+7 (951) 826-98-39`, он же Telegram, а `+7 (951) 826-58-47` — второй мобильный,
   который владелец подтвердил 17.11.2026. Взял сайт: основной `826-98-39`,
   городской `229-19-50`, номера `928` нет ни в одном файле.
2. **Пометка Telegram.** Требование «951-й только с пометкой Telegram» выросло из той же
   ошибочной посылки. Раз `826-98-39` — основной телефон сайта, на лицевой стороне он
   стоит как телефон (в четырёх концепциях) или как телефон с подписью «запись»
   (в 05). Отдельной строкой без роли он не появляется. На обороте, где рядом стоит
   городской, он всегда подписан «Telegram».
3. **Знак.** В задании знак описан как «круглая мишень». Фактический `logo.svg` —
   суперкар в скруглённом щите с латунной линией под ним (viewBox 0 0 72 44).
   Не перерисовывал и не «улучшал»: печатная версия знака собрана из того же файла,
   в трёх вариантах — `light` (для тёмного фона), `plate` (щит как плашка) и `bare`
   (только линии машины).
4. **Название пятой концепции.** В задании подсказка «два бокса с подъёмниками».
   На сайте (`about.astro`) сказано точнее: «Рабочий пост на два подъёмника», а на
   фото — две машины в боксах одного поста. Поэтому концепция называется
   **«Два подъёмника»**, а на лицевой стороне стоит строка «ДВА ПОДЪЁМНИКА».
5. **Размер.** В задании в одном месте 300 dpi, в другом «2268×1322». 96×56 мм при
   600 dpi — это 2267,7×1322,8 px, то есть 2268×1323. Сделал 600 dpi (запас для
   типографии), 300 dpi лежит отдельными файлами. Расхождение на пиксель — только
   округление.

## Печать

* Готовый размер 90×50 мм горизонтально, рабочий холст 96×56 мм (вылеты +3 мм).
* Безопасная зона 4 мм от реза: минимальный фактический отступ текста — 4,04 мм от линии реза (7,04 мм от края холста).
* Мелкий текст — от 6 pt (в основном 6,4–7), телефоны — от 8 pt (фактически 8,0–10,2).
* Текст в кривых, шрифтов в PDF не встроено вовсе, прозрачности — через `/ExtGState`.
* Фон `#0B1410` в CMYK ориентировочно **60/40/40/100**. Это почти «богатый чёрный»
  без плотной подложки: при печати на мелованной бумаге просите не экономить на
  краске, иначе фон уйдёт в зелень. Светлые концепции (02, 04) печатаются в один
  прогон, фон `#F4EFE6` — 0/3/6/0.
* Акцент — один на сторону, как в задании: на тёмном фоне `#E0A96D` (brass) или
  `#C87F45` (copper), на светлом — `#9A5B2C` (copperDark). В итоговых макетах хватило
  двух: `#E0A96D` и `#9A5B2C`.
* PDF (`print/`) — вспомогательный: страницы уже с вылетами, на сводных листах
  добавлены уголки реза. Это не файл для типографии, а способ проверить размеры.

## Проверка

Автоматика (`check.mjs` + `verify.mjs`) читает паспорта макетов и сами PNG. Последний
прогон — `scripts/report.md`, итог «всё чисто». Ручная таблица по пунктам задания:

| Пункт | Да / нет | Чем подтверждается |
|---|---|---|
| 1. Телефоны и адрес совпадают с сайтом посимвольно | да | `verify.mjs` вытаскивает все строки вида «+7 (…)» из десяти макетов: ровно два номера, оба из `settings.ts`; «928» не встречается ни разу |
| 2. Факты не выдуманы (город, адрес, ориентир, часы, сайт, почта, юрлицо) | да | те же строки сверяются с `DEFAULTS`; `ФОРБИДДЕН`-список из `content.mjs` (22 позиции: «дёшево», «лучший», «гарантия качества» и т. п.) — ноль совпадений |
| 3. QR читается и ведёт на сайт | да | jsQR по PNG 600 dpi: 5 из 5 сторон читаются, содержимое `https://ats-rostov.ru`; сторона кода 12,0–12,4 мм, модуль ≥ 0,4 мм, тихая зона 4 модуля |
| 4. Запрещённых слов и чужих брендов нет | да | тот же список + проверка на слова брендов из задания; на макетах нет ни логотипов, ни фото машин, ни номеров авто |
| 5. Кегли: мелкий ≥ 6 pt, телефоны ≥ 8 pt | да | пересчёт каждой строки из паспорта: минимум 6,0 pt, телефоны 8,0–10,2 pt |
| 6. Текст в безопасной зоне 4 мм | да | габариты каждого блока из паспорта: минимальный отступ от линии реза 4,04 мм, от края холста 7,04 мм |
| 7. Контраст ≥ 4,5:1 | да | расчёт WCAG по каждому тексту с учётом прозрачности: минимум 4,69:1 (телефон `#9A5B2C` на `#F4EFE6` в 02 и 04), следующий — 8,97:1 |
| 8. Только два шрифта и палитра сайта | да | в SVG нет `<text>`, весь текст в кривых; начертания — Unbounded 600 и Golos Text 400/500/700 из `fonts.css`; все fill/stroke сверены с `tokens.css` — 7 цветов, ни одного чужого |
| 9. Концепции различаются композицией, а не цветом | да | разные сетки: 01 — знак слева + строка названия; 02 — бланк с выносками; 03 — знак во весь край + узкая колонка; 04 — воздух и две линейки; 05 — две колонны и мерная стойка. Две тёмные, две светлые, одна бланковая — цвета тоже разные, но различие не в них |
| 10. Коллаж читается | да | 3300×4050, пары в масштабе 1:1 по отношению друг к другу, подписи Unbounded 36 px и Golos 26 px, шапка и дата, без теней и наклонов; JPG 706 КБ |

Дополнительно: `check.mjs` попарно проверяет пересечения «текст × текст», «текст ×
графика», «текст × QR» — 0 нарушений на 20 сторонах. Предупреждения о зазоре меньше
1 мм (`WARN=1`) на финальном прогоне тоже пусты.

## Итог: пять названий

1. **Ночной цех** — тёмный фон, крупный знак, латунная линия, название в строку.
2. **Смета** — бланк заказ-наряда с подписями и выносками.
3. **Мишень** — знак обрезан краем, текст в узкой колонке.
4. **Светлая** — слоновая кость, воздух, две тонкие линейки.
5. **Два подъёмника** — две колонны как два поста, между ними мерная стойка.

## Какая сильнее и почему

**01 «Ночной цех».** Она лучше всех решает задачу визитки: за полсекунды видно, кто это
и как позвонить, при этом карточка выглядит продолжением сайта, а не отдельной
самодеятельностью. Знак работает как знак, название — как название, телефон не спорит
с ними за внимание, а тёмный фон с латунью даёт ту самую «вывеску на Портовой»,
которую заказчик уже выбрал для сайта. Плюс она самая устойчивая к типографии: текст
в кривых, один акцент, ровные зазоры, ничего не зависит от точности приводки.

**02 «Смета»** — вторая по силе, но по другой причине: она не про красоту, а про
работу. Если визитки будут лежать на стойке и их будут брать люди, приехавшие за
ремонтом, бланк честнее глянца.

**05 «Два подъёмника»** — самая интересная, но требует доводки: идея читается на
втором взгляде, а не на первом.

## Что дорабатывать

* **01** — попробовать вариант с названием в две строки под более крупный знак; проверить
  латунную линию на вылете, чтобы при сдвиге реза она не «обрывалась» заметно.
* **02** — сейчас самая плотная по тексту: на печати стоит проверить пунктирные выноски
  при 6 pt, они могут «замылиться»; возможно, убрать строку «РАБОТЫ» на лицевой.
* **03** — обрезка знака зависит от точности реза: при сдвиге на 1 мм меняется вся
  композиция. Нужен вариант, где обрезка гарантированно попадает в безопасное поле.
* **04** — самая спокойная, но и самая «никакая» на столе среди других визиток:
  можно добавить один графический жест (например, ту же латунную линию, но тонкую).
* **05** — довести мерную стойку: сейчас риски через 1,2 мм, при печати часть может
  слиться; проверить, читается ли список работ на обороте при 6,6 pt.
* Всем — живой прогон на реальной бумаге (меловка 300 г, матовая ламинация) и проверка
  QR камерой телефона уже с напечатанного листа, а не с PNG.

## Ограничения этого прогона

* Ветка. Задание просило ветку `agent-01/cards`, но сессия закреплена за веткой
  `arena/653a5683-avtotehservis`: переключаться на другие ветки здесь нельзя.
  Коммит и пуш сделаны в неё, папка та же — `agents/agent-01/cards/`.
* PDF собран своим минимальным писателем (`scripts/lib/pdfwrite.mjs`): resvg-js v2
  не умеет PDF. Писатель понимает M/L/C/Q/A/Z, заливку, обводку, прозрачность и
  групповые трансформации — этого хватает, потому что весь текст уже в кривых.
* Проверка — автоматическая плюс просмотр глазами. Свежий взгляд человека, который
  не видел макетов, всё равно нужен: автоматика не ловит «некрасиво».
