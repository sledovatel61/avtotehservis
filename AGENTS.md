# AGENTS.md — как работать в этом репозитории

Единый вход для любого агента и любого нового чата. Прочитай целиком до первой команды:
здесь то, что иначе выясняется ценой целого круга. **Владелец — не программист: §13
обязателен к исполнению в каждом ответе, а не «по желанию».** Актуальное состояние проекта —
`docs/backlog.md`, история заданий — `prompts/`, отчёты приёмки — `docs/reports/`.

---

## 1. Что это

Сайт автосервиса «АвтоТехСервис» (Ростов-на-Дону, ул. Портовая, 439). Не мокап и не демо:
боевой домен, живые заявки, реальная мастерская для владельца.

| Что | Где |
|---|---|
| Боевой сайт | `https://ats-rostov.ru` (GitHub Pages, HTTPS включён) |
| Превью | `https://sledovatel61.github.io/avtotehservis/` — **единственное превью**, закрыто `robots.txt` от индексации |
| Мастерская владельца | `/manage/` — фото работ, цены, отзывы, статьи |
| Прослойка заявок | `https://ats-leads.ats439.workers.dev` (Cloudflare Worker, `relay/`), проверка: `/health` |
| Рабочая ветка | `preview/github-pages` — деплой в Pages идёт с неё |

Стек: **Astro 5, `output: 'server'`** + SQLite (Node, локально/SSR) → статический экспорт
(`scripts/export-pages.mjs`) → GitHub Pages. Заявки: форма → Worker → Telegram + почта.
Контент работ, цен, отзывов и статей — **файлы в `site/content/*.json`**, правятся из
`/manage/` через GitHub API (коммит браузером). Это не «временное решение» — это
единственная работающая схема на GitHub Pages, см. §6.

## 2. Первые пять минут

```bash
git fetch origin
# Сессионная ветка Arena создаётся от main, а сайт живёт в preview/github-pages.
# Поэтому первым делом подтянуть превью в свою ветку — fast-forward, без merge-коммита:
git merge --ff-only origin/preview/github-pages
# Дальше работать в отдельном worktree, репозиторий держать чистым:
git worktree add -f /tmp/wtN origin/preview/github-pages
cd /tmp/wtN/site && npm ci
```

- Ветку создавать **всегда от `origin/preview/github-pages`**, не от `main`.
- PR — **всегда в `preview/github-pages`**.
- Перед задачей прочитать: `docs/backlog.md` (что сейчас важно), свой файл задания в
  `prompts/`, и раздел §8 (DoD), чтобы не переделывать.

---

## 3. Ветки, PR, git

| Правило | Почему |
|---|---|
| `git merge --ff-only origin/preview/github-pages` в начале работы | иначе ветка «отстала» и PR тащит лишнее |
| `git reset --hard` в чужой/агентской ветке **запрещён** | уничтожает работу другого агента |
| `git push --force` **запрещён** | то же |
| `main` не трогать | это архив ранних этапов, сайт живёт в `preview/github-pages` |
| Свой PR не мержить | решение за оркестратором |
| Конфликт в общем файле (`Base.astro`, `export-pages.mjs`, `pages.yml`) — не «побеждать», а сообщить | владелец файла назначается в брифе круга |
| Один PR = одна тема | иначе откат невозможен |

Ветки агентов называются `agent/<круг>-<тема>`, ветки сессий Arena — `arena/<id>-avtotehservis`.
Не переименовывать ветку, в которой работаешь.

## 4. Кто есть кто

| Агент | Роль | Зона |
|---|---|---|
| **А5** | сайт | страницы, вёрстка, SEO, аналитика, клиентские скрипты |
| **А7** | мастерская и админка | `site/public/manage/**`, `site/src/pages/admin/**`, `github.js` |
| **А10** | данные, схема, гейты, экспорт | `site/content/**`, `src/shared/*-schema.ts`, `src/server/*-store.ts`, `scripts/export-pages.mjs`, `scripts/check-*.mjs`, `middleware.ts` |
| **А11** | воркер заявок | `relay/**` (контракт `/leads`, `/reviews`, лимиты, тексты уведомлений) |
| **А12** | приёмка | ничего не правит, проверяет и пишет отчёт |

- **Новые агенты не заводятся.** Если работы больше, чем ролей — делить на этапы, а не
  добавлять участников.
- А6 недоступен, A13–A15 отменены.
- Оркестратор — человек + агент в чате: выдаёт задания файлами в `prompts/`, проверяет
  фактическое состояние, мержит.

## 6. Почему контент — файлы, а не база

На GitHub Pages **нет серверного рантайма**: `/admin/**` — SSR-страницы, в статику они не
попадают вовсе, а SQLite создаётся временно внутри `export-pages.mjs` (`migrate.ts` +
`seed.ts` во временном каталоге) и умирает вместе со сборкой. Всё, что сохранено через
`INSERT INTO …` из админки, **на боевой сайт не попадёт никогда**.

Поэтому:

- источник истины — `site/content/*.json`;
- публикация = коммит через GitHub API из `/manage/` (fine-grained token, Contents: write);
- сборка 1–3 минуты, потом контент на сайте;
- сид, миграции и таблицы **не удалять**: они нужны локальному SSR и тестам;
- `/admin/cases`, `/admin/reviews`, `/admin/news` → **301** в `/manage/` (см. `middleware.ts`).

## 7. Гейты (что нельзя ломать)

| Гейт | Что проверяет |
|---|---|
| `node --test tests/*.test.ts` | 316+ тестов; база не должна уменьшаться |
| `scripts/check-pages.mjs` | каждая локальная ссылка/ассет существует, `/manage` = noindex, sitemap |
| `scripts/check-prices-sync.mjs --refs-only` | нет зашитых сумм и битых `{{price:…}}` |
| `scripts/check-reviews.mjs` / `check-reviews-artifact.mjs` | схема отзывов и отсутствие демо на домене |
| `scripts/check-cases.mjs` | записи работ и файлы фото согласованы |
| `scripts/check-news.mjs` (+`--strict`) | схема `site/content/news.json`, черновики не попадают в артефакт |
| `scripts/check-media-budget.mjs` | бюджет веса фото |
| `scripts/check-analytics.mjs` | без ID счётчиков в HTML нет; с ID — есть — **появляется в круге 89**, задание `prompts/133` |
| `scripts/check-intro-3d-off.mjs` | заставка и 3D остаются выключенными |
| `npm run typecheck` | типы |

**Тесты не ослаблять и не удалять ради зелёного прогона.** Если тест проверяет старое
поведение — переписать на новое и объяснить в PR, а не вычеркнуть.

## 8. Definition of Done

Задача не готова, пока в PR не приложено:

```
cd site
npm ci
npm run typecheck
npm run build
PUBLIC_DEMO_REVIEWS=1 PUBLIC_ORIGIN=https://sledovatel61.github.io PUBLIC_BASE_PATH=/avtotehservis npm run build:pages
node --test tests/*.test.ts
node scripts/check-pages.mjs          # с теми же PUBLIC_ORIGIN/PUBLIC_BASE_PATH
```

и сверх того:

1. Вывод команд (число тестов, `PASS` гейтов) — текстом, не пересказом.
2. Список изменённых файлов и одна строка «что изменилось для владельца».
3. Для визуальных задач — **URL страницы**, а не скриншот. Скриншоты не принимаются.
4. Для задач про контент — `diff` количества записей до/после.
5. Честный раздел «что не проверено» — это повышает доверие, а не понижает.

Слово «готово» без проверяемого артефакта = не готово.

## 9. Запреты

- Ослаблять или удалять тесты, гейты, проверки.
- Удалять `seed-data.ts`, `migrations/`, таблицы БД, функции `server/content.ts`.
- Трогать `CNAME`, `robots.txt` (кроме правки по заданию), `site/public/media/**` вне своей задачи.
- Выдумывать адрес, страну, реквизиты, отзывы, цены, «примеры» на боевом домене. Демо-отзывы
  на домене запрещены; на превью — только с чипом «пример».
- Менять `CONSENT_VERSION` (`relay/wrangler.toml`) — сверяется с сайтом в `relay-smoke.yml`;
  смена ломает все заявки с `400 consent_version`. Для политики — отдельное `policy_version`.
- Перевыпускать `BOT_TOKEN` Telegram. Токен рабочий.
- Вставлять секреты в код, чат, скриншоты. Секреты задаёт владелец в GitHub Secrets.
- Менять цены в текстах «на глаз»: только `{{price:ключ}}` из `prices.json`.
- Переписывать юридические тексты без пометки «требует проверки юристом» и без согласования.
- inline `onclick` и `<script>` в разметке: CSP `script-src 'self'` заблокирует.

## 10. Известные ловушки

| Ловушка | Что делать |
|---|---|
| `node --test` на чистом worktree → сотни fail | сначала `npm run build && npm run build:pages` (тестам нужен `pages-dist`) |
| `check-pages.mjs` без env → `Unprefixed URL` | задать `PUBLIC_ORIGIN`/`PUBLIC_BASE_PATH` |
| Артефакты Pages не скачиваются из песочницы | собирать локально `build:pages`, не через `gh run download` |
| `gh run download` вне git-каталога | запускать из корня репозитория |
| `gh workflow run` → 403 | кнопки нет; пересборка = push в `preview/github-pages` |
| `curl` к `ats-rostov.ru` из песочницы → `000` | смотреть через `fetch_page`; редиректы локально — через `curl 127.0.0.1:PORT` |
| `trailingSlash: 'never'` | `/admin/cases/` → сначала 301 Astro, потом 301 middleware; это норма |
| Правки `/admin/**` не видны на домене | их там нет физически, см. §6 |
| `git worktree add -b …` без пути | создаёт каталог в репозитории; всегда указывать `/tmp/wtN` |

## 11. Формат заданий и отчётов

- Задание: `prompts/NNN-task-rNN-<тема>.md`. Нумерация сквозная, без пропусков и без второй
  папки для них.
- В задании обязательны: ветка, объём (какие файлы), зависимости от других агентов,
  что **запрещено** трогать, критерии приёмки, команды проверки.
- Отчёт приёмки: `docs/reports/rNN-acceptance.md`. Первая строка — вердикт. Дальше таблица
  «проверка / чем проверял / результат» и список дефектов с файлом и строкой.
- Пожелания и «было бы неплохо» в отчёт не попадают — только расхождения с заданием.

## 12. Что делает только владелец

Агент не может и не должен пытаться: DNS домена, регистрация в Метрике/GA/Search Console/
Вебмастере, аккаунты почтовых сервисов, Cloudflare KV namespace, GitHub Secrets, включение
HTTPS в настройках Pages. Такие пункты идут в `docs/backlog.md` в раздел «Владельцу» с
пометкой «блокер запуска» или «не блокер».

## 13. Как говорить с владельцем

> **Это правило сильнее любых привычек агента и действует всегда, включая новый чат,
> сжатый контекст и чужую сессию.** Если сомневаешься, как писать, — пиши проще.

Владелец — организатор, а **не инженер и не программист**. Он хорошо понимает нейросети
и процессы, но не читает код и не обязан знать слов вроде `noindex`, `KV`, `CSP`, `SSR`.
Половина технического текста для него — шум, из-за которого он теряет суть и дольше
разбирается. Понятное объяснение важнее подробного.

**Как писать:**

1. **Сначала — что делать.** Первый абзац отвечает на вопрос «что мне сделать», а не
   «как это устроено». Детали — ниже, если они вообще нужны.
2. **Бытовой смысл → потом термин.** «Сайт закрыт от поиска, в каждой странице стоит
   запрет для роботов (`noindex`)», а не наоборот.
3. **Коротко.** Обычный ответ — 3–8 абзацев или таблица. Не выкладывать в чат задания,
   diff'ы, логи, номера строк и листинги файлов: они лежат в репозитории, туда и отсылать.
4. **Пошагово, с кнопками.** Если владельцу что-то нажимать — нумерованные шаги, точные
   названия кнопок, где они на экране, что должно получиться в конце. Образец стиля —
   `docs/secrets-setup.md` и `docs/owner-kv-namespace.md`.
5. **Без жаргона без перевода.** Встретилось слово, которого нет в обычной жизни, —
   объясни в скобках в одну фразу или замени.
6. **Всегда говори, что от него нужно.** В конце — короткий список «что нужно от вас»
   (или «ничего не нужно»). И отдельно — что сделано для него, в 3–5 пунктах.
7. **Ошибку признавать прямо.** Не прятать в технические подробности; сказать, что
   сломалось в бытовых словах и что делаем дальше.
8. **Скрины не читаются** — просить адрес страницы и фразу с экрана, а не картинку.

**Что не считается «простым языком»:** сокращения из кода, английские термины без
перевода, «см. файл», отсылки к строкам кода, длинные списки проверок. Всё это — только по
прямой просьбе владельца.
