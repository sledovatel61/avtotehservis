## 4. Major

### 4.1. «Красивый фон» доведён до серых полос: постобработка удалила кадр, а не сгладила шов

`site/scripts/build-images.mjs:675` (блок 10c):

```js
const target = ramp + (colMean[x] - gMean) + (rnd() - 0.5) * 4;
const delta  = target - lum;                       // перезапись каждого пикселя
```

В `target` нет ни одного члена, который зависел бы от **пикселя** исходника: только средняя колонки
`colMean[x]`, глобальная средняя и шум ±2. То есть из кадра остаётся одномерный профиль по X плюс зерно:
вся двумерная структура (верстак, стеллаж, машина, свет из ворот) стёрта. Комментарий над блоком
(«+ 8 % вертикальной фактуры исходника») описывает не тот код, который под ним написан — 8 % нигде не участвуют.

Замер (моя утилита, sRGB-яркость):

| файл | mean | остаток после снятия row/col-средних (sd) | средний |Δ| по Y | средний |Δ| по X | max |
|---|---|---|---|---|---|
| `bg-raw.jpg` (AI-мастер) | 48,6 | **44,37** | 7,55 | 6,33 | 255 |
| `bg-smooth.jpg` → `svc-bg-1600.webp` | 43,9 | **20,43** | **0,85** | 1,61 | **120** |

Половина дисперсии ушла, градиент по вертикали упал в 9 раз, света срезаны до 120 (было 255) — кадр стал
низкоконтрастной «клеёнкой». При этом в нём остались **вертикальные полосы**: sd остатка «колонка минус
тренд» 4,45, максимальный скачок между соседними колонками **18,4** единицы яркости (у мастера 21,9 — то есть
артефакт не вылечен, а законсервирован). На экране это читается как шторы/полосы — см.
`reviews/assets-round21/bg-only-1440.jpg` (фон без текста и карточек) и сравнение
`reviews/assets-round21/bg-master-vs-postprocess.png` (сверху мастер, снизу то, что на сайте).

Задание, B1: «Не „клеёнка“: фактура должна читаться как материал (бетон, металл, свет), а не как шум».
Здесь ровно наоборот: материал стёрт, шум остался. Отчёт автора (§«Что не получилось», п. 6) это признаёт,
но называет «фактура сохранена зерном и горизонтальным световым профилем» — по коду фактуры там нет.
Пункт G1 («фон имеет фактуру») формально зелёный, по смыслу — нет.

Что нужно: сглаживать **только** профиль строк (то, из-за чего был шов), сохраняя локальный контраст кадра —
например, вычитать из каждого пикселя разницу между средней его строки и монотонной рампой, а не подменять
пиксель целевой яркостью. И перемерить после этого «ступеньку строк» — при таком подходе она останется ≤ 3
(проверял на похожей схеме в круге 20: снятие только низкочастотной составляющей шва не даёт).

### 4.2. Третья из трёх видимых карточек — не фактура, а размытая мозаика

`site/scripts/synth-svc-textures.mjs` рисует четыре «процедурные» фактуры через value-noise плюс узор;
после аффинного прохода к целевой средней узор оказывается в пределах ±5 единиц и на 640 px его нет.

Резкость (дисперсия лапласиана на кропе 400×300 из центра, чем больше — тем больше деталей):

| файл | лапласиан | что видно на экране |
|---|---|---|
| `svc-1-640.webp` (шиномонтаж, AI) | **594,7** | колесо на подъёмнике |
| `svc-4-640.webp` (ТО/масло, AI) | **642,7** | масло в двигатель |
| `svc-3-640.webp` (ремонт шин, синтез) | 54,7 | полосы протектора — читаются |
| `svc-5-640.webp` (ходовая, синтез) | 8,1 | серая мгла |
| `svc-2-640.webp` (балансировка, синтез) | 5,1 | концентрические кольца, «рябь» |
| **`svc-6-640.webp` (электрика, синтез)** | **2,5** | **серая шахматная мгла** — третья карточка в кадре 1440 |

Разница в 200–250 раз. На рендере 1440 (см. `reviews/assets-round21/card3-elektrika-1440.png`) третья карточка —
серый размытый прямоугольник между двумя фотографиями; на 1024/768/390 она тоже видна (в кадре 2/2/1 карточки).
Критерий G2 «три карточки разные и не „выбеленные“» гейт считает по «разбросу» = max − min: у карточки 6 это
69,5 (min 54, max 96), порог 34 пройден, но реальный sd зоны — **7,1** против 30,2 и 34,1 у соседних.
Метрика «разброс» на max−min не отличает фактуру от ровной заливки с зерном; критерий надо считать по sd
или по локальному контрасту (лапласиан), иначе он не про «фактуру», а про наличие одного светлого пикселя.

Задание, B2: «три разные фактуры, а не одна под тремя оттенками». Файлы разные, фактура одна — шум.
Синтез «косы кабеля» (`patElectric`, строка 33–41) в готовом 640-производном не виден вовсе.
Варианты лечения: поднять амплитуду узора до видимой (разброс 70 сейчас уходит в шум и виньетку),
либо взять для трёх видимых карточек AI-кадры, а синтез оставить скрытым (`balansirovka`, `remont-shin`).

### 4.5. `tsc` падает: `Cannot assign to 'render' because it is a function`

`site/src/client/global.ts:203-204`:

```ts
const origRender = render;
render = (animate?: boolean) => { origRender(animate); sayAll(); };
```

`render` объявлена как `function render(...)` — это FunctionDeclaration, переприсваивать её нельзя.
`npx tsc --noEmit`:
```
src/client/global.ts(204,3): error TS2630: Cannot assign to 'render' because it is a function.
```
На базе `87dd3be` тот же `tsc --noEmit` проходит без вывода. Критерий E1 задания («`tsc` без ошибок») не выполнен.
`npm test` этого не показывает, потому что `npm test` начинается с `npm run build` (esbuild типы не проверяет),
а `typecheck` в `test` не входит — зелёный прогон в отчёте создаёт ложное впечатление.
Лечение: `const renderBase = ...;` + локальная обёртка, либо `function render()` оставить и вызывать `say()`
из `go`/обработчиков вместо переприсваивания.

для «Галереи работ» и «Отзывов» счётчик читается как «Экран 1 из 6» / «Экран 1 из 3» (проверил в браузере).
Для скринридера это новый бессмысленный текст, которого раньше не было; дефолт стоит сделать пустым

(тени и блик), при sd 30,2. Порог «≥ 34» такой метрикой проходит даже ровная заливка с одним светлым пикселем
(карточка 6: max 96, min 54 → «разброс» 69,5 при sd 7,1). Критерий G2 в отчёте выглядит выполненным

CDP `encodedDataLength`, DPR 1». Мой замер той же методикой, что дала таблицу «до» в задании (без ступенчатого

(у автора base 800/729/569 против моих 679/560/481). Для 1280 запас по абсолюту всего 10 КБ — это стоит держать
в голове следующему кругу, и лучше вернуть абсолютную метрику, а не дельту.

**5.5. Печать: карточки остаются тёмными.** В `@media print` отключается только `.svc-bg`; `.svc-card`
остаётся `rgb(16,32,26)`, `h3` — `rgb(244,239,230)`. На бумаге (белый лист, фоны по умолчанию не печатаются)

страницы услуг.

border-box контейнера и видит «0 px». В «Галерее работ» при том же контейнере `nav.right` = 900,
то есть стрелки встают на 20 px правее линии всех остальных блоков и почти вплотную к краю экрана на 1024
(1024 = краю окна). Формально по заданию (±8 к «полю контейнера») проходит, визуально — выпадает из сетки.

**5.7. На 360 px появилась горизонтальная прокрутка 6 px.** `scrollWidth` 366 при `innerWidth` 360
(`nav.right` = 366); на базе `87dd3be` при той же ширине 360/360. Причина — тот же `margin-right:-20px` (§5.6).
Требуемые пять ширин (390…1440) чистые, поэтому minor, но регрессия новая и от гейта скрыта:
`render-svc.mjs` рисует только 1440/1280/1024/768/390.

**5.8. Карточка выросла на 28,4 px вместо разрешённых 22.** Задание, B6: «нижняя часть растёт максимум
на высоту новой кнопки (+22 px)». Факт: карточка 515,9 → **544,3** (+28,4) при 1440, причина — `min-height:44px`
плюс `padding:12px 20px` (итого 48,4 при прежних 25) и `margin-top` 6 → 10 px. Высота секции при этом в норме
(922 при 920…1040), поэтому minor, но числовой допуск задания превышен.
