## 10. Гейт: 17/17 своих мутантов — и четыре чужих, которые он не видит

`node scripts/check-about-bg.mjs` → `rc=0`, «все нормы выполнены», 17/17 мутантов падают.
Но проверка видимости сделана не на рендере, а на файлах мастеров, и это видно, если гасить
слой так, как это делает живой CSS:

| что сделал | ожидание §3 | факт |
|---|---|---|
| `opacity:.12` на `.fact-bg` | падение (слой погашен) | **rc=0** |
| `opacity:.05` на `.about-bg` | падение | **rc=0** |
| `display:none` на `.feat-bg` | падение | **rc=0** |
| `background:rgba(11,20,16,.9)!important` в том же `.fact-bg::after` | падение по разбросу | **rc=0** |
| скрим плашек `.95` в исходном значении | падение | rc=1 («вне диапазона 0,74…0,82» + пол C1 18,6/12) |
| скрим плашек `.55` | падение | rc=1 (только «вне диапазона») |
| `.sec-head` 760 px | падение | rc=1 (§2.2 сирота, 3 строки/18 %) |
| `.fact b` без `balance` | падение | rc=1 (строка 11 %) |
| `.facts` без `--strip` | падение | rc=1 (§2.4 дыра + плашка 239 px) |
| скрим кнопки `.95` | падение | rc=1 (диапазон + пол D 19,9/11) |
| мастер `card-1` заменён на плоский серый | падение | rc=1 (средняя 19,4 / разброс 4) |

Причина первых четырёх — гейт читает **текст** CSS регуляркой, а не вычисленный стиль:
`/\.fact-bg::after\{[^}]*linear-gradient\(95deg,…/` находит строку в файле, даже когда действует
`background:…!important`, и молча пропускает. А пол §3 считается по мастеру, который этот же
скрипт нормирует под целевые числа, поэтому от CSS он не зависит вообще: настоящий мутант
«скрим плашек 0,90 → падает по разбросу» (мутант №1 из §3 задания) в наборе реализован как
полная замена блока — он падает по «нет градиента», то есть по синтаксису.

Итог: защита от рецидива круга 18 формально есть, фактически её можно обойти одним `!important`
или одной строкой `opacity`. Ровно та же болезнь, что описана в §5 задания («проверяли
соответствие букве, а не результату на экране»), только теперь на уровне гейта.

Побочно: запас пола на мастерах +19…+79 при пороге ≥3 (`sec-bg-2560` 37,1, `fact-1` 71,9,
`card-1` 60,2, `btn` 96,7 против базы средней 17,8), потому что база сравнения — средняя кадра,
а не минимум; правки скрима в диапазоне 0,74…0,82 гейт не двигают вовсе.
