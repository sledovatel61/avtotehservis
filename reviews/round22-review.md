**Оговорка про `naturalWidth ≥ 640`.** У картинки с `srcset/sizes` браузер по спеке HTML

(`currentSrc`: 720 ≥ 640 на 1440/1280) плюс интринзик всех трёх файлов (480/720/1080). На 1024
брауер по `sizes` из задания честно берёт 480 px (слот 471 px) — это и есть смысл responsive-
картинки; качество при DPR 1 достаточное (638 px на экране из 480-файла — лёгкий апскейл,
заметных артефактов нет).

## Что не получилось / ограничения

1. `naturalWidth` у srcset-картинки — density-corrected (см. оговорку в B2); буквальный чек
   `naturalWidth ≥ 640` в браузере невыполним для любой responsive-картинки с слотом <640,
   гейт проверяет ширину выбранного файла.
2. Покрытие page-head по высоте 99,7–99,8 % — субпиксельное округление `getBoundingClientRect`
   (object-fit:cover структурно даёт ≥100 %); гейт допускает ≥99,5.
3. Трети фонов на мобильных ширинах физически не выдерживались одним мастером (cover-кроп
   18–45 % кадра сжимает любую модуляцию) — решено геометрией файлов + тон-маппингом,
   а не подгоночными циклами; амплитуды калиброваны по замерам (4 итерации детерминированной
   постобработки, перегенераций AI не было).
4. `cases/reviews/brands` на about оставлены без фонов (ритм, см. B7); если приёмка захочет
   фон и там — это следующий круг, лимит AI-генераций на этот исчерпан (3/3).
5. Синхронизация с `origin/main` и веткой оркестратора не делась (unrelated roots, как в r17–r21:
   слияние удаляет работу); дерево принято tree-adoption в начале раунда.
