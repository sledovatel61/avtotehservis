## 5. Блокер: CTA первого экрана перекрыт панелью карусели на мобильных

Причина: `.hero{min-height:max(420px,58svh)}` (`media.css:34`) при текстовой панели высотой ~460–540 px. Панель `.slide-in` выходит за пределы героя (`overflow:hidden` её режет), а `.hero-ui` (`position:absolute; bottom:26px`) оказывается **на кнопках**.

| Вьюпорт | высота героя | панель ниже героя | «Записаться на визит»: клик в 25 точках | «Все услуги» |
|---|---|---|---|---|
| 320×568 | 420 | +71 px | 1 из 25 точек попадает в кнопку | **0 из 25**, 100 % за пределами героя |
| 360×640 | 420 | +59 px | **0 из 25** | 5 из 25, 80 % вне героя |
| 360×740 | 429 | +54 px | **0 из 25** | 5 из 25, 80 % вне героя |
| 375×667 | 420 | +59 px | **0 из 25** | 5 из 25, 80 % вне героя |
| 390×844 | 490 | +11 px | 25 из 25 ✔ | **10 из 25** (остальное — стрелки и точки) |
| 412×915 | 531 | −9 | 25 из 25 ✔ | 0 из 25 (перекрыта `.container`) |
| 414×896 | 520 | −4 | 25 из 25 ✔ | 0 из 25 (перекрыта `.hero-arrow`) |
| 640×800 | 464 | −31 | 15 из 25 (остальное — `.container`) | 15 из 25 |
| 768 / 1024 / 1440 | — | — | 25 из 25 ✔ | 25 из 25 ✔ |

Проверено **настоящим кликом мыши**, не `.click()`:

```
360×640  клик по (155,461) на «Записаться на визит» [424–474]: elementFromPoint=DIV.container → URL /        (не сработало)
640×800  клик по (149,475) на «Записаться на визит» [438–488]: elementFromPoint=DIV.container → URL /        (не сработало)
390×844  клик по (155,483) на «Записаться на визит» [446–496]: elementFromPoint=A.btn        → URL /appointment  (ok)
390×844  клик по «Все услуги» → переключился слайд (is-active стал 2-м), URL остался /
```

Скриншот 360×640: `/tmp/bp/se-360x640.png` — видно, как стрелка «←» и точки легли прямо на оранжевую кнопку, «ВСЕ УСЛУГИ» срезана нижней границей героя.

Почему это блокер, а не minor: «Записаться на визит» — **основной сценарий** первого экрана, и на 360×640 / 375×667 / 320×568 (самые частые мобильные) он не открывает форму. `.hero-ui .container` не имеет `pointer-events:none`, поэтому прозрачный контейнер панели ловит клики.

Что мешает это увидеть: браузера у автора нет, а расчёт по CSS был. Достаточно было проверить не «помещается ли текст», а «не пересекаются ли блоки по вертикали» — суммарная высота панели (eyebrow + h1 в 4 строки + sub в 4 строки + две кнопки = ~460 px) плюс 2×26 px отступа UI больше 420–490 px героя.

## 6. Major

### 6.1 Неон съел читаемость `h1` на десктопе

Задание §5.4 требовало проверить, что неон не поднимет яркость под текстом; проверяли только `slide-sub`. Подзаголовок действительно в порядке (§7.1), а **заголовок** — нет: на 1180–1920 `h1` физически лежит на светящемся названии вывески (кадр стал крупнее: 1,281 вместо 1,79, вывеска занимает верхние 40 % героя).

Замер зоны `h1` (цвет `rgb(244,239,230)`, 50,4 px / 600 — крупный текст, порог 3 : 1):

| Ширина | худший пиксель | доля < 3 : 1 | доля < 4,5 : 1 |
|---|---|---|---|
| 1024 | 11,29 | 0,0 % | 0,0 % |
| 1180 | 1,16 | **12,9 %** | 14,7 % |
| 1280 | 1,11 | **15,9 %** | 18,0 % |
| 1366 | 1,13 | **19,1 %** | 21,7 % |
| 1440 | 1,12 | **21,9 %** | 24,6 % |
| 1920 | 1,10 | **34,4 %** | 38,3 % |

Причинность проверена прямым экспериментом на 1440 (гашу только слой неона):

| | худший | < 3 : 1 | < 4,5 : 1 |
|---|---|---|---|
| неон **включён** | 1,12 | 21,9 % | 24,6 % |
| неон **выключен** | 9,22 | 0,0 % | 0,0 % |

То есть весь дефект создан неоном. На скриншоте `hero-1440` белые буквы «Ремонт авто на Портовой — от колеса до двигателя» накладываются на светящееся «АвтоТехСервис» и в местах пересечения читаются плохо (проверено глазами, `/tmp/bp/hero-1440.png`).

Лечится либо опусканием текстового блока/уменьшением `h1`, либо ослаблением ореола в зоне, куда попадает текст, либо возвратом к панели под текстом на всех ширинах (сейчас она только ≤1024). Требование §5.4 сформулировано про `slide-sub`, но принцип «неон не должен ломать читаемость» — общий; здесь он нарушен на самом крупном элементе экрана.

### 6.2 Мобильный кроп обрезает букву названия — заявление не воспроизводится

В сдаче: «Кроп close **x 300…1817, y 138…2160 = 1517×2022 (3:4)**: правый край — в замеренном межбуквенном промежутке **1516…1544** (после «С»), **ни одна буква не обрезана**».

Проверил по оригиналу `original-front-close-3840x2160.jpg` (полоса названия, яркие пиксели > 190):

```
сегменты букв около правого края: [1546,1664] [1680,1829] [1840,1961] [1982,2108]
профиль яркости: 1810:41 1813:36 1816:31 1817:29 1820:24 1825:14 1829:6 1831:2 1832:1 ...
```

Кроп кончается на **x = 1817**, а буква «С» занимает **1680…1829** — то есть правый край кропа проходит **по букве**, срезая её последние 12 px (≈8 % ширины буквы). Промежуток после неё начинается на 1830, а не на 1516–1544 (там ещё «xC»).

В браузере это видно: на 390 и 360 заголовок вывески обрезан краем экрана — ««АвтоТехС…», правая часть «С» срезана (`/tmp/bp/title-390.png`, `edge-390.png`). Критерий приёмки §7 («ни одна буква не обрезана краем экрана») **не выполнен**. Сдвиг кропа на ~25 px влево (или ширина 1490 вместо 1517) убирает дефект.
