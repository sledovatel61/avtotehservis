Заявки — офлайн-очередь и идемпотентность

Демо показывает, как заявка живёт после отправки: БД → outbox → Telegram/почта с ретраями. Ниже — очередь из localStorage.

Очередь

Заявки пишутся в БД первой. Если Telegram упал — письмо уходит. Упало всё — заявка остаётся со статусом accepted, клиент видит номер.

POST /api/leads → 201 {ticket, status:"accepted"}
→ outbox → TG sendMessage → SMTP avtotehservis439@mail.ru

Идемпотентность

Ключ idempotency_key: uuid-v4 шлётся с формой. Повтор — не создаёт дубль, возвращает тот же ticket.

uuid — генерируется при загрузке, хранится в localStorage

Публикация кейса — 60 сек

Мастер открывает /admin с телефона, жмёт «+ Кейc», выбирает 1–6 фото (HEIC/MOV — конверт sharp+ffmpeg на сервере, preview на клиенте), заполняет заголовок + категорию, жмёт «Опубликовать». EXIF GPS — чистим, WebP 800/1200 генерируем, 60 сек.

Демо — без реальных токенов. Токен бота и пароль почты — только в env.
