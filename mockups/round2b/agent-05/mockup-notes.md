## 4. Типографика

Пара: **Unbounded 600** (дисплей — заголовки, номера, цифры) + **Golos Text 400/500/700** (текст, меню, кнопки). Итого 2 гарнитуры / 4 начертания. Обе — OFL-1.1 (подтверждено `METADATA.pb` в google/fonts: `ofl/unbounded`, `ofl/golostext`). Кириллица подтверждена наличием официальных cyrillic-сабсетов в npm-пакетах `@fontsource/unbounded` и `@fontsource/golos-text` (`unbounded-cyrillic-600.woff2`, `golos-cyrillic-{400,500,700}.woff2`) и строками `subsets: "cyrillic"` в METADATA.pb. Сабсеты кириллица+латинь вложены локально: **88 КБ суммарно** (Unbounded 33,5 КБ, Golos 54,5 КБ — лимит 120 КБ на гарнитуру не превышен), `unicode-range`, `font-display:swap`, фолбэк `system-ui`. Никаких CDN и Google Fonts. Заголовки через `clamp()` (H1 1,9–3,15rem), плотный отрицательный трекинг −0,02em, капс дозирован (только надзаголовки-eyebrow и кнопки). Почему эта пара: Unbounded — геометричный дисплей с характером (заметно «дороже» Montserrat-капса), Golos Text — нейтральный, читабельный в 17 px/1,6 против топорных Open Sans 14/32. Продакшн-альтернатива, если понадобится больше начертаний: вариативные `Unbounded[wght].ttf` / `GolosText[wght].ttf` с инстансингом при сборке.

## 5. Решения (с обоснованием)

1. **Ночь+изумруд+медь+слоновая кость** вместо «серого на чёрном» (направление A5 «глубокая тёмная премиум»); светлая секция «Смета до ремонта» даёт ритм чередования из §7.3 и выполняет персональную задачу A5 (смета — отдельная секция; продублирована слайдом героя №2 и плашкой «Стоимость — после осмотра» на `service.html`).
2. **Только собственные SVG-заглушки (22 файла, 22,6 КБ)**: hero-графика, услуги 4:3, кейсы с разделителем «ДО/ПОСЛЕ», новости, схема проезда. Ни одного стокового изображения референса; подписи честно говорят «фото появится после съёмки» (по docs/07 владельцу нужно 12–18 фото кейсов).
3. **`service.html` и `post.html` — по одному файлу** с подстановкой контента из `?s=slug` / `?p=slug` (структура задания требует ровно 8 файлов). Без JS страницы отдают статический контент по умолчанию (шиномонтаж / первая статья) — «открываются двойным кликом» при любом раскладе.
4. **Форма: все 11 дефектов §5 закрыты поштучно** (таблица §1). «Занятые» слоты детерминированы (хэш даты) — демо воспроизводимо; демо-триггер ошибки — телефон `+7 (900) 000-00-00` (подсказка есть прямо в экране ошибки).
5. **Идемпотентность и черновик:** uuid-ключ живёт в черновике; повторная отправка после успеха показывает тот же номер и «дубль не создан»; черновик — debounce 500 мс, удаляется после успеха; при недоступном localStorage (приватный режим, ограничения file://) форма полностью работает без черновика — `safeLS`-обёртка проверена в jsdom на двух origins.
6. **Отзывы без фабрикаций:** примеры отзывов помечены плашкой «демо»; рейтинги показаны тремя карточками с источниками и оговоркой «данные заказчика, требуется проверка» про Яндекс; никакого AggregateRating в JSON-LD.
7. **Марки — текстовая бегущая строка названий**, не логотипы (чужие товарные знаки); пауза при hover/focus, при reduced-motion — статичный скроллящийся список.
8. **Аналитика — только `console.debug('[demo-event]', …)`** (~25 событий: hero_slide, step_view/next/back, submit_attempt/success/error, payload_view, news_filter, call_click, telegram_click, route_click, menu_open, lightbox_open…). Чужой ID Метрики — ловушка, своего счётчика в мокапе нет.
9. **Нативные карусели одного паттерна** (transform+свайп+стрелки) вместо Owl: один код на слайдер услуг, галерею и отзывы; стрелки секции ищутся в общем контейнере, чтобы не ломать композицию «заголовок + навигация справа».
10. **`admin.html` (бонус):** заявки из формы автоматически попадают в таблицу админки (общий localStorage), статусы переключаются, публикация кейса с 60-секундным таймером (KPI docs/00 «публикация ≤ 60 с»), журнал действий. Всё локально, без сети.

Цепочка в продакшне: `POST /api/leads` → серверная валидация (телефон 11 цифр, VIN 17 без I/O/Q, год 1980–2026, slug-и услуг из whitelist) → запись в БД с UNIQUE по `idempotency_key` (дубль → тот же ticket) → немедленный ответ `201 {ticket:"A-DDMM-XXXX", status:"accepted"}` — клиент видит номер **до** доставки → outbox-таблица → воркер: Telegram `sendMessage` владельцу (бот) **и** письмо на `avtotehservis439@mail.ru` (SMTP) → ретраи с экспоненциальной задержкой → статус доставки в админке.
