## 4. Палитра — тёмная техничная, акцент электро-циан

| Роль | Цвет | Контраст | Проходит AA (4.5:1 текст / 3:1 UI) |
|---|---|---|---|
| Фон `--bg` | `#0B0D10` | — | — |
| Поверхность карточек `--surface` | `#15181C` | — | — |
| Текст `--text` на `--bg` | `#EDEFEF` | **16.86 : 1** | Да, AAA |
| Текст `--text` на `--surface` | `#EDEFEF` | **15.43 : 1** | Да, AAA |
| Приглушённый `--muted` на `--bg` | `#9AA3A8` | **7.58 : 1** | Да |
| Приглушённый `--muted` на `--surface` | `#9AA3A8` | **6.93 : 1** | Да |
| Акцент `--accent` на `--bg` (ссылки/иконки) | `#5CF2FF` | **14.45 : 1** | Да |
| Акцент `--accent-ink` (тёмный текст) на `--accent` (кнопки) | `#06141A` | **13.89 : 1** | Да |
| Белый `#FFFFFF` на `--accent` | — | **1.35 : 1** | **Нет** — поэтому кнопки используют тёмный текст, не белый |
| Успех `--success` на `--bg` | `#5FE3A0` | **12.03 : 1** | Да |
| Ошибка `--error` на `--bg` | `#FF6B6B` | **7.01 : 1** | Да |
| Функциональная рамка поля `--field-border` на `--surface` | `#616B73` | **3.27 : 1** | Да (non-text UI, порог 3:1) |

Декоративный `--border` (`#262B30`, разделители без функции) намеренно ниже 3:1 — он не несёт информации и не обязан проходить контраст по WCAG 1.4.11. Все интерактивные рамки (поля форм, чипы, слоты) используют `--field-border`, который проходит 3:1. Палитра строилась так, чтобы не превратиться в «серое на чёрном»: разница между `--bg` и `--surface` всего 4% яркости (визуальный слой), но текст везде контрастирует с фоном в 14–17 раз — читаемость не приносится в жертву «плоскому» тёмному стилю.

## 6. Обоснованные решения

1. **Полный отказ от трейдмарк-логотипов марок** в бегущей строке (референс использовал логотипы Infiniti/Lexus/BMW и т.д.) — заменено текстовыми названиями марок без графики брендов, чтобы не использовать чужую интеллектуальную собственность без разрешения.
2. **Markup по рефересу, но без аккордеона в блоке «О компании»** — у референса 4 пункта-аккордеона с выдуманными цифрами стажа; мы используем статичные карточки с подтверждёнными фактами (часы, марки, гарантия, 2 канала связи), раскрытие по клику не нужно, когда фактов меньше и они короче.
3. **View Transitions API как прогрессивное улучшение** (`@view-transition{navigation:auto;}`) — переход между страницами плавный в поддерживающих браузерах, в остальных — обычная навигация без JS и без веса.
4. **Единый `app.js` на все 8+1 страниц** вместо отдельного скрипта на каждую — код переиспользуется (меню, слайдер, лайтбокс, формы), при этом каждая функция проверяет наличие своего DOM-узла перед инициализацией (`if(wizard){...}`), поэтому один файл безопасно подключён везде без ошибок в консоли.
5. **Демо-админка (бонус) не связана с живой галереей других страниц** — в отличие от одностраничного мокапа прошлого этапа, здесь 8 независимых HTML-файлов без общего JS-состояния между вкладками; «публикация» добавляет карточку в собственный предпросмотр на `admin.html`, это честнее, чем имитировать несуществующую синхронизацию между статическими файлами.
6. **E-mail убран из обеих форм** (запись и контакты) — у референса это было лишнее обязательное поле; у нас два контакта для связи — звонок и Telegram, e-mail используется только как транспорт заявок на бэкенде (см. §7), не как поле ввода для клиента.
7. **Новости — 3 категории 1-в-1 как у референса** (Новости/Акции/Статьи) — это единственное решение референса, которое не нуждалось в переделке; содержимое — честные демо-заглушки без выдуманных цифр и скидок.
8. **Контраст посчитан и перепроверен числом, а не на глаз** — личное задание: «не сделай серое на чёрном». Решение — принудительно держать текст на фоне не ниже 14:1, а акцентный цвет выбирать таким, чтобы кнопочный текст оставался тёмным (белый на циане проваливает AA).
9. **SVG-заглушки вместо base64** — все изображения (галерея, услуги, новости, карта) — инлайновые `<svg>` с градиентами/фигурами, а не растровые файлы: это держит вес страницы на уровне 10–27 КБ за HTML-файл вместо сотен килобайт на фото.
10. **Платная папка `Реквизиты.PDF.pdf` не использовалась** — банковские реквизиты и домашний юридический адрес из неё не публикуются нигде на сайте, как и предписано в `docs/01-company-research.md` §1.1.

## 7. Анимации (§8)

| Эффект | Триггер | Длительность | Вес (КБ) | `prefers-reduced-motion` |
|---|---|---|---|---|
| Слайдер-герой (fade + сдвиг) | Автопрокрутка / клик стрелки-точки | 420 мс | 0 (CSS) | Автопрокрутка отключается, переключение — мгновенное |
| Появление секций при скролле | `IntersectionObserver` на `.reveal` | 420 мс, каскад 0/80/160 мс | 0 | Элементы сразу видимы |
| Hover карточек услуг | `:hover` на `.svc-card` | 220 мс | 0 | Отключено |
| Карусель галереи/отзывов | `scroll-snap` + свайп | нативно (без фикс. длительности) | 0 | Свайп остаётся, анимация скролла — без сглаживания |
| Лайтбокс (масштаб + прозрачность) | Клик по карточке | 220 мс | 0 | Мгновенное появление |
| Переход шагов формы | Клик «Далее/Назад» | 220 мс (`translateX`+`opacity`) | 0 | Мгновенная смена шага |
| Прогресс-бар формы | Переход шага | 220 мс (`transform:scaleX`) | 0 | Мгновенно |
| Компактная шапка при скролле | `scroll` (y>36px) | 220 мс (`padding`) | 0 | Отключено |
| Бегущая строка марок | CSS `@keyframes marquee`, пауза на hover | 26 с линейно, бесконечно | 0 | Полностью отключена (статичный список) |
| Переход между страницами | Навигация (клик по ссылке) | View Transitions API, мгновенный fallback | 0 | Группы `::view-transition-*` без анимации |
| Экран успеха формы | Завершение отправки | 220 мс (галочка, scale) | 0 | Мгновенно |
| Нажатие кнопки | `:active` | 150 мс (`transform:scale(.97)`) | 0 | Отключено |

Все 12 эффектов используют только `transform`/`opacity` (плюс нативный `scroll-snap` и CSS `@view-transition`), укладываются в 150–600 мс. Бегущая строка марок — единственная «бесконечная» анимация, что явно разрешено спецификацией (аналог референса), с обязательной паузой на hover и полным отключением при `prefers-reduced-motion`.

## 8. Заявки — контракт и серверная цепочка (§6)

Мокап не делает сетевых вызовов. На `appointment.html`, шаг 5, кнопка «Что уйдёт на сервер» показывает реальный JSON, который формируется из введённых данных (поле `idempotency_key` — `crypto.randomUUID()`, генерируется один раз на сессию формы и переживает повторные попытки отправки, чтобы ретраи не плодили дубли).

Предполагаемая боевая схема (описание, не код):
1. `POST /api/leads` с телом как в §6 брифа → ответ `201 {ticket, status:"accepted"}`.
2. Сервер: валидация → запись в БД → `outbox`-очередь → Telegram `sendMessage` владельцу (бот, `chat_id` из переменных окружения) → письмо на `avtotehservis439@mail.ru` через SMTP → при неудаче — ретраи с отступом → статус виден в реальной админке.
3. Если Telegram недоступен — письмо всё равно уходит; если оба канала упали — заявка остаётся в БД, клиент не видит ошибку (видит «принято, номер такой-то»), доставка повторяется автоматически.
4. Токен бота, `chat_id`, пароль SMTP — только в переменных окружения сервера. В этом мокапе таких значений нет нигде: ни в HTML, ни в JS, ни в комментариях.

## 9. Заглушки — что демонстрационное

- Все изображения (hero, услуги, галерея, новости, карта) — CSS/SVG-заглушки, не реальные фото.
- Видео в галерее в этом раунде не делали (в брифе раунда 2Б видео-карточка не требуется явно, в отличие от раунда 2А) — оставили фото-кейсы по `docs/07-photo-brief.md`.
- Номер заявки (`№ ATS-XXXXXX`) генерируется случайно на клиенте, никуда не отправляется.
- Новости (8 карточек) — целиком демо-контент без привязки к реальным событиям; специально избегали конкретных цифр в разделе «Акции», чтобы не создавать ложные ожидания.
- Демо-отзывы (3 карточки без источника) помечены «Демо-отзыв», в отличие от трёх карточек с реальными источниками рейтинга (Яндекс/2ГИС/Zoon).
- Админка (`admin.html`) — без логина, без сохранения после перезагрузки, с явной плашкой «Демо-режим» вверху страницы; заявки в таблице — три выдуманных демо-записи с частично скрытыми телефонами.
- Политика конфиденциальности и согласие — короткие демо-тексты в модалках, требуют юридической проверки перед реальным запуском.

## 10. Чего не проверял (честно)

- Реальный рендеринг в браузере на 320/390/768/1024/1440 px — в песочнице нет headless-браузера (Chromium недоступен), проверка велась только статическим анализом CSS и логическим прогоном через `jsdom`.
- Автопрокрутку слайдера и свайп по тач-экрану — `jsdom` не умеет ждать реальные таймеры/тач-события так, как настоящий браузер; клики по стрелкам/точкам (тот же код) проверены и работают.
- Визуальное срабатывание `prefers-reduced-motion` и фокус-ловушку по полному перебору Tab — код присутствует и логически эквивалентен уже проверенным местам (Esc), но отдельным автотестом не прогонял.
- Фактический LCP/CLS/Lighthouse-метрики — не измерял, в среде нет браузера для аудита.
