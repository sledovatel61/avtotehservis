**Как проводилось функциональное тестирование.** В sandbox нет браузера (chromium/puppeteer недоступны, сеть ограничена только нужными registry-хостами), но `jsdom` установился из `npm` и позволил выполнить реальный JS-код мокапа в DOM-окружении. Прогнан сценарий: открытие квиза → ошибка на пустом шаге 1 → выбор ветки → шаг 2 без бренда (блок) → бренд заполнен → «не помню год» → VIN фильтрует I/O/Q → «не знаю VIN» → шаг 5 без чекбокса (блок) → чекбокс отмечен → телефон автоформатируется в `+7 (XXX) XXX-XX-XX` → короткий телефон блокирует → валидный телефон пропускает → шаг 7 без согласия (блок) → согласие отмечено → спиннер «отправка» → успех с номером заявки формата `№ ATS-XXXXXX`; далее лайтбокс (открытие/счётчик/next/Esc), видео-модалка (открытие/закрытие), мобильное меню (открытие/Esc), FAQ (8 пунктов), админка (вход без пароля → включение режима «слабая сеть» → публикация с ретраями → карточка реально появляется в живой галерее). **Итог: 34 проверки, 34 success, 0 провалов.** Это не замена ручного тестирания в реальном браузере на реальных устройствах, но даёт высокую уверенность, что логика (не вёрстка/визуал) работает как задумано.

## 2. Обоснованные решения

1. **Тёмная палитра сохранена из концепции**, но каждая пара текст/фон проверена числовым контрастом (раздел 4) — личное задание А1, а не произвольный выбор.
2. **Кнопки — тёмный текст (`#14181C`) на оранжевом, а не белый.** Белый на оранжевом даёт 2.87:1 (провал AA), тёмный — 6.23:1 (проход). Осознанно предотвращённая типовая ошибка тёмных UI.
3. **Квиз — 7 шагов с прогресс-баром**, главный CTA вместо статичной формы: по отраслевым источникам из Этапа 1 пошаговые опросники конвертят лучше формы.
4. **Единый источник фактов — таблица §7 промпта**, а не `Реквизиты.PDF.pdf` (файл не распознан инструментами в sandbox) — чтобы не внести непроверенные данные.
5. **Отзывы раздельно по источникам (Яндекс 4,5/182, 2ГИС 3,6/12, Zoon 2,2/1), без усреднения и без `AggregateRating`** — как требует бриф, без соблазна показать только лучшую цифру.
6. **Админка — демо без логина, без сохранения после перезагрузки**, с плашкой «Демо-режим»: бриф прямо просит client-only прототип, не рабочую CMS.
7. **Личное задание «слабый интернет»**: переключатель в демо-админке — публикация идёт через симулированные повторные попытки (статус «попытка 1/3…» → успех на 2-й), наглядно показывая сценарий плохой связи на объекте, а не просто текстом.

## 3. Что является заглушкой/демо (и не должно восприниматься как финальный контент)

- Все фотографии в галерее — **CSS-градиенты + SVG-иконки**, подписаны как условные категории работ («шиномонтаж», «развал-схождение» и т.д.), это не реальные кейсы.
- Видео-карточка открывает модалку-заглушку с текстом «Здесь будет видео 20–30 с» — файла видео нет.
- Собственные отзывы (3 карточки) — обобщённый текст без сумм, дат, имён и обещаний, с пометкой «Будет заменено реальными отзывами после модерации».
- Номер заявки после отправки квиза (`№ ATS-XXXXXX`) — генерируется случайно на клиенте, никуда не отправляется.
- Админка целиком — демонстрационный экран без аутентификации и без сохранения данных; список из 3 «заявок» — заглушка.
- Карта — `.map-stub`: CSS/SVG-имитация с точкой и подписями, без встраивания стороннего iframe (ограничение брифа).
- Политика конфиденциальности и форма согласия в модалках — заглушочный текст, подлежит юридической проверке перед запуском.
- Значения часов работы помечены как «подтверждено владельцем 21.10.2026» — остальные факты без даты подтверждения считать актуальными на момент Этапа 1/2.

## 5. Аналитика (события, заявленные в коде как `track()`)

Реализованы как единая функция `track(name, detail)`, которая сейчас только пишет в `console.log('[demo-analytics]', name, detail)` — это сознательная заглушка: в брифе сказано «перечисли события в заметках», без требования реальной интеграции с GA/Я.Метрикой на этапе мокапа.

| Событие | Когда срабатывает |
|---|---|
| `quiz_open` | Первый просмотр блока квиза (через IntersectionObserver) |
| `step_view` | Переход на новый шаг (вызывается из `showStep()`), с номером шага |
| `step_next` | Нажатие «Далее» (успешное или заблокированное — фиксируется всегда, фактический переход см. `step_view`) |
| `step_back` | Нажатие «Назад» |
| `skip_vin` | Нажатие кнопки «Не знаю VIN» |
| `quiz_submit_attempt` | Нажатие «Отправить» на шаге 7 (до результата) |
| `quiz_success` | Успешное завершение симулированной отправки, вместе с сгенерированным ID заявки |
| `call_click` | Клик по любой `tel:`-ссылке (шапка, sticky-bar, контакты) |
| `telegram_click` | Клик по ссылке Telegram |
| `route_click` | Клик по ссылке «Построить маршрут» / источник на Яндекс.Картах |

## 6. Анимации (§9) — таблица

| Эффект | Триггер | Длительность | Свойства | Поведение при `prefers-reduced-motion` |
|---|---|---|---|---|
| Появление карточек при скролле | `IntersectionObserver` на карточки услуг/галереи/отзывов | 220 мс | `opacity`, `transform: translateY` | Отключено — элементы сразу видимы без сдвига |
| Открытие лайтбокса | Клик по карточке галереи | 180 мс | `opacity` фона + `transform: scale` на изображении | Отключено — мгновенное появление |
| Появление sticky-бара | Выход первого экрана (hero) из вьюпорта | 200 мс | `transform: translateY`, `opacity` | Отключено — бар появляется без анимации |
| Переход между шагами квиза | Клик «Далее»/«Назад» | 160 мс | `opacity` + `transform: translateX(8px)` | Отключено — шаг меняется мгновенно |
| Нажатие кнопки | `:active` на `.btn` | 100 мс (CSS transition) | `transform: scale(.98)` | Отключено |
| Открытие модалок (политика/согласие/отзыв/видео) | Клик по ссылке/кнопке | 180 мс | `opacity` + `transform: scale(.96→1)` | Отключено |
| Раскрытие FAQ (`<details>`) | Клик по вопросу | 150 мс | `max-height`/`opacity` на `.faq-a` (через нативный `<details>` + CSS) | Отключено — раскрытие без плавности |

Все переходы используют только `transform`/`opacity` (плюс нативный `<details>`), укладываются в 100–220 мс (диапазон 120–300 мс соблюдён с запасом на нижней границе для кнопки — осознанно короче, чтобы не ощущалось как лаг при частом нажатии).
