## 2. Блокер A6 воспроизведён — и не одним способом

### 2.1. Прямой запрос к приложению

```
30 заявок с X-Forwarded-For: 1.1.1.1  → 30 × 201
31-я с тем же XFF                     → 429          ← лимит реально работает
32-я с XFF: 2.2.2.2                   → 201          ← новый бакет
33-я с XFF: 3.3.3.3                   → 201
```

### 2.2. Через прокси с семантикой nginx из `deploy/`

Это ключевая проверка: клиент не может «просто так» подставить заголовок — это должен пропустить прокси. Смоделировал ровно то, что делает конфиг:

```nginx
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # "<клиентский XFF>, <реальный IP>"
```

```
30 заявок через прокси, клиент шлёт XFF 5.5.5.5  → 30 × 201
31-я, тот же XFF                                → 429
32-я, XFF 6.6.6.6 (реальный адрес не меняется)   → 201
```

Обход работает **в боевой схеме**, а не только при прямом доступе к Node.

### 2.3. Перебор пароля администратора — блокировка снимается полностью

```
10 попыток «wrongpass» с ротацией XFF через прокси:
  401 × 10, ни одной блокировки
контроль: 6 попыток без подмены (один адрес):
  401 × 5, на 6-й — «Слишком много попыток входа. Повторите через 15 минут.»

прямой доступ, 8 попыток с ротацией XFF → 401 × 8, блокировки нет
```

Причина одна на всё: `clientIp()` и `loginRateKey()` берут **первый** элемент `X-Forwarded-For`, а nginx дописывает реальный адрес **в конец**. Первым остаётся то, что прислал клиент.

**Это не регресс третьего круга.** Тот же код был в первом коммите `b8cb474` — я проверил `git show`. Но в третьем круге IP стал единственным жёстким ключом квоты, и дефект из «косметического» превратился в дыру: заявки льются в Telegram владельца без ограничения, а пароль админки можно перебирать бесконечно.

**Требование задания не выполнено:** §12 — «Rate-limit: заявки 5/час с IP, загрузки 30/час, вход 5/15 мин». Лимит «с IP» существует формально и не работает.

## 3. Чего A6 не сказал: наивные способы починки не работают

Проверил два очевидных варианта — оба не годятся, и это важно передать автору, чтобы не потратить круг.

**Вариант «взять `Astro.clientAddress`».** Разобрал `@astrojs/node`: адрес берётся как `forwardedClientIp || req.socket.remoteAddress`, причём forwarded-заголовку доверяют только когда Host прошёл проверку `security.allowedDomains`. Проверил оба режима живьём:

| Конфигурация | `X-Forwarded-For: 6.6.6.6` | Итог |
|---|---|---|
| `allowedDomains` не задан (как сейчас) | `clientAddress = 127.0.0.1` | за nginx **все клиенты получат 127.0.0.1** → один общий бакет: 5 заявок в час на весь сайт, вход заблокируется после 5 чужих попыток |
| `allowedDomains` задан | `clientAddress = 6.6.6.6` | подделка проходит, `getFirstForwardedValue` берёт **первый** элемент |

То есть простая замена источника адреса либо оставляет дыру, либо делает сайт неработоспособным (fail-closed в худшем смысле).

**Вариант «переставить nginx и не трогать код».** Недостаточно: приложение всё равно читает первый элемент, а `$proxy_add_x_forwarded_for` оставляет клиентское значение первым.

Правильный минимум — **оба уровня**:

1. `deploy/nginx.conf`: `proxy_set_header X-Forwarded-For $remote_addr;` (перезапись, а не дописывание; `X-Real-IP $remote_addr` уже стоит).
2. Приложение: один хелпер `clientIp()` — сначала `X-Real-IP`, затем **последний** элемент `X-Forwarded-For`, затем `'local'`; и `loginRateKey()` должен вызывать его же, а не дублировать разбор.
3. Тесты: ротация XFF → 429 и блокировка входа.

## 4. Minor — подтвердилось

1. **`phones_extra` — мёртвая настройка.** В админке есть шесть полей («Доп. 1/2 — название/показ/tel»), `E0`/`E1` объявлены в **14 файлах** и ни разу не используются; сменил номера в настройках — на `/`, `/contacts`, `/about` **0 вхождений**. Это не расходится с утверждённым мокапом (там тоже только основной телефон и Telegram), но владелец будет править поля, которые ничего не делают. Либо выводить, либо убрать из админки и кода.
2. **`Range: bytes=100-50` → 500.** `Buffer.alloc(end - start + 1)` при `end < start` получает отрицательный размер. Баг старый, но стоит рядом с уже починенным 416 — чинится одной строкой (`416`).
3. **`'local'` при отсутствии заголовка** — все клиенты в одном бакете. За nginx не проявляется, при прямом `npm start` делает лимит 5/час общим на весь сайт. Закроется тем же хелпером.
