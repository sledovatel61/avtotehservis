## 1. Формулировка задания (как получена)

Задание пришло сообщением, а не файлом. Ниже — полная фиксация требований, чтобы следующий
круг не восстанавливал их по памяти. Формулировки владельца сохранены, комментарии агента
помечены.

**Вопрос.** Реализуем ли 3D-фон на странице Voyah Free и стоит ли его включать.

**Что сделать:**

1. Своя ветка, сдача — PR в `main`.
2. Два прототипа: **«глубина»** (вариант A) и **«силуэт в глубине»** (вариант B).
3. Свой шейдер, **≤ 14 КБ gzip**, **0 текстур**.
4. **Пауза вне экрана.**
5. **Автоотключение на слабых устройствах.**
6. Поддержка **`prefers-reduced-motion`** и **`saveData`**.
7. Кнопка **«выключить»**.
8. Честный вердикт с цифрами: **fps на 4 профилях**, **вес**, **батарея**, **память после 20 переходов**.
9. **«Не стоит» — тоже приемлемый результат.**

Требования 3–7 заданы как жёсткие лимиты и гейты, а не как пожелания: их несоблюдение — блокер.
Требование 8 прямо разрешает отрицательный вердикт, поэтому «не включать» считается полноценным
результатом работы, а не её провалом.

### 1.1 Что агент добавил от себя (и почему)

Задание не оговаривало четыре вещи, без которых его нельзя выполнить корректно. Решения приняты
агентом и зафиксированы здесь, чтобы владелец мог их отменить:

| Решение | Почему |
|---|---|
| Фон **выключен по умолчанию** (`BG3D=off`), включается переменной окружения | Действующие документы проекта запрещают WebGL/3D: `prompts/00-universal-agent-prompt.md:81` и `docs/00-brief.md:65`. Отменять запрет агента не уполномочивали — значит, код обязан поставляться неактивным |
| Белый список страниц (`BG3D_PAGES`) в коде, а не в админке | Фон — это шейдер и бюджет GPU, а не контент; владелец не должен иметь возможность включить его случайно при редактировании услуги |
| Лаборатория `/lab/bg3d` (только при `BG3D_LAB=1`, `noindex`) | Требование 8 (fps, батарея, память) нельзя снять без стенда, где переключаются вариант, качество, масштаб и частота; на боевых страницах такой стенд — дыра |
| Замеры в песочнице + харнесс для живого браузера | В среде нет GPU и браузера (см. §2.4): часть цифр — модель, и это помечено в каждом отчёте |

## 2. Расхождения с репозиторием

### 2.1 Файла задания нет

В `prompts/` лежат задания `00`–`18`; файла `44-task-r30-bg-3d.md` в чекауте нет, в истории
`main` он тоже не появлялся. Спецификация восстановлена из сообщения и зафиксирована в §1.
**Самодельный файл в `prompts/` агент не создавал**: подделывать документ владельца нельзя,
а этот файл — единственный источник правды о том, что именно было задано.

### 2.2 Базы `51eae33` не существует

Задание называло базовым коммитом `51eae33`. В репозитории такого объекта нет:

```
$ git cat-file -t 51eae33          # → fatal: Not a valid object name
$ git rev-parse origin/main        # → d0c382f31fc228c39e995606208d1c70e69ff0b1
```

Работа начата от фактического `main` = `d0c382f`. Расхождение указано в описании PR: если
`51eae33` существует в другой копии репозитория, ветка переставляется на неё без конфликтов —
изменения не пересекаются с чужими файлами, кроме одной страницы (`site/src/pages/services/[slug].astro`,
2 строки импорта + 1 строка в разметке).

### 2.3 Страницы Voyah Free нет

Задание говорит о «странице Voyah Free», но услуги с таким slug в репозитории нет:

```
$ curl -o /dev/null -w '%{http_code}' http://localhost:4321/services/voyah-free   # → 404
```

В базе (и в `scripts/seed.ts`) услуги `voyah-free` нет, отдельной страницы модели Voyah Free
тоже нет — есть общий шаблон `site/src/pages/services/[slug].astro`, который рисует любую
услугу из таблицы `services`.

**Следствие для работы:** интеграция сделана так, чтобы включиться ровно в тот момент, когда
страница появится, и не трогать сайт до этого:

- `site/src/server/bg3d-config.ts` — белый список `BG3D_PAGES = { 'voyah-free': 'silhouette' }`
  и разбор флага окружения;
- `site/src/pages/services/[slug].astro` — `{bg3d.enabled && <Bg3dLayer variant={bg3d.variant} />}`;
- замеры сняты на лабораторном стенде `/lab/bg3d` (тот же слой, тот же шейдер, те же ворота),
  а в тесте интеграции услуга с нужным slug заводится во временной базе
  (`site/tests/bg3d.test.ts`, блок «ИНТЕГРАЦИЯ СО СТРАНИЦЕЙ»).

То есть «страницы нет» не сняло ни одного требования: слой, шейдер, ворота и замеры существуют
и проверены, а точка подключения — одна строка в шаблоне услуги.

### 2.4 В среде нет GPU и браузера

Песочница: `Intel(R) Xeon(R) @ 2.60GHz`, **2 ядра**, Node v22.22.3, ни одного браузера,
ни Mesa/llvmpipe, хосты загрузки браузеров Playwright/Puppeteer недоступны. Поэтому:

- **измерено** здесь: вес, компилируемость шейдера (Khronos glslang WASM), состав SPIR-V,
  стоимость кадра в операциях (CPU-порт шейдера), нс/пиксель на CPU, жизненный цикл и память
  JS-стороны (jsdom + mock-WebGL, 20 циклов);
- **смоделировано**: fps и батарея (формулы и источники констант — `method.md` §4–5), погрешность ±50 %;
- **не измерено вовсе**: реальные fps, реальное время GPU, реальная память драйвера, тепловой
  троттлинг, поведение iOS Safari. Для этого написан харнесс `site/scripts/bg3d-device-metrics.mjs`,
  который в этой среде честно отказывается запускаться и печатает инструкцию.

Это напрямую влияет на вердикт: включать фон по умолчанию на основании модели — нечестно
(подробнее в `verdict.md` §4.3).
