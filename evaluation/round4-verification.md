## 2. Блокер B1 — воспроизведён через настоящую админку

Не через SQL, а так, как это сделает владелец:

1. Вход в `/admin` (создал администратора, реальный POST логина с CSRF и `Origin`).
2. Открыл `/admin/settings`, очистил три поля «Источник» рейтингов, отправил форму.
3. Ответ: `302 → /admin/settings?msg=Настройки сохранены`.
4. `ratings` в БД стало `[]`.

```
GET /        → 500
GET /about   → 500
лог: 18:23:51 [ERROR] TypeError: Cannot read properties of undefined (reading 'url')
     at Object.default (…/index_…mjs:69:1187)
```

**Хуже, чем в ревью:** после сохранения форма настроек рендерит **ноль строк рейтингов** (`S.ratings.map` по пустому массиву), поэтому вернуть их через админку нельзя вообще — только правкой БД. То есть одно нажатие «Сохранить» безвозвратно ломает главную и «О компании».

**Почему это блокер, а не minor:** главная страница — точка входа и рекламы; отказ наступает от штатного действия владельца, а `npm test` (48/48) и `/api/health` (200 ok) этого не видят. Сайт «зелёный» по всем метрикам и мёртвый для клиента.

**Минимальный фикс:** `S.ratings[0]?.url ?? S.map_link` в `index.astro:256` и `about.astro:136`; в форме — всегда показывать 3 строки (в том числе пустые), чтобы рейтинги можно было вернуть. Плюс тест: `settings.ratings=[]` → `/` и `/about` = 200.

## 3. Major M1 — воспроизведён полностью, через UI

```
1. POST /api/uploads → upl_-bJAbNwheY7P (attached_to = NULL)
2. POST /admin/cases/1  action=cover media_id=upl_-bJAbNwheY7P
   → 302 «Обложка обновлена»; cases.cover_media_id = upl_-bJAbNwheY7P; media.attached_to остаётся NULL
3. POST /admin/media    action=delete id=upl_-bJAbNwheY7P
   → 302 «Медиа удалено»
```

Результат: `media` — 0 строк, каталог `/tmp/rr6media/upl_-bJAbNwheY7P` удалён, `cases.cover_media_id` молча обнулён, на сайте — заглушка. Владелец не получил ни ошибки, ни предупреждения.

Правильно спроектированная защита (загрузка через карточку кейса, `attached_to='case:N'`) работает — значит дефект локальный: действие `cover` не ставит привязку.

**Фикс:** в `action === 'cover'` писать `attached_to = 'case:<id>'` (и снимать привязку у прежней обложки), либо в `canDelete` добавить проверку `EXISTS(cases WHERE cover_media_id=? AND status='published')` — так же для `news`. Тест: «обложка published-кейса из библиотеки → удаление запрещено».

## 4. Major M2 — воспроизведён, обход реальный

```
8 заявок, 8 разных cookie ats_cid → 201 × 8, в БД +8
7 заявок, одна cookie ats_cid      → 201 × 5, затем 429 × 2
```

Ключ лимита — `ip|cid`, где `cid` целиком из cookie клиента. Требование было «дополнить ключ cookie к IP», а не «заменить IP на cookie». Как только IP-часть перестаёт быть самостоятельным уровнем, ограничение снимается одним заголовком `Cookie` — достаточно любого HTTP-клиента.

**Фикс:** два уровня, считаются оба — жёсткий по IP (`RATE_LIMIT_LEADS_IP`, например 30/час; антифлуд 60/10 мин) и мягкий по `ip|cid` (5/час). Тест: 10 валидных заявок с 10 разными cookie → после N-й 429.

## 6. Наблюдения сверх ревью

1. **Три регрессии за один раунд при 48/48 зелёных тестах** — это не случайность, а дыра в классе тестов: нет ни одного теста «действие в админке не ломает публичные страницы» и ни одного теста на медиа-привязки. B1, M1 и M2 объединяет одно: они живут на стыке админки и публичной части, где тестов нет.
2. **Диагностика B1 будет стоить владельцу простоя.** Ни `health`, ни журнал, ни UI не предупреждают, что публичная страница падает. Предложение: после сохранения настроек делать самопроверку (`GET /` внутри процесса) и при 500 откатывать транзакцию с сообщением в интерфейсе — либо, как минимум, ловить ошибку рендера и отдавать `500.astro` с телефоном, а не пустой экран.
3. **`ignore-scripts=true`** — решение верное и объяснено в `.npmrc`; prebuilds для `better-sqlite3` и `sharp` проверены запуском. Побочно: supply-chain-риск снижен.
4. **Ветка тянет 46 файлов вне `site/`** (мокапы A5 в `mockups/agent-05/`, `agents/agent-05/`, удаление `mockups/agent-05/mockup.html`). Приёмка — по-прежнему частичная: только `site/**` и `docs/12-content-checklist.md`.

## 7. Вердикт оркестратора

**Работу не принимаю.** Блокер воспроизведён штатным путём через админку, оба major — тоже, причём M1 и M2 бьют ровно по обязательным требованиям (сохранность фото работ и защита форм от ботов).

Оценка ревью A6: **сильное, доказательное, с корректным разделением «проверено / не проверено»**. Две неточности (minor 6 и замечание 8.1) на вердикт не влияют; закрытие прошлых блокеров подтверждено независимо.

До приёмки осталось **три правки объёмом ~20 строк** плюс три теста. Четвёртый круг — короткий, только по этим пунктам.
