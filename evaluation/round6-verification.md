## 4. Чего не увидели ни A5, ни A6: пустые лимиты убивают приём заявок

**Это блокер приёмки, а не стилистика.**

`.env.example` содержит **активные** строки с пустыми значениями:

```
# Лимиты (необязательно; значения по умолчанию в src/server/ratelimit.ts):
RATE_LIMIT_LEADS=
RATE_LIMIT_LEADS_IP=
RATE_LIMIT_UPLOADS=
RATE_LIMIT_ANTIFLOOD=
RATE_LIMIT_ANTIFLOOD_IP=
```

`deploy/deploy.md` §4 велит: `cp .env.example /etc/avtotehservis/env` и перечисляет лимиты как **необязательные**. systemd `EnvironmentFile` превращает `RATE_LIMIT_LEADS=` в переменную с **пустой строкой**. А код читает так:

```ts
const maxLeads = Number(process.env.RATE_LIMIT_LEADS ?? LIMITS.leads.max);
```

`??` не спасает от пустой строки — она не `null`/`undefined`. `Number('') === 0` → лимит **0** → `arr.length >= max` истинно всегда.

**Воспроизведено** на инстансе с пустыми `RATE_LIMIT_*` (ровно то, что даёт `cp .env.example`):

```
POST /api/leads   → 429 {"error":{"code":"too_many","message":"Слишком много обращений к форме…"}}
POST /api/uploads → 429 {"error":{"code":"too_many","message":"Слишком много загрузок…"}}
```

То есть на сервере, развёрнутом по инструкции, **сайт не принимает ни одной заявки и ни одного фото**, а выглядит это как «сработала защита от спама». Ни `health`, ни журнал об этом не скажут. Гейт G7 в такой конфигурации недостижим в принципе — и именно поэтому дефект важнее остальных мелочей.

**Откуда взялось:** строки появились в `837b349`, когда закрывали minor-6 первого ревью («лимитов нет в `.env.example`»). Формально закрыли, фактически добавили ловушку: раньше переменных не было вообще — и `??` работал.

**Тот же класс, мягче:** `SESSION_SECRET=` (пустой) не ломает сайт, но соль хеша IP становится пустой — `hashIp` использует `?? 'avtotehservis'`, а пустая строка не `null`. Приватность слабеет молча.

**Почему не поймали тесты:** `npm test` не выставляет переменные окружения пустыми — проверяется поведение по умолчанию, а дефект живёт ровно в конфигурации из документации.
