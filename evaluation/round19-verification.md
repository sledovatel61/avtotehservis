Дата: 27.10.2026. Ветка: `arena/099a14c5-avtotehservis`. Работа A5: `arena/c0d7d4ba-avtotehservis`,
коммит **`7c7fa57`**. Ревью A6: `4b5ee83`, вердикт **APPROVE WITH COMMENTS** (2 major, 7 minor).

**Принято с правками.** Правки касаются трёх вещей, которые ревьюер либо не мог увидеть из своей

(2) проверка зон в гейте была тавтологичной, (3) контраст мерился на одном окне из пяти.

## 1. Главный дефект: на Pages фон секции не грузился вообще

Это не мелочь и не косметика: на `https://sledovatel61.github.io/avtotehservis/` секция выглядела
бы **почти как до круга** — плоская плашка с фотками только в карточках, а большой фон за заголовком
не появлялся. Ни A5, ни A6 этого не поймали, потому что оба проверяли локальную сборку под корнем
сайта, а не под префиксом `/avtotehservis/`.

### Причина

Фон секции был объявлен CSS-ом через `image-set()` внутри `@supports`:

```css
@supports (background-image:image-set(url('/img/tri-bg-2560.avif') type('image/avif'))){
  .dirs{background-image:image-set(url('/img/tri-bg-2560.avif') type('image/avif'), url('/img/tri-bg-2560.webp') type('image/webp'))}
}
```

Минцификатор сборки переписал внутреннее объявление в **голые строки**:

```css
.dirs{background-image:image-set("/img/tri-bg-2560.avif" 1x type("image/avif"),"/img/tri-bg-2560.webp" 1x type("image/webp"))}
```

`export-pages.mjs` умел добавлять префикс `/avtotehservis` только к ссылкам вида `url(/img/…)`.
Голые строки он не видел → в собранном CSS осталось `/img/tri-bg-2560.avif` → на Pages это
`https://sledovatel61.github.io/img/...` → **404**, фон не рисуется. Локально под корнем всё работало,
поэтому все проверки были зелёные.

### Что сделано

1. **Фон секции переведён на слой `<picture>`, как у карточек** (это же и правильнее по смыслу):
   `<div class="dirs-bg"><picture><source media="(max-width:640px)" type="image/avif" srcset="/img/tri-bg-m-900.avif">…</picture></div>`,
   `position:absolute; inset:0; z-index:0`, `.dirs::before` — затемнение `z-index:1`, контейнер — `z-index:2`.
   Побочная выгода: мобильный кадр выбирается `<source media>`, а не `@supports { @media { … } }`,
   и avif/webp раздаются честно.
2. **`export-pages.mjs` научился префиксовать оба вида ссылок** — и `url(/img/…)`, и голые строки
   внутри `image-set("…")`; правило `(,\s*)(["'])/(?!//)` с проверкой расширения.
3. **`check-pages.mjs` теперь проверяет CSS-ссылки и `srcset`.** Раньше он смотрел только HTML.
   Теперь: каждый `url(…)`, каждая строка внутри `image-set(…)`, каждый элемент `srcset` обязаны
   начинаться с `/avtotehservis/` и указывать на существующий файл.
   Прогнал мутанта: вписал в собранный CSS `.mut1{background-image:url(/img/tri-bg-2560.webp)}` →
   гейт упал строкой `Unprefixed CSS asset: /img/tri-bg-2560.webp`, exit 1. После восстановления — PASS.

### Проверка, что фон теперь реально приходит

Рендер Chromium 153 по сети, а не по `getComputedStyle`:

| окно | что запрашивается | статус |
|---|---|---|
| 1440×900 | `tri-bg-2560.avif` | **200** |
| 1024×600 | `tri-bg-2560.avif` | **200** |
| 390×844 | `tri-bg-m-900.avif` | **200** |

До правки в сети было `404 /img/tri-bg-2560.avif` — то есть браузер получал фон секции
без префикса и не рисовал ничего.

## 6. Ограничения (честно)

1. **Боевой URL из песочницы не открывается** (сетевой allowlist). Выкладка проверена так:
   успешный run Pages, содержимое ветки через API, и локальный рендер того же дерева под префиксом
   `/avtotehservis/` — именно он и поймал дефект с 404.
2. **`prefers-reduced-data`** — правило есть, но движок не поддерживает; поведение не проверено.
3. **Мастера карточек — апскейл ×2,08** из raw генератора 1376–1408 px (замечание A6 §3). Под скримом
   0,76–0,92 и в тёмной палитре мягкость не читается; на 1440 браузер берёт `-640` (1,7× карточки),
   то есть всегда уменьшает. Если заказчик захочет резче — нужна перегенерация в большем разрешении.
4. **`tri-bg-960` удалён** — решение принято: на 768 грузится `tri-bg-2560` (34,1 КБ), это в лимите;
   отдельный файл ради 10 КБ экономии не окупает лишнюю ветку в разметке.
