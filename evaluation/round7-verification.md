## 1. Блокер закрыт — проверен в трёх конфигурациях

| Конфигурация | Ожидание | Результат |
|---|---|---|
| Все `RATE_LIMIT_*` пустые (как после `cp .env.example`) | заявка и загрузка проходят | **201 / 201** (было 429 / 429) |
| `RATE_LIMIT_LEADS=0`, `ANTIFLOOD=abc`, `ANTIFLOOD_IP=-5`, `UPLOADS=' '`, `LEADS_IP=3` | мусор → дефолты, валидное число соблюдается | 201, 201, 201, затем **429** на 4-й — жёсткая квота 3 работает |

Код: `limitFromEnv(name, dflt)` — `undefined`, пустая строка, пробелы, `0`, отрицательные и нечисловые значения дают значение по умолчанию; положительное число применяется. Все пять чтений лимитов переведены на хелпер (`grep "Number(process.env"` по `src/` — остался только `SMTP_PORT`, где стоит `||`).

`.env.example`: строки `RATE_LIMIT_*` **закомментированы**, рядом предупреждение не оставлять активных пустых `VAR=`. `deploy.md` §4 больше не предлагает их заполнять и объясняет, что дефолт действует при незаданной **или пустой** переменной.

## 2. Главная проверка: развёртывание «как на сервере»

Собрал окружение ровно из `.env.example` (18 переменных, из них 9 пустых), подставил только обязательные `PUBLIC_SITE_URL/HOST/PORT/DATA_DIR/MEDIA_DIR` — то есть сделал то, что предписывает `deploy.md` §4. Запустил собранный сервер:

```
GET /  /about  /services  /appointment  /contacts  /privacy  /api/health  → 200 ×7

POST /api/leads   (X-Real-IP + X-Forwarded-For как от nginx) → 201, талон A-2210-1146
POST /api/uploads (фото 600×400)                              → 201, /media/upl_…/master.jpg
POST /admin/login                                             → 302 → /admin → 200
32 заявки с одного IP                                          → 30×201, затем 429
```

То есть **сайт на сервере, развёрнутом по инструкции, принимает заявки, фото и пускает владельца в админку** — а защита от спама при этом работает на дефолтах. Именно это и было сломано до правки.
