# АвтоТехСервис — сайт (Astro + SQLite)

Продакшн-реализация утверждённого мокапа `mockups/round2b/agent-05/` (заказчик выбрал 21.10.2026). Задание — `prompts/04-implementation-task.md`.

## Быстрый старт (разработка)

```bash
npm ci
npm run migrate      # схема БД → data/site.sqlite3 (gitignored)
npm run seed         # услуги, кейсы-заглушки, марки; БЕЗ демо-заявок/отзывов/новостей
npm run admin:create -- owner "пароль-не-короче-12"
npm run dev          # http://localhost:4321  (или HOST=0.0.0.0 npm run dev)
```

В `site/.npmrc` включён `ignore-scripts`: better-sqlite3@13.0.3 ships с готовыми бинарниками (`prebuilds/`), но `npm ci` из-за lockfile v3 не видит флаг `gypfile:false` пакета и пытался бы собрать его из исходников (нужны компилятор и доступ к nodejs.org). Других зависимостей, которым нужны install-скрипты, в дереве нет (подробности — в комментариях внутри `.npmrc`).

Продакшн: `npm run build && npm start` (один процесс node, `dist/server/entry.mjs`). Деплой — `deploy/deploy.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | локальная разработка |
| `npm run build` | сборка (сервер + клиент) |
| `npm start` | запуск собранного сервера |
| `npm run migrate` | миграции SQLite (отдельно от старта — как требует задание) |
| `npm run seed` | наполнение услугами/настройками/кейсами-заглушками |
| `npm run seed:demo` | демо-новости и демо-отзывы для показа (отдельно от `seed`; помечены: `news.slug 'demo-*'`, `reviews.source='demo'`) |
| `npm run seed:demo:clear` | удаляет **только** помеченные демо-записи |
| `npm run smoke -- <url>` | проверка живого сервера одной командой (по умолчанию `http://localhost:4321`); каждая проверка — строка `ok`/`FAIL`, код выхода 1 при любом падении |
| `npm run admin:create` | создать администратора (пароль печатается один раз) |
| `npm test` | unit + интеграционные + E2E + админка (pretest сам делает build) |
| `npm run typecheck` | `tsc --noEmit` (TS strict) |
| `npm run audit` | `npm audit --omit=dev` |

> **Демо-отзывы — вымышленные люди.** Их нельзя оставлять на боевом сайте: перед запуском
> выполните `npm run seed:demo:clear` (подробнее — `docs/13-launch-checklist.md` §6).

## Стек и версии (зафиксированы 21.10.2026, совпали с заданием)

astro 7.4.1 · @astrojs/node 11.1.9 (standalone) · better-sqlite3 13.0.3 · zod 4.6.7 · sharp 0.35.5 · nodemailer 10.1.7 · telegraf 4.16.3 · typescript (dev) · jsdom (dev, только тесты). Клиентский JS — нативный TypeScript, без фреймворков. CSS — из мокапа (13 слоёв + utils + admin), без библиотек.

Отклонения от ориентиров задания (честно):
- **Node**: в песочнице разработки v22.22.3, не 24.22.0. Код совместим: type-stripping (`node scripts/*.ts`) работает на ≥22.18 и на 24; на сервер ставить 24.x по `deploy.md`. `engines: >=22.18`.
- Скрипты запускаются нативным `node` без tsx/ts-node (меньше зависимостей).
- Встроенная сессия @astrojs/node (filesystem) не используется — свои сессии в БД (хеш токена, 7 дней).
- `security.checkOrigin` Astro отключён: встроенная проверка сверяет Origin с `site`-конфигом, а не с Host запроса; реализована своя (double-submit cookie + Origin/Referer против Host и `PUBLIC_SITE_URL`).

## Переменные окружения (`.env.example` → копия на сервере)

`PUBLIC_SITE_URL`, `HOST`, `PORT`, `DATA_DIR`, `MEDIA_DIR`, `BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_API_BASE` (для тестовой заглушки), `SMTP_HOST/PORT/SECURE/USER/PASS`, `MAIL_FROM`, `MAIL_TO`, `SMTP_JSON_DIR` (тестовый транспорт: письма в каталог JSON-файлами), `SESSION_SECRET`, `FFMPEG_PATH` (опционально: автопостер и проверка длительности видео), `RATE_LIMIT_LEADS/LEADS_IP/UPLOADS/ANTIFLOOD/ANTIFLOOD_IP` (лимиты заявок двухуровневые: жёсткий по IP + мягкий IP+cookie; значения по умолчанию и пояснения — в `.env.example` и `deploy/deploy.md`). Секреты — только env; в git — лишь `.env.example` без значений.

## Архитектура заявок (ноль потерь)

`POST /api/leads` → zod-валидация → одна транзакция: `INSERT leads` (UNIQUE `idempotency_key`) + 2 строки `outbox` → `201 {ticket}` (клиент видит номер до доставки) → воркер (старт + каждые 30 с) доставляет: Telegram (telegraf, `TELEGRAM_API_BASE`) и письмо (nodemailer/SMTP) → ретраи 1/5/30 мин/2/6 ч, максимум 8 попыток → `failed` + красный бейдж и кнопка «Отправить ещё раз» в админке. Занятый слот → `409` со списком свободных. Honeypot и мгновенная отправка — тихо игнорируются. IP — только хешем, телефоны в логах маскируются.

## Отчёт о тестах (22.10.2026, `npm test` — 58 проверок, все зелёные)

Запускалось в песочнице Node 22.22.3, без сети и реальных Telegram/SMTP (транспорты подменены локальными заглушками — как требует задание §8.9):

- **Unit (16):** телефон всех форм → `+7XXXXXXXXXX`; год 1975/2027 отклоняются, 1980/2026 принимаются; VIN с I/O/Q отклоняется; пробег >2 млн отклоняется; whitelist услуг из БД + «diagnostika»; согласие обязательно; uuid v4; **серверные сообщения валидации — всегда по-русски** (английские дефолты zod подменяются); талон `A-DDMM-XXXX` уникален на 300 генерациях; 10 слотов 09:00–18:00, окно 14 дней; Markdown-санитайзер (сырой HTML экранируется, `javascript:`-ссылки не проходят); маскировка телефонов в логах; бэкофф `[1,5,30,120,360…]`, лимит 8; сигнатуры JPEG/PNG/WebP/AVIF, SVG отклоняется; scrypt-хеш/проверка; **`limitFromEnv`: пустая строка, пробелы, `0`, мусор и отрицательные значения → дефолт, валидное число → число (блокер ревью round5 — `cp .env.example` с активными пустыми `RATE_LIMIT_*` через systemd давал `Number('')=0` → лимит 0 → 429 на каждую заявку и загрузку)**; **`seed:demo` помечает все записи и идемпотентен, `seed:demo:clear` удаляет только помеченное — реальные отзыв и новость не трогает**.
- **Интеграционные (26, шесть поднятых серверов + HTTP-заглушка Telegram):** полный сценарий 201→БД→outbox→обе доставки `sent` (в письме и Telegram-сообщении — номер); идемпотентность (тот же ключ → тот же талон, одна заявка, 2 строки outbox); вместимость слота → 409 со свободными; 400 с перечнем полей (11 кейсов); устаревшее согласие → 400; honeypot/мгновенная отправка не сохраняются; обращение контактов → `K-DDMM-XXXX`; загрузка фото (10 файлов sharp-вариантов, выдача `immutable`, SVG → 400, 16 МБ → 413, path traversal → 404); фото привязываются к заявке; **Telegram упал → письмо ушло**; **SMTP упал → Telegram ушёл**; **оба упали → заявка в БД, догоняющая доставка**; ручной ретрай; **квота заявок тратится только на успешные создания: 5 невалидных → 400 каждая, затем 201/201 и лишь после исчерпания квоты — 429 с Retry-After**; **механика антифлуда: peekLimit не расходует, consumeLimit расходует**; **health на сервере с пустой БД → 503 `degraded` (schema=false, db=true, каталоги записываемы)**; **пустые рейтинги (`settings.ratings='[]'`) не роняют `/` и `/about` — 200**; **двухуровневые лимиты: 5 заявок с одной cookie проходят, ротация `ats_cid` упирается в жёсткую квоту по IP (429), шквал невалидных с ротацией cookie — в жёсткий антифлуд по IP**; **свежеопубликованный кейс сразу виден на `/` и `/about` первым в галерее**; **клиентский IP из прокси-заголовков (блокер ревью round5): при жёсткой квоте 3/ч на IP десять заявок с ротацией ПЕРВОГО значения `X-Forwarded-For` дают 201×3 и 429 начиная с 4-й — и с `X-Real-IP` (перезапись nginx), и без него (по последнему элементу XFF); два клиента с разными `X-Real-IP` не мешают друг другу**; **перевёрнутый `Range: bytes=100-50` → 416, а не 500**; **сервер с ПУСТЫМИ `RATE_LIMIT_*` (как после `cp .env.example` + systemd `EnvironmentFile`) принимает первую заявку и первую загрузку — 201, а не 429**; страницы, 404 и 301 со старых `.html` (`service.html?s=` → `/services/slug`).
- **E2E формы (3, jsdom + живой сервер):** 5 экранов до серверного талона (маска телефона, ошибки под полями, слоты из `/api/slots`, черновик в localStorage, удаление черновика после успеха); prefill `?s=`, «не знаю — нужна диагностика», ASAP; короткая форма контактов → талон `K-`.
- **Админка (13):** без сессии редирект на вход; неверный пароль 401; блокировка после 5 попыток; CSRF-подделка и чужой Origin → 403; успешный вход (httpOnly, SameSite=Lax) + дашборд + журнал; заявка из формы видна в админке; смена статуса + запись в журнал; черновик кейса/новости не виден публично → публикация видна → скрытие убирает; выход уничтожает сессию; видео без постера отклоняется; **обложка опубликованного кейса, взятая из библиотеки, не удаляется (302 с err, строка media и файлы на месте), «Сделать обложкой» привязывает медиа к кейсу**; **сохранение настроек с пустыми источниками рейтингов → 302, `/` и `/about` живы, форма всегда с тремя строками рейтингов, возврат без правки БД, `tel:` хранится с «+»**; **блокировка входа не обходится ротацией первого значения `X-Forwarded-For`: 6 попыток → «Слишком много попыток» и с `X-Real-IP`, и без него (ключ — последний элемент XFF)**.
- **Бэкап/восстановление:** `backup.sh` (онлайн-копия БД + integrity_check + медиа) и `restore.sh` прогнаны фактически: копия восстановлена в отдельный каталог, `integrity_check=ok`, заявки на месте. Медиа-архив не зависит от имени каталога (`tar -C "$MEDIA_DIR" .`): цикл бэкап→удаление→восстановление повторно прогнан для каталога с пробелом и кириллицей в имени — содержимое вернулось побайтово.
- `npm audit`: **0 уязвимостей** (prod и full). `npm run typecheck`: чисто.

### Что НЕ проверено (и почему)

- **Lighthouse / LCP / CLS / INP** — в песочнице нет Chrome. Косвенные замеры (curl+gzip): HTML главной **9,0 КБ** (бюджет 120 КБ), JS на страницу **≤9,4 КБ gzip** (бюджет 100 КБ), CSS **11,2 КБ**, шрифты 88 КБ woff2 с preload двух критичных сабсетов; изображения — лёгкие SVG-заглушки с width/height, lazy ниже первого экрана. Рисков для ≥90 не видно, но числом не подтверждено.
- **Визуальная раскладка 320–1440, фокус-ловушки вживую, свайпы, View Transitions, эмуляция reduced-motion** — нет браузера; логика проверена jsdom, стили перенесены из мокапа побайтово (13 слоёв), инлайновые style заменены классами (CSP).
- **Реальные Telegram и SMTP** — нет доступов владельца (токен бота, пароль приложения mail.ru). Транспорты подменялись заглушками; коды отправки боевые.
- **Публикация кейса с настоящего телефона ≤60 с** — устройства нет; сценарий укладывается в 4 действия на одном экране (файлы → заголовок → «Опубликовать»), прогресс загрузки через XHR реализован.
- **Горизонтальный скролл на 320 px** — не проверялся в браузере (раскладка mobile-first из мокапа, `overflow-x` защищён).
- **`nginx -t`** — в песочнице нет nginx, конфигурация проверена только чтением. HTTP/2 включён совместимым со старыми версиями способом (`listen 443 ssl http2;` вместо `http2 on;`, которая требует nginx ≥1.25.1, а Debian 12 поставляет 1.22). На сервере перед reload обязательно выполнить `nginx -t` — это зафиксировано в `deploy/deploy.md`.
