## 2. Задача А. Фото сервиса: ретушь и подготовка

Исходник: `docs/photos-source/service-front-2026-10-22.jpg` (1600×900). Разбор — в

### А1. Что сделать с кадром

| Действие | Обязательно |
|---|---|
| Убрать серую машину с открытым капотом справа | да |
| Убрать мусорный бак и посторонние предметы слева/у входа | да |
| Выровнять перспективу (вертикали кирпичных стен — вертикальны) | да |
| Подтянуть экспозицию и цвет: тёмно-зелёный/тёплый тон в тон палитры, без «кислоты» | да |
| Заменить/успокоить небо (ровное, вечернее или пасмурное — под тёмную тему) | да |
| Сохранить вывеску: название и три телефона — **читаемы, не изменены, не замазаны** | да |
| Убрать/размыть регистрационные номера машин (на кадре читаются `Т888ТН 761`, `У046КС 161`) | да |
| Не менять архитектуру, количество ворот, бренды на баннере | да |
| Не добавлять людей, машины, оборудование, которых не было | да |

Если правишь генеративно (inpaint/img2img) — сохрани рабочий оригинал и пиши в отчёте, что именно
изменено. Промпт для редактирования — в §2.3.

### А2. Финальные файлы (положить в `site/public/img/`)

| Имя | Назначение | Размеры | Формат |
|---|---|---|---|
| `hero-service-<W>.avif` + `.webp` | фон первого слайда hero | 2560, 1600, 960, 640 по ширине | AVIF (основной) + WebP |

| `strip-sign` | полоса «фактов»: вывеска крупно | 1200×? кроп | AVIF/WebP |

Требования к весу: **hero ≤ 250 КБ** на вариант 2560 AVIF, ≤ 400 КБ WebP; остальные ≤ 120 КБ.

### А3. Промпт для редактирования фото (img2img / inpaint)

Один и тот же исходник, три прохода — так чище, чем всё сразу:

```
Проход 1 — убрать лишнее:
Отредактируй фотографию автосервиса. Убери серый автомобиль с открытым капотом справа,
мусорный бак слева, провода и мелкий мусор у входа. Восстанови на их месте асфальт,
тротуарную плитку и кирпичную стену так, чтобы не было видно следов редактирования.
Не меняй здание, ворота, вывеску и всё, что на ней написано. Не добавляй новые объекты.

Проход 2 — свет и цвет:
Выровняй перспективу: вертикальные линии стен должны быть строго вертикальными.
Сделай кадр вечерним: мягкий тёплый свет из боксов, прохладные тени снаружи.
Приведи цвет к тёмно-зелёной гамме: глубокие тёмные тени, тёплые медные акценты света.
Не пересвечивай вывеску. Сохрани читаемость названия и телефонов на баннере.

Проход 3 — небо и чистота:
Замени небо на ровное пасмурное с лёгкой дымкой, без яркого солнца и без птиц.
Убери блики и случайные отражения на асфальте, оставь лёгкую влажность.
Финальный кадр: чисто, аккуратно, профессионально, без людей и без машин на улице.
```

**Чего делать нельзя:** «улучшать» вывеску (перерисовывать текст, телефоны, логотипы брендов),
добавлять вторую вывеску, менять число ворот, ставить на передний план чужие машины.

## 3. Задача Б. Сгенерированные фоны (декорация, не «наш сервис»)

Правило: **AI-картинки — это декор**, они не изображают конкретный сервис заказчика. Поэтому:
без вывесок, без названий, без логотипов, без читаемых номеров и без лиц крупным планом.
Реальные фото сервиса — только настоящие (§2).

Нужно **3 фона**, не больше (каждый — вес и LCP):

| Имя | Где | Сюжет |
|---|---|---|
| `hero-tyre-<W>` | слайд 2 hero | макро колеса на станке, тёмный цех, боке |
| `hero-tools-<W>` | слайд 3 hero | инструменты на верстаке, тёплый свет, тёмный фон |
| `texture-metal` | фон секции «Как мы работаем» / подвал | шлифованный металл/диск, царапины, тёмная текстура |

Промпты (генерировать в 16:9, 2560×1440, тёмная гамма, **без текста**):

```
1. Колесо на шиномонтажном станке крупным планом, тёмный автосервис, объёмный свет из глубины
кадра, тёплые медные блики на металле, холодные изумрудные тени, малая глубина резкости,
кинематографично, фотореализм, без текста, без людей, без логотипов, 16:9

2. Набор автомобильных инструментов на тёмном верстаке: ключи, головки, трещотка, фонарь,
тёплый направленный свет сбоку, глубокие тени, тёмно-зелёный фон, пыль в луче света,
кинематографично, фотореализм, без текста, без логотипов, 16:9

3. Абстрактная макро-текстура шлифованного металла и литого диска: круговые следы обработки,
мелкие царапины, тёмный графит с медными и изумрудными отблесками, драматичный контровой свет,
без текста, без предметов целиком, 16:9
```

Композиция: оставляй **пустую зону слева** (там текст) — либо генерируй с симметричным сюжетом
и накладывай градиент в CSS. Проверь контраст: текст на фоне ≥ 4.5:1 (замерить, не «на глаз»).

Если у тебя нет доступа к генератору изображений — **не подменяй** результат CSS-градиентами молча:
сделай §2 и §4 на реальном фото, а в отчёте напиши «генерация недоступна», приложив готовые промпты.

## 4. Задача В. Новая композиция главной

### В1. Hero — фото вместо абстракции

Три слайда сохраняем (структура и тексты — из утверждённого мокапа, менять не надо), меняем фон:

| Слайд | Фон |
|---|---|
| 1 «Ремонт авто на Портовой» | **реальное фото фасада** (§2), кадр с вывеской |
| 2 «Сначала смета — потом ремонт» | `hero-tyre` (AI) |
| 3 «Колёса, ходовая, двигатель» | `hero-tools` (AI) |

Требования:

- фон — `<img>`/`<picture>` с `srcset`, а не CSS `background-image`: нужен `fetchpriority="high"`
  и правильный LCP (проверка Pages-экспорта тоже проходит только по `<img>`);
- первый слайд: `fetchpriority="high"`, `decoding="async"`, остальные — `loading="lazy"`;
- поверх фото — двухслойный оверлей: плотный градиент слева (под текст) + лёгкое затемнение
  по всей площади, чтобы текст читался и на светлых участках (небо, вывеска);
- кадрирование под мобилку: `object-position` так, чтобы на 390 px в кадр попадала **вывеска**,
  а не асфальт; проверить на 360/390/640/1024/1440;
- `prefers-reduced-motion` — автопрокрутка и параллакс (если добавишь) отключаются;
- высота: на десктопе кадр занимает первый экран целиком, но не мешает увидеть начало следующей
  секции на 900 px высоты (подсказка-«стрелка вниз» или выглядывающая полоса фото).

### В2. Полоса под hero — «сервис вблизи»

Новая полоса из **трёх кропов одного реального фото** (вывеска крупно, левый бокс, правые ворота) —
горизонтальная лента во всю ширину, с подписями:

- «Портовая, 439 — два бокса» / «Шиномонтаж и ремонт в одном месте» / «Работаем ежедневно 9:00–19:00».

Это «якорь» для глаза сразу после hero. Без карусели и без анимации: статичная лента, hover — лёгкий зум.

### В3. «О компании» — заменить заглушку

`svc-1.svg` → `about-service` (реальное фото, кроп кадра §2). Подпись под фото: адрес и «въезд со
стороны Портовой». Никаких «фото появится после съёмки».

### В4. Галерея кейсов — убрать двойной текст

Пока реальных фото «до/после» нет, галерея остаётся на заглушках, но привести в порядок:

- из SVG-заглушек **убрать весь текст** (он дублирует подпись карточки) — оставить только графику;
- убрать повторяющуюся фразу «фото появится после съёмки» из `alt` и подписей карточек:
  достаточно **одного** пояснения под секцией: «Показываем только реальные работы — фото появятся
  после съёмки»;
- «до / после» оставить как маркер в углу, но не наезжающим на заголовок;
- подпись карточки — одной строкой с ellipsis, полное название — в lightbox.

### В5. Ритм и «красота» (то, что просил заказчик)

Не переделывая структуру, добавить:

1. **Разные ширины**: фото-полоса во всю ширину (§В2) и одна секция с крупным кадром — против
   монотонности одинаковых контейнеров.
2. **Воздух**: увеличить вертикальные отступы секций на десктопе (не на мобилке — там наоборот плотнее).
3. **Типографика**: заголовки секций — один размер и один ритм; убрать случаи, где `h2` переносится
   на 3 строки при 1440 px.
4. **Шапка**: пункты меню в одну строку (`white-space:nowrap`, при нехватке — уменьшить gap/шрифт
   на 1 px, но не ломать высоту); при скролле фон `rgba(11,20,16,.97)` + `blur(14px)`, чтобы
   контент не просвечивал.
5. **Микроанимация**: появление секций — сдвиг 12 px вместо 24 px (сейчас слишком «прыгает»),
   hover карточек — `translateY(-3px)`, без масштабирования картинок внутри карточки.
6. **Фото-фокус**: у всех фото — единая цветокоррекция (тёмная, тёплая, чуть приглушённая
   насыщенность), чтобы реальные фото и AI-фоны не спорили друг с другом.

## 5. Технические требования

- Не ломать существующее: `npm test` ≥ 58/58, `npm run smoke` 14/14, `npm run typecheck` — 0.
- Новые изображения — только в `site/public/img/` (публичные) и `docs/photos-source/` (исходники).
  В `site/src/` картинки бинарём не кладём.
- Никаких внешних CDN, шрифтов, стоков по ссылке — всё локально.
- `alt` осмысленный; декоративные фоны — `alt=""` + `aria-hidden`.
- Мобильная версия: hero не «съедает» весь экран, фото не растягивается с искажением
  (`object-fit:cover`), текст не наезжает на вывеску в неудобных местах.
- Lighthouse-цель: Performance ≥ 90 на мобильном профиле. Если браузера нет — считай вес первого
  экрана и пиши цифры в отчёте, не выдумывай оценку.
- Демо на GitHub Pages собирается скриптом `scripts/export-pages.mjs` (ветка `preview/github-pages`):
  он берёт `dist/client` целиком, поэтому новые файлы из `public/img/` подхватятся. Перенос демо —
  **не твоя задача**, его делает оркестратор после приёмки. Но проверь, что после `npm run build`
  новые картинки лежат в `dist/client/img/`.
