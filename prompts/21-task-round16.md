## 1. КРИТИЧНО. Шов на левом крае кадра — ошибка сборки картинок, она в проде с круга 14

Заказчик описал это словами «немного обрезалась и прижалась к левой стороне» и прислал скрин
`c-182140`. На самом деле кадр не обрезан: **в мастере стоит чёрный столбец** шириной 176 px
(11 % кадра), а правее — нормальная сцена. На 768×1024 это видно как вертикальная кромка.

Причина — `site/scripts/build-images.mjs`, строка ~205:

```js
const leftBand = await sharp(vertFile).extract({left:0, top:0, width:LEFT, height:H1}).flop().raw().toBuffer();
const W1 = LEFT + SW;                       // 176 + 1376 = 1552
const canvas = Buffer.alloc(W1 * H1 * 3);
Buffer.from(leftBand).copy(canvas, 0);       // ← ДЕФЕКТ
```

`leftBand` — это 176 × 873 (построчно), холст — 1552 × 873. Сплошное копирование кладёт 460 944
байта подряд в буфер со шагом строки 4656 → заполняются первые `⌈460944/4656⌉ = 99` строк,
ниже остаётся **нулевой (чёрный) столбец** шириной 176 px.

**Проверено численно** (средняя яркость колонок `master-desk-2560.jpg` до фикса): x 0…285 → **1,6**,
x 292… → **7,0**, скачок ×4,4 на ровном месте. Именно это гасил VOID-дим, и именно поэтому левый
край казался «прижатым».

**Как правильно** — построчно:

```js
const band = Buffer.from(leftBand);                 // копия один раз, не в цикле
for (let y = 0; y < H1; y++) {
  band.copy(canvas, y * W1 * 3, y * LEFT * 3, (y + 1) * LEFT * 3);
}
```

**Проверка после пересборки** (обязательно приложить вывод):

```js
// средняя яркость колонок x = 285 / 290 / 295 в public/img/hero-service-2560.webp
// норма: |c - b| < 1,0  (у оркестратора 11,06 / 10,87 / 11,05 — скачок 0,17)
```

и кроп ×4 левого края `hero-768x1024` и `about-390x844`: **кромки нет**, яркость плавная.

После правки пересобрать `node site/scripts/build-images.mjs` (~70 с) и **приложить
`sha256sum` двух сборок подряд** — должны совпасть (это уже требовалось в круге 15).

## 2. Первый экран вылезал за окно на 20 px

`max-height:calc(100svh - 96px)` считает шапку как 96 px, но в превью над шапкой стоит
демо-плашка (35 px) → реальная шапка 116 px. Рендер 1217×598: герой заканчивался на **618**
при `innerHeight` 598, то есть низ кадра и подпись полосы уезжали под сгиб.

**Требование:** высота героя — от переменной, а не от магического числа.

```css
/* base.css */
body{ --hdr:96px; }
body[data-preview="true"]{ --hdr:116px; }   /* демо-плашка в превью */

/* hero.css */
.hero-slide img{ max-height:calc(100svh - var(--hdr)) }
@media (min-width:641px) and (max-width:1023px) and (max-height:560px){
  .hero{ height:calc(100svh - var(--hdr) - 4px) }
}
```

**Проверка:** на 1217×598, 1024×600, 1920×950 `hero.bottom == innerHeight` (±1 px).

## 3. Шапка шире окна на 1024–1366 и ломалась на 861–1023

Считал по метрикам Golos Text (`fontTools`), потом подтвердил в браузере:

| окно | что требовала шапка | что было |
|---|---|---|
| 1024 | **1122 px** | кнопка «Записаться» за краем |

Причина: порог бургера стоял на `max-width:860px`, подпись под логотипом (196 px) и цифры
телефона не сворачивались вовсе.

| окно | логотип-подпись «РОСТОВ-НА-ДОНУ · ПОРТОВАЯ 439» | цифры телефона | меню | бургер |
|---|---|---|---|---|
| ≥1360 | да | да | 14 px, одна строка | нет |
| 1280–1359 | нет | да | одна строка | нет |
| 1200–1279 | да | нет (иконка) | одна строка | нет |
| 1024–1199 | нет | нет (иконка) | 13,5 px, одна строка | нет |
| 861–1023 | нет | нет | — | **да** (порог опустить) |
| ≤560 | нет | нет | — | да, 44 px, логотип 40 px |
| ≤380 | нет | нет | — | ещё компактнее |

**Проверка (обязательно таблицей):** для 320 / 360 / 390 / 414 / 768 / 861 / 926 / 1024 / 1199 /
1280 / 1360 / 1440 — `document.documentElement.scrollWidth === clientWidth`, `.hdr-cta.right ≤
clientWidth`, пункты меню на одной строке (`new Set(tops).size === 1`).

## 6. Короткий ландшафт (641–1023 при `max-height:560px`): кнопки не нажимались

Ревью A6: 9 079 px² перекрытия `.hero-ui` и CTA, `elementFromPoint` по кнопке — мимо.
Колоночная схема не годится: в рендере текст упирался в низ (`cta.bottom` 425 при 390).

**Требование:** фото снова фоном, текст колонкой, контролы в правый нижний угол:

```css
@media (min-width:641px) and (max-width:1023px) and (max-height:560px){
  .hero{flex-direction:row;height:calc(100svh - var(--hdr) - 4px);min-height:0}
  .slide-in{max-width:70%}
  .hero-ui{position:absolute;left:auto;right:12px;bottom:10px}
}
```

**Проверка:** 844×390 и 926×428 — пересечение `.hero-ui` и CTA = **0 px²**, все 9 точек
`elementFromPoint` попадают в кнопку, реальный клик проходит.

## 7. Гейты должны падать на мутантах — иначе это не гейты

Системный дефект прошлых кругов: `check-hero-layout.mjs` содержал `const heroW = vw` (тавтология),
`check-safe-zone.mjs` возвращал готовое `cars:'ok'`. Ревью A6 п.11.4. **Правило круга 16:
у каждого чекера есть секция «самопроверка на мутантах»**, где он обязан упасть.

1. **`site/scripts/check-cascade.mjs` — новый.** Разбирает `hero.css` как CSS (без браузера),
   считает каскад для конкретного окна и проверяет:
   * ширина `.hero` == ширине окна на 8 окнах 1024…2560;
   * `.hero .slide-in` `padding-left` ≥ 16 px на 320/360/390/414/430;
   * в треке нет `max(460px, 76svh)`;
   * на 844×390 `.hero-ui` — `position:absolute; right:12px`, `.slide-in` `max-width:70%`;
   * **нет повторов правил внутри одного медиа** и **блок `≥1024` ровно один**.
   Мутанты: вернуть `max-width` на `.hero`; вернуть `margin:10px` в мобильный блок; вернуть трек
   `76svh`; продублировать правило. Все четыре обязаны ловиться.
   *Важно:* не писать проверку «каждый медиа-запрос встречается ровно один раз» — в `hero.css`
   законно 15 блоков на 12 условий (`max-width:640` нужен в разных местах), такой порог — ложный FAIL.
2. **`check-hero-layout.mjs`** — убрать `const heroW = vw`; проверять *объявления*, которые держат
   строку (`.hdr` без `flex-wrap` и с переполнением-запретом), и добавить мутантов.
3. **`check-safe-zone.mjs`** — мобильная проверка считается по `cover`-математике от координат
   мастера (`title`, `cars` в `safe-zone-geom.json`), а не возвращает `'ok'`. Мутанты: сдвинуть
   машины за кадр, сломать `posY`, уменьшить полосу.
4. `site/package.json` → `scripts.test` должен вызывать `check-cascade.mjs` **до**
   `check-safe-zone.mjs`, чтобы падение каскада было видно сразу.
