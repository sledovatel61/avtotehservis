# Задание A15 (круг 87): раздел «Отзывы» в админке `/manage`

**Ветка:** от `origin/preview/github-pages`, имя `agent/r87-reviews-admin`. PR — в `preview/github-pages`.
**Роль:** статическая админка (`site/public/manage/*`), которая пишет в репозиторий через GitHub API.
**Зависит от:** A13 (`prompts/109`) — схема `site/content/reviews.json`. Контракт схемы не менять, только читать/писать.

## Что нужно

Третья вкладка в `/manage` — **«Отзывы»** (`#reviews`), рядом с «Фото работ» и «Цены и услуги».

### Состав экрана

1. **Список отзывов** из `site/content/reviews.json`: карточка в строку — звёзды, имя, дата, статус, первые ~120 знаков текста.
   - фильтр по статусу: `Все / Опубликованные / Скрытые` (+ счётчики);
   - сортировка: новые сверху;
   - демо-записи видны и помечены чипом «пример» — их можно удалить одной кнопкой «Удалить все примеры» (с подтверждением), чтобы перед запуском не искать по одной.
2. **Действия в строке:** «Опубликовать» (если `hidden`), «Скрыть» (если `published`), «Изменить» (текст, имя, оценка, дата), «Удалить» (с подтверждением).
3. **Кнопка «+ Добавить отзыв»** — форма: имя, оценка, текст, источник (`site` / `yandex` / `2gis`), ссылка на источник (необязательно), дата.
4. **Плашка модерации**: «Отзывы с сайта приходят в Telegram и на почту. Здесь вы их публикуете — автоматически они не появляются.» Плюс поле «Вставить текст из Telegram» — textarea, куда владелец копирует присланный отзыв и жмёт «Разобрать»: простой парсинг строк `Оценка: N/5`, `Имя: …`, остальное — текст; поля заполняются, владелец проверяет и сохраняет.

### Правила записи (как у цен — круг 86)

- Одна кнопка **«Сохранить»** внизу вкладки: копит изменения и делает **один** коммит в `site/content/reviews.json`. Сообщение коммита: `Отзывы: правка из админки (N изменений)`; отдельно для удаления: `Отзывы: удалено N`.
- Реализация — через существующий `site/public/manage/github.js`: добавь метод `saveReviews(json, count)` по образцу `savePrices` (blob → tree → commit → PATCH ref, с fallback при конфликте ref).
- Валидация перед сохранением (зеркало сайта): имя 2–40, текст 20–1500, оценка 1–5, `id` уникален и не меняется, дата `YYYY-MM-DD`.
- `updated_at` обновляется при каждом сохранении.
- Удаление последнего опубликованного отзыва разрешено, но с предупреждением «На сайте вернётся заглушка про Яндекс.Карты».
- Кнопка «Сохранить» блокируется, пока есть ошибки валидации; после успеха — «Отправлено. GitHub собирает сайт — 1–2 минуты» и ссылка «Открыть /otzyvy на сайте ↗» + «Ход сборки ↗».
- CSP админки: без inline-обработчиков (`onclick` запрещён), только `addEventListener` — как в существующих вкладках.
- Пустое состояние: «Пока нет отзывов. Добавьте вручную или дождитесь отзыва с сайта.»

### Документация

`docs/manage-reviews.md` — короткая инструкция для владельца (нумерованные шаги: где вкладка, как опубликовать пришедший отзыв, как удалить, что увидит посетитель). Стиль — как `docs/email-setup.md`: «куда нажать → что вписать → как проверить».

## Тесты (`site/tests/manage-reviews.test.ts`, jsdom — по образцу `site/tests/manage-prices.test.ts`)

1. Загрузка: `hidden` и `published` показываются, счётчики верные, демо помечены.
2. «Скрыть» меняет `status` в снапшоте, но **не** отправляет коммит до «Сохранить».
3. «Сохранить» без изменений ничего не коммитит (кнопка неактивна).
4. Два изменения → один коммит, сообщение содержит число изменений.
5. Валидация: текст 19 знаков → ошибка, кнопка заблокирована; 20 → сохраняется.
6. Удаление: спрашивает подтверждение; после подтверждения запись уходит, коммит один.
7. «Удалить все примеры» убирает ровно `demo: true`, настоящие отзывы не трогает.
8. «Разобрать» из Telegram: строка `Оценка: 5/5` и `Имя: Павел И.` попадают в поля, остальное — в текст.
9. Никаких `innerHTML` с пользовательским текстом: имя/текст экранируются (проверка, что `<script>` в отзыве не выполняется).
