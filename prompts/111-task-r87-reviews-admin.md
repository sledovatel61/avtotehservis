## Задача

Третья вкладка в `/manage` — **«Отзывы»** (`#reviews`), рядом с «Фото работ» и «Цены и услуги».

### Экран

1. **Список отзывов** из `site/content/reviews.json`: строка-карточка — звёзды, имя, дата, статус, первые ~120 знаков текста.
   - фильтр `Все / Опубликованные / Скрытые` со счётчиками;
   - сортировка: новые сверху;
   - демо-записи видны, помечены чипом «пример», и есть кнопка **«Удалить все примеры»** (с подтверждением) — чтобы перед запуском не искать по одной.
2. **Действия в строке:** «Опубликовать» (если `hidden`), «Скрыть» (если `published`), «Изменить» (имя, текст, оценка, дата), «Удалить» (с подтверждением).
3. **«+ Добавить отзыв»**: имя, оценка, текст, источник (`site`/`yandex`/`2gis`), ссылка на источник (необязательно), дата.
4. **Плашка модерации:** «Отзывы с сайта приходят в Telegram и на почту. Здесь вы их публикуете — автоматически они не появляются.» Плюс поле **«Вставить текст из Telegram»**: textarea → кнопка «Разобрать» → парсинг строк `Оценка: N/5`, `Имя: …`, остальное в текст; поля заполняются, владелец проверяет и сохраняет.

### Правила записи (как с ценами в круге 86)

- Одна кнопка **«Сохранить»** внизу вкладки: копит изменения и делает **один** коммит в `site/content/reviews.json`. Сообщение: `Отзывы: правка из админки (N изменений)`; для удаления — `Отзывы: удалено N`.
- Реализация — через существующий `site/public/manage/github.js`: метод `saveReviews(json, count)` по образцу `savePrices` (blob → tree → commit → PATCH ref, с обработкой конфликта ref).
- Валидация (зеркало схемы Агента 10): имя 2–40, текст 20–1500, оценка 1–5, `id` уникален и не меняется, дата `YYYY-MM-DD`. Форма `id` для новой записи: `r-YYYY-MM-DD-NNN` (следующий свободный номер).
- `updated_at` обновляется при сохранении.
- Удаление последнего опубликованного отзыва разрешено с предупреждением: «На сайте вернётся заглушка про Яндекс.Карты».
- Кнопка «Сохранить» заблокирована, пока есть ошибки валидации. После успеха: «Отправлено. GitHub собирает сайт — 1–2 минуты» + ссылки «Открыть /otzyvy на сайте ↗» и «Ход сборки ↗».
- CSP админки: **без inline-обработчиков** (`onclick` запрещён), только `addEventListener` — как в существующих вкладках.
- Пустое состояние: «Пока нет отзывов. Добавьте вручную или дождитесь отзыва с сайта.»

### Документация

`docs/manage-reviews.md` — инструкция для владельца в стиле `docs/email-setup.md`: «куда нажать → что вписать → как проверить». Обязательно шаг «как опубликовать отзыв, пришедший в Telegram» и «как удалить все примеры перед запуском».

## Тесты `site/tests/manage-reviews.test.ts` (jsdom, по образцу `manage-prices.test.ts`)

1. Загрузка: `hidden` и `published` показываются, счётчики верные, демо помечены.
2. «Скрыть» меняет статус в снапшоте, но коммита до «Сохранить» нет.
3. «Сохранить» без изменений неактивна и ничего не коммитит.
4. Два изменения → **один** коммит, в сообщении число изменений.
5. Валидация: текст 19 знаков → ошибка и кнопка заблокирована; 20 → сохраняется.
6. Удаление спрашивает подтверждение; после — запись уходит, коммит один.
7. «Удалить все примеры» убирает ровно `demo: true`, настоящие не трогает.
8. «Разобрать»: `Оценка: 5/5` и `Имя: Павел И.` попадают в поля, остальное — в текст.
9. Экранирование: `<script>` в имени/тексте не выполняется (никакого `innerHTML` с данными пользователя).
