## Обязательное поведение

### 1. Категории — свёрнутые секции

- Каждая категория — `<details class="price-category" data-category="group:to">` с
  `<summary>`. **По умолчанию свёрнуто** (атрибута `open` нет).
- В заголовке секции: название, счётчик позиций («6 работ», склонения: 1 работа, 2 работы,
  5 работ), бейдж «не сохранено: N» (только когда N > 0) и, если есть, «скрыто: N».
- Состояние «развёрнуто» запоминается между заходами: `localStorage['atsPricesOpen']` —
  массив `data-category`. Все обращения к `localStorage` в `try/catch` (приватный режим,
  запрет хранилища) — интерфейс обязан работать и без него.
- После сохранения и после перерисовки открытые секции остаются открытыми, курсор/фокус
  не теряется. Текст в `summary` не перехватывает клик по кнопкам внутри (кнопок в summary нет).
- Секция «Плашки на главной» — тоже свёрнутая, только для чтения, как сейчас.

### 2. Строка: просмотр → «Изменить» → правка названия и цены

Режим просмотра (одна строка, компактно):

```
Амортизаторы, передние            1800–2501 ₽   [Изменить] [Скрыть] [Удалить]
```

- «Изменить» включает режим правки **внутри строки**: поля «Название» и «Цена»
  (для комплектов — «Легковой» и «Кроссовер»; для ремонта колёс — «Радиус» и «Цена»;
  для Voyah — «Название», «Примечание», «Цена»). Кнопки в режиме правки: «Готово» и «Отмена».
- Лимиты полей — из `LIMITS` браузерной схемы (`name`, `radius`, `note`, `price`), в том числе
  `maxlength` на инпутах.
- «Готово» проверяет значения: пустое/короткое название, цена без цифры — сообщение под полем
  (`role="alert"`), режим правки не закрывается. Валидные значения уходят в **общий список
  несохранённых изменений категории**, а не в GitHub.
- «Отмена» возвращает значения строки к последнему сохранённому состоянию (и к уже введённым,
  но не сохранённым правкам этой строки, если они были).
- Изменённая, но не сохранённая строка помечается бейджем «не сохранено» и подсветкой.
- `id` позиции при переименовании **не меняется** — иначе сломаются токены в текстах.
  Если позиция новая (добавлена в этой сессии) — правится просто её черновик.

### 3. «Удалить» — насовсем, с подтверждением и защитой ссылок

- Кнопка «Удалить» (класс `danger`) → строка переходит в состояние «Удалить «ТЕСТ» навсегда?»
  с кнопками «Да, удалить» и «Отмена» **внутри строки** (не `confirm()`: на телефоне
  системный диалог выглядит как ошибка, а нам нужен понятный текст).
- После подтверждения строка получает вид «Будет удалено после сохранения» и кнопку «Вернуть».
  Удаление входит в несохранённые изменения категории и уходит в GitHub **вместе с остальными
  правками этой категории, одним коммитом**.
- Перед подтверждением интерфейс читает `./price-refs.json` (файл готовит Агент 10;
  в проде он лежит рядом с `prices.js`, в разработке — `npm run build:refs`; отсутствие файла —
  не ошибка, см. ниже) и смотрит ссылки на эту позицию:
  - ссылки по `id`: удалять **можно** — тексты продолжат работать, только если id нигде не
    используется; если используется, показываем список файлов/страниц и **запрещаем** удаление:
    «На эту работу ссылаются страницы: /services/tormoza/, /prices/. Удалить сможет разработчик
    после правки текстов. Пока нажмите «Скрыть» — цена исчезнет с сайта, а тексты останутся
    целыми.»;
  - ссылки по `alias` (слаг названия): то же самое, плюс отдельная строка для переименования —
    «Это название упоминается в текстах: … Переименовать сможет разработчик»;
  - если `featured[].ref` указывает на удаляемую позицию Voyah — запрет с текстом про плашку
    на главной;
  - если файл ссылок не загрузился — **разрешаем** удаление, но предупреждаем: «Проверить
    ссылки в текстах не удалось. Если после сохранения сборка остановится, напишите разработчику».
    Страховка на этот случай — гейт `--refs-only` в CI (Агент 10), он не даст опубликовать сырой
    `{{price:…}}`.
- «Скрыть» / «Показать обратно» остаются отдельной кнопкой (владелец прямо сказал: «сейчас
  только скрыть» — значит скрытие полезно, но перестаёт быть единственным способом убрать строку).

### 4. Ровно одна кнопка сохранения — внизу категории

- Убрать липкую панель `<div class="price-sticky">` с «Сохранить всё» и все построчные
  «Сохранить».
- Внизу каждой секции — **одна** кнопка: `Сохранить` + подпись «Изменений: N» слева от неё.
  Она disabled, если в этой категории нет изменений или идёт сохранение.
- Кнопка сохраняет **всё** изменённое в категории одним коммитом: новые строки, правки названий,
  правки цен, удаления, `hidden`. Форма «Добавить работу» остаётся внизу категории, но её кнопка
  называется «Добавить в список» и только добавляет черновик в несохранённые (в текущей версии
  она уже так и делает — сохранить формулировку и поведение).
- В шапке раздела можно оставить **текст** «Несохранённые изменения: N» без кнопки — это
  подсказка, а не второе сохранение. Никаких других кнопок «Сохранить» на вкладке быть не должно.
- Уход со страницы/отключение ключа при несохранённых изменениях — по-прежнему `beforeunload`
  и подтверждение в `mayDisconnect()`.

### 5. Сохранение: один коммит, понятные ошибки

- Один вызов `api.savePrices(apply, count, progress)` на категорию. Внутри `apply` — применить
  к свежему документу, в порядке: добавления → переименования/цены/`hidden` → удаления;
  затем `validate()`; затем `next.updated_at = today()`.
- Удаление **идемпотентно**: если позиции уже нет в свежем файле — это не ошибка (кто-то удалил
  её параллельно), просто пропускаем.
- Конфликт по цене (поле изменилось у обоих) — прежний текст «Кто-то изменил эти цены
  одновременно: …». Отсутствующая строка, которую правили, — прежний текст «Эту строку кто-то
  удалил, пока вы правили: …».
- После успеха: `snapshot` обновляется, несохранённые изменения категории очищаются, секция
  остаётся открытой, сообщение «Сохранено. Сайт обновится через 1–2 минуты», ссылки «Открыть
  прайс на сайте ↗», «Ход сборки ↗», кнопка «Обновить статус» — как сейчас.
- Ошибки — по-русски, без `Error:` и стека; 401/403/404/409/422 — текущие тексты сохранить.

### 6. Мобильный и доступность

- 360 и 390 px: строка не ломается, кнопки переносятся, цель нажатия ≥ 44 px по высоте,
  название и цена читаемы, горизонтального скролла нет.
- Нативные `<details>/<summary>` (клавиатура и скринридер работают без костылей), сообщения —
  `role="status"` / `role="alert"`, `aria-live="polite"`.
- Никаких inline-обработчиков и `<script>` внутри HTML — CSP `script-src 'self'`. Все слушатели
  навешиваются в `render()`.
- `escapeHTML` для всех данных из файла (названия, цены, примечания) — как сейчас.
- CSS — в существующих переменных/токенах `manage.css`, порядок свойств не ломать
  (`node scripts/lint-css-order.mjs`, если он есть в наборе гейтов).

## Тесты (`site/tests/manage-prices.test.ts`, jsdom — как уже принято в проекте)

1. Все категории по умолчанию свёрнуты (`details.open === false`), счётчик позиций в summary верный.
2. Открытие секции пишется в `localStorage`, после повторного `render()`/перезагрузки состояние
   восстанавливается; при недоступном `localStorage` ничего не падает.
3. На вкладке нет `[data-save-all]`, нет `[data-save-row]`; в каждой категории ровно одна кнопка
   сохранения и она disabled без изменений.
4. «Изменить» → правка названия и цены → «Готово» → строка помечена «не сохранено», кнопка
   категории активна; «Отмена» возвращает прежние значения.
5. «Удалить» → подтверждение → «Будет удалено», «Вернуть» отменяет; при сохранении позиция
   исчезает из документа в **одном** коммите вместе с правкой цены и добавлением.
6. Позиция со ссылками в `price-refs.json` (по `id` и по `alias`) — удаление запрещено,
   показан список страниц и совет «Скрыть»; переименование с alias-ссылками — запрещено.
   Ответ 404 на `price-refs.json` — удаление разрешено с предупреждением.
7. После сохранения несохранённые изменения пусты, счётчики нулевые, секция открыта.
