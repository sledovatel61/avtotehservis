## 1. Почему это отдаём тебе, а не A10

Твоя работа по знаку — единственная в проекте, где форму **восстанавливали по эталону
и принимали по числам**: IoU 0,98579, bbox ±1 px, площадь +0,13 %, ошибка контура
средняя 0,318 px / максимум 1,334 px, и всё это закрыто гейтом с мутантами. Машина — та же
задача: есть эталон (габариты + фотографии владельца), есть силуэт, который надо воспроизвести,
и есть «похоже / не похоже», которое надо превратить в число.

A10 сделал в фоне другое: он собрал силуэт из примитивов и **прямо написал в коде**, что это
«не портрет Voyah Free, а кроссовер в тумане». Для задачи «чтобы была прям оч похожа» это
неверная постановка, и она уже привела к тому, что владелец видит кривую машину.

## 2. Что должно появиться

### 2.1 Один модуль вместо двух машин

Сейчас в репозитории **две разные неверные машины**: своя в заставке (`site/src/client/voyah-intro.ts`,
задание №52, агент A5) и своя в фоне (`site/src/client/bg3d/shader.ts`, `carSdf`). Если каждый
дорисует свою «похожую», вернёмся к тому же разговору.

Ты создаёшь **единственный источник правды** — `site/src/client/car-profile.ts`:

```ts
export interface CarPoint { x: number; y: number }   // метры, x — вдоль кузова, y — вверх, 0 = земля
export const CAR = {
  length: 4.905, width: 1.950, height: 1.645, wheelbase: 2.960,
  clearance: 0.180, tyre: 0.7375,              // диаметр колеса 255/45 R20
  axles: [-1.480, +1.480],                     // x осей от центра кузова
  body:  { top: CarPoint[], bottom: CarPoint[] },   // верхняя и нижняя кромка кузова
  cabin: { top: CarPoint[], bottom: CarPoint[] },   // остекление: верх и подоконная линия
  nose:  CarPoint[], tail: CarPoint[],              // свесы/фары/фонарь — для света, не для формы
} as const;
export const SCALE = { intro: 1 / 2.742, bg3d: 1 / 2.742 } as const; // метры → единицы сцены
export const PROFILE_GLSL: string;   // ESSL 1.00: carProfile(vec2), carCabin(vec2), carWheels(vec2)
export function carProfileJS(x: number, y: number): number;  // та же функция на JS, для гейта
```

Требования к модулю:

1. **Никаких библиотек.** ESSL 1.00 (WebGL1 и WebGL2), без `#version`, циклы только с
   константными границами, без массивов с переменным индексом. Образец стиля —
   `site/src/client/bg3d/shader.ts`.
2. **Профиль строится по опорным точкам**, а не из «двух боксов и двух срезов». Скругления —
   `smin` с разным `k` по зонам, но без пиков: крыша выпуклая, стык капота и лобового плавный.
3. **Две реализации (GLSL и JS) обязаны совпадать**: гейт рендерит `PROFILE_GLSL` в headless
   Chromium и сверяет с `carProfileJS` по маске — IoU ≥ 0,99. Это ловит целый класс ошибок,
   который иначе не виден: шейдер компилируется, а форма в нём не та.
4. **Масштаб не выдумывать**: земля в фоне зафиксирована на `y = −0,44`, высота кузова
   в единицах сцены — 0,60 (было 0,70), отсюда 1 единица = 2,742 м. Если меняешь — меняешь
   вместе с тенью, отражением и контактной линией у A10 (задача №55), иначе тень уедет.

### 2.2 Геометрия в двух шейдерах

- **Фон** — `bg3d/shader.ts`: `carSdf` заменяется на обёртку над `carProfile` из модуля;
  правятся связанные вещи: контактная тень (`gy`), отражение (`rg`, второй проход),
  контровой свет по кромке (`edge`), ореолы фар/фонаря (координаты `(0.90, −0.03)` и
  `(−0.92, −0.02)` считаются из `CAR.nose`/`CAR.tail`, а не «на глаз»).
- **Заставка** — `voyah-intro.ts`: **сам не правь.** A5 уже в работе по №52. Модуль
  сдаёшь ты, A5 подключает его у себя одной правкой. Если A5 успеет раньше со своей
  геометрией — его код заменяется вызовом модуля, второй копии в репозитории быть не должно.

## 3. Эталон: что значит «похожа»

### 3.1 Габариты (жёстко, допуск ±2 %)

| Параметр | Значение |
|---|---|
| длина × ширина × высота | 4905 × 1950 × 1645 мм |
| база | 2960 мм |
| клиренс | 180 мм |
| колёса | 255/45 R20 → диаметр 0,7375 м |
| колея перед / зад | 1654 / 1648 мм |

Отношения, которые гейт печатает и проверяет: длина/высота **2,98**, база/длина **0,603**,
диаметр колеса/высота **0,448**, зазор арки ≈ **0,035 м** над колесом.

### 3.2 Черты, по которым узнаётся Free (без логотипа и надписей)

Длинный капот, кабина сдвинута назад; крыша выпуклая, падает к корме, заканчивается кромкой;
толстая наклонная стойка C; лобовое ≈ 30° от вертикали, заднее стекло ≈ 22°, наклонная дверь
багажника; непрерывная подоконная линия от фары к заднему фонарю; арки посажены на колесо,
между ними порог; крупные колёса с читаемым диском; короткий передний свес, узкая фара;
фонарь во всю ширину.

**Запрещено:** шильдики, логотип, номер, читаемые надписи, решётка с эмблемой. Только форма.
(Это правило арт-дирекшна и запрет выдумывать бренды — оно остаётся.)

### 3.3 Фотографии владельца — есть, и есть чистый профиль

21.10 владелец прислал набор фото; разложены и размечены в
**`docs/brand/voyah/refs/r31/`** (см. `PROFILE.md`):

| Файл | Роль |

| `front-quarter-black.webp`, `front-quarter-white.webp`, `front-quarter-green.webp` | лобовое, фары, решётка, свес |
| `rear-quarter-white.webp` | наклон двери багажника, фонарь во всю ширину, спойлер |

В `PROFILE.md` §3 координаты уже сняты по сетке: корма x≈55, нос x≈1140, верх крыши y≈330,
земля y≈700, оси x≈960 и x≈280 (y≈600), подоконная линия 395–415, линия капота ≈430,
порог ≈620, кромка спойлера x 90…190 / y≈345. **Масштаб: 1 px = 4,52 мм.**

**Важно, это ловушка:** фото снято с перспективой — по нему база выходит 3,074 м при паспортных
2,960 (+3,9 %), а диаметр колеса «по внешнему контуру шины» — 0,588 вместо 0,7375.
Поэтому: **масштаб и пропорции — только из паспорта §3.1, форма — из фото.**
Фото задаёт изгибы, свесы, наклон стоек и линию крыши, но не метры.
В отчёте отдельной строкой: что взято из паспорта, что с фото, где они разошлись и почему.

Плюс **наложение рендера на фото** — `scripts/car-profile.mjs --overlay` (см. §4 п.5):
контур из GLSL полупрозрачно поверх `side-grid.jpg`. Это и есть приёмка формы.

## 4. Чем доказывать (без этого не принимается)

1. **Орто-рендер силуэта** `site/scripts/car-profile.mjs`: PNG 1200×500, чистый орто без
   перспективы, с направляющими — земля, оси колёс, база, крыша, порог, линия капота.
   Рендер идёт **из GLSL** (headless Chromium, SwiftShader), а не из JS-версии.
2. **Числа** из того же скрипта: длина/высота, база/длина, колесо/высота, клиренс, зазор арки —
   сравнение с §3.1, допуск ±2 %.
3. **Сверка GLSL ↔ JS**: IoU ≥ 0,99 по маске 400×160. Расхождение — это баг в шейдере, а не
   «допуск».
4. **Гейт** `site/scripts/check-car-profile.mjs` в `npm test`, с `--self-test`, минимум **5**
   мутантов, каждый обязан падать: «длина −12 %», «крыша +10 см», «колёса −15 %»,
   «арка без зазора», «кабина сдвинута вперёд». Плюс мутант «вторая копия профиля
   в `voyah-intro.ts`/`bg3d/shader.ts`» — гейт обязан это ловить (один источник, не два).
5. **Наложение на фото** — `--overlay docs/reports/r31/side-grid.jpg`: контур из GLSL поверх
   профиля владельца, полупрозрачно, результат в `docs/reports/r31-car-profile/overlay-side.jpg`.
   Это главный визуальный артефакт сдачи: по нему сразу видно, где форма ушла.
6. **Кадры фона** до/после: `/voyah-free` 1440×900 и 390×844 через

   иначе watchdog погасит фон), кроп машины ×3. Стенд: `/lab/bg3d?variant=silhouette&demo=1`
   и `variant=depth` через `site/scripts/bg3d-lab-shot.mjs`.
7. **Кадры заставки** не твои — их снимет A5 после подключения модуля.
8. `npm test` — **rc=0**. `npm run measure:bg3d` — стоимость кадра в бюджете (было 941 оп/px,
   допуск +10 %). Штатный тест на 20 циклов — без утечек.
9. Отчёт `docs/reports/r31-car-profile/report.md`: таблица «параметр / эталон / факт / Δ»,
