## 1. Блокер: пустые `RATE_LIMIT_*` из `.env.example` отключают приём заявок

### Как воспроизвести (проверено оркестратором)

```bash
# ровно то, что делает deploy.md §4: cp .env.example /etc/avtotehservis/env
DATA_DIR=/tmp/d MEDIA_DIR=/tmp/m PORT=4363 \
RATE_LIMIT_LEADS= RATE_LIMIT_LEADS_IP= RATE_LIMIT_UPLOADS= \
RATE_LIMIT_ANTIFLOOD= RATE_LIMIT_ANTIFLOOD_IP= \
node ./dist/server/entry.mjs

curl -X POST localhost:4363/api/leads   -d @lead.json  → 429 "Слишком много обращений к форме"
curl -X POST localhost:4363/api/uploads -F file=@p.jpg → 429 "Слишком много загрузок"
```

### Почему

```ts
// src/pages/api/leads.ts:29,32,54,55 и src/pages/api/uploads.ts:10
const maxLeads = Number(process.env.RATE_LIMIT_LEADS ?? LIMITS.leads.max);
```

`??` срабатывает только на `null`/`undefined`. Пустая строка — не то и не другое:

```
Number('') === 0   →   arr.length >= 0   →   всегда «лимит исчерпан» → 429
```

systemd `EnvironmentFile` строку `RATE_LIMIT_LEADS=` превращает именно в пустую строку. В `.env.example` эти строки **активны** (без `#`), а комментарий над ними гласит «необязательно; значения по умолчанию в `src/server/ratelimit.ts`» — то есть оставить пустыми выглядит нормально. Результат: на сервере, развёрнутом по инструкции, сайт **не принимает ни одной заявки и ни одного фото**.

Строки появились в `837b349` при закрытии minor-6 первого ревью — формально «добавили лимиты в пример», фактически добавили ловушку.

### Что сделать

**1. Один хелпер вместо пяти `Number(...)`** — например в `src/server/ratelimit.ts`:

```ts
/** Лимит из env: пустая строка, мусор, 0 и отрицательные значения → значение по умолчанию.
 *  Иначе `cp .env.example` (где строки пустые) даёт Number('') === 0 и блокирует всё. */
export function limitFromEnv(name: string, dflt: number): number {
  const raw = process.env[name];
  if (raw === undefined || raw.trim() === '') return dflt;
  const n = Number(raw);
  return Number.isFinite(n) && n > 0 ? n : dflt;
}
```

Заменить все пять чтений:
`limistFromEnv('RATE_LIMIT_ANTIFLOOD_IP', LIMITS.antifloodIp.max)` и так далее.

**2. `.env.example`: закомментировать строки**, чтобы копирование файла не создавало пустых переменных:

```bash
# Лимиты (необязательно; по умолчанию — значения из src/server/ratelimit.ts).
# Раскомментируйте и задайте число, только если нужно изменить:
# RATE_LIMIT_LEADS=5
# RATE_LIMIT_LEADS_IP=30
# RATE_LIMIT_UPLOADS=30
# RATE_LIMIT_ANTIFLOOD=30
# RATE_LIMIT_ANTIFLOOD_IP=60
```

**3. Тест** (unit или интеграционный): при `RATE_LIMIT_LEADS=''`, `RATE_LIMIT_ANTIFLOOD_IP=''`, `RATE_LIMIT_UPLOADS=''` первая же заявка и первая загрузка дают **201**, а не 429. Достаточно одного теста на хелпер (`limitFromEnv('X', 5)` при `X=''` → 5, при `X='0'` → 5, при `X='abc'` → 5, при `X='7'` → 7) плюс интеграционного «сервер с пустыми переменными принимает заявку».

**4. `deploy.md`** — в §4 убрать лимиты из списка «заполнить» (они необязательные) и добавить строку: значения по умолчанию действуют, если переменная **не задана или пуста**.

## 2. Та же ловушка рядом: `SESSION_SECRET=`

`src/server/leads.ts:21`:

```ts
return sha256(ip + '::' + (process.env.SESSION_SECRET ?? 'avtotehservis'));
```

При пустой строке соль становится пустой — молча слабее. Сайт не падает, но приватность хуже.

**Сделать:** `(process.env.SESSION_SECRET || 'avtotehservis')` — или, лучше, при пустом значении писать в лог предупреждение на старте: `[config] SESSION_SECRET не задан — хеш IP без соли`. Достаточно `||`.
