# Задание 85-2 · Агент 11 «админка цен» — раздел `/admin/prices`

Владелец сервиса попросил: «в админке раздел по редактированию цен и услуг, чтобы мастер
открывал, видел текущие цены по каждой категории, вводил новую и нажимал „Сохранить“».
Ты делаешь этот раздел в уже существующей серверной админке (`/admin`, Astro SSR + SQLite).

Параллельно **Агент 10** делает хранилище цен (`site/content/prices.json` + схему), а
**Агент 7** — такую же правку в статической админке `/manage/` на GitHub Pages. Твоя ветка
от них не зависит: контракт файла зафиксирован в §2, работай строго по нему.

**Ветка:** `agent/85-prices-admin` от `origin/preview/github-pages`.
**PR:** в `preview/github-pages`. Не мержить — публикует оркестратор.

---

## 1. Что должно получиться

Новый раздел `/admin/prices` в меню админки (между «Услугами» и «Медиа», подпись
**«Цены и услуги»**), где можно:

1. Увидеть **все** цены сайта по категориям: восемь групп прайса, шины (три таблицы),
   прайс Voyah Free, три плашки на главной.
2. В каждой строке — текущая цена и поле для новой. Кнопка **«Сохранить»** на категорию
   (сохраняет все изменённые строки этой категории) и общая кнопка **«Сохранить всё»**
   на липкой панели, если изменений больше одной категории.
3. Добавить услугу в любую категорию: поля «Название работы» и «Цена», кнопка
   «Добавить в категорию». Новая строка встаёт в конец категории и сразу появляется на
   сайте (после публикации — см. §5).
4. Удалить добавленную по ошибке строку — с подтверждением и **без** физического удаления:
   пометка `hidden: true` в позиции (сайт её не рисует, история сохраняется). Для
   «родных» позиций удаление тоже доступно, но с предупреждением «исчезнет со страницы
   прайса» — мастеру это нужно редко, но пусть будет.
5. Всё, что видит мастер, — по-русски, без слов JSON, API, коммит, репозиторий, файл.

Цены, которые правит мастер, автоматически обновляются **везде**: `/prices`, карточки
услуг, главная, `/voyah-free`, `/about` — это забота Агента 10, твоя задача — не завести
второй источник правды.

## 2. Источник правды и контракт (менять нельзя)

Единственный файл — `site/content/prices.json`, схема и API — `src/shared/prices-schema.ts`
и `src/server/prices-store.ts` (их пишет Агент 10, см. `prompts/100-task-r85-prices-store.md`).
Схема в двух словах:

- `groups[]`: `{ id, title, service, items: [{ id, name, price, hidden? }] }` — `id` латиницей,
  `price` — строка как у клиента (`1200 ₽`, `от 1500 ₽ за место`, `2200–4000 ₽`).
- `tyres`: `{ set: [{ id, radius, passenger, crossover }], repair: [{ id, range, price }],
  extra: [{ id, name, price }] }`.
- `voyah`: `[{ id, name, note, price }]`, `featured`: `[{ id, ref, title, note }]`.
- `updated_at`: `ГГГГ-ММ-ДД`, ставится при сохранении — это дата «Цифры подтверждены …»,
  которую видит клиент на `/prices` и `/services`.
- id уникальны по всему файлу; новые id — `slugifyRu(name)` + суффикс при совпадении
  (`zamena-masla`, `zamena-masla-2`).

**Пока Агента 10 не влили**, `prices-store.ts` в твоей ветке может отсутствовать. Тогда:
возьми контракт §2 как есть, создай **временную** тонкую обёртку
`src/server/prices-admin-store.ts` (чтение/запись файла + `validatePrices`-совместимая
проверка), а в PR напиши, что при мерже нужно переключить импорт на `prices-store.ts`,
если оркестратор не сделает это сам. Второй экземпляр валидации в проекте остаться не должен.

Запись — атомарная: `prices.json.tmp` → `rename`. Перед записью перечитать файл и применить
изменения к свежей версии (last-write-wins по каждой строке, а не по файлу целиком), чтобы
параллельная правка из `/manage/` не потерялась молча.

## 3. Как должен выглядеть экран

- `<h1 class="adm-h1">Цены и услуги</h1>` + строка-пояснение: «Здесь меняются цены на сайте.
  После сохранения цифры обновятся на всех страницах: в прайсе, на карточках услуг и на
  главной».
- Липкая панель сверху (`position: sticky`, как у остальных админ-страниц): «Изменений: N»,
  кнопки «Сохранить всё», «Отменить изменения» (перезагрузить), статус сохранения
  («Сохранено в 14:32», «19.11.2026»).
- Дальше — блоки-категории `<details open>` (заголовок = название группы + количество
  позиций + «изменено: N»):
  1. **Прайс на странице «Прайс»** — 8 групп, внутри таблица: «Работа» (только чтение),
     «Сейчас» (серым), «Новая цена» (input), «Скрыть». Внизу группы — строка добавления:
     «Название работы», «Цена», кнопка «Добавить».
  2. **Шины и колёса** — три таблицы, у `set` два поля (легковые / кроссовер).
  3. **Voyah Free** — позиции с колонкой «Пояснение» (только чтение) и ценой.
  4. **Плашки на главной** — три плашки: название и пояснение только чтение, цена берётся
     из позиции Voyah (покажи это текстом, не полем: «цена берётся из позиции „Масло в
     двигателе + все фильтры“»).
- Подсказки мелким шрифтом: «Пишите как для клиента: 1200 ₽, от 1500 ₽, 2200–4000 ₽».
  Ошибка — под полем, по-русски: «Похоже, это не цена. Напишите, например: 1200 ₽».
- Мобильный вид 390 px: таблица превращается в карточки (название, «сейчас», поле),
  поля и кнопки не меньше 44 px. Проверь руками по CSS-брейкпоинтам проекта.
- Никакого JS-фреймворка: обычная форма `POST` + серверный рендер, как в `/admin/services`.
  Если очень нужен счётчик изменений — маленький inline-скрипт, не больше 30 строк.

## 4. Технические требования админки (как у остальных разделов)

- `Admin.astro` + `section="prices"`, добавить пункт в `NAV` (`/admin/prices`, «Цены и услуги»).
- Сессия: `sessionFromContext`, CSRF: `ensureCsrfCookie` + `csrfValidForm`, отказ —
  `csrfRefusal`. Все POST — с `_csrf`.
- Журнал: `logAction(user.id, 'prices_save', 'prices', '<категория или all>', { changed: N })`,
  по одной записи на сохранённую категорию; в `/admin/log` это должно читаться.
- После успешного сохранения — `redirect` с `?msg=…` (как в `/admin/services`), после
  ошибки — `?err=…`; текст ошибки без стека и без имён файлов.
- Валидация на сервере (не только в браузере): имя 2–120 символов, цена 1–40 символов и
  содержит цифру; запрет пустых и «0 ₽» без слова «от»; дубли id отсекаются.
- Права: раздел доступен тем же ролям, что и «Услуги» (см. `sessionFromContext`/роли
  в `admin-auth.ts`); если роли нет — 403, как в остальных разделах.
- Никаких новых зависимостей.

## 5. Публикация — честно и по-русски

Сайт живёт на GitHub Pages, где серверной админки нет. Поэтому над формой — блок
«Как изменения попадут на сайт»:

- для владельца/разработчика: «Изменения сохраняются в файле цен; на опубликованном сайте
  они появятся после публикации (это делает разработчик или раздел „Цены“ на странице
  /manage/)»;
- для мастера: «Если вы меняете цены в этом разделе, скажите об этом — мы опубликуем.
  Быстрее всего — раздел „Цены“ на странице /manage/».
- кнопка **«Скачать файл цен»** (`GET /admin/prices/export`, `Content-Disposition:
  attachment; filename=prices.json`, `no-store`) — чтобы изменения можно было передать
  без доступа к серверу.

Не обещай в интерфейсе мгновенного обновления сайта: это ложь, и мастер в неё поверит.

## 7. Приёмка

```
npm ci

npm run build
node --test tests/prices-admin.test.ts

```

Плюс сценарий руками (опиши в PR, что именно проверил): вход в админку → «Цены и услуги» →
правка цены в группе «Тормоза» → «Сохранить» → дата обновилась, в `/admin/log` появилась
запись, на `/prices` новая цифра → добавление «Развал-схождение, 1500 ₽» в «Подвеску» →
строка на `/prices` в конце группы → скрытие строки → её нет на странице → «Скачать файл
цен» отдаёт валидный JSON → мобильный вид 390 px.

В отчёте PR: что осталось за Агентом 10 (переключение импорта), какие тексты увидит мастер
и где он видит, что изменения уже на сайте.

## 8. Чего делать нельзя

- Складывать цены в SQLite «чтобы было удобнее» — сайт читает файл, второй источник правды
  недопустим.
- Писать «JSON», «API», «коммит», «репозиторий», «токен» в интерфейсе мастера.
- Делать раздел только для владельца с ролью «админ»: Паша — обычный пользователь админки.
- Тянуть зависимости, переписывать чужие разделы админки, менять нумерацию талонов и т.п.
