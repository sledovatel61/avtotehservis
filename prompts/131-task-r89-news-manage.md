## Задача

Владелец хочет вести статьи сам. Сейчас их можно создать только через `/admin/news`, а админки на боевом домене нет — то есть сегодня Паша физически не может опубликовать статью. Нужна вкладка **«Полезное»** в `/manage/`: полный цикл «создать → черновик → фото → опубликовать → изменить → удалить».

Редактор в мастерской **один**: фото работ, цены, отзывы и статьи — четыре вкладки одного `/manage/`, отдельной админки не появляется.

## 1. `github.js` — чтение и запись статей

Добавить методы по образцу `readReviews` / `saveReviews` (там уже есть защита от одновременного сохранения, повтор при 409/422, понятные ошибки):

```js
async readNews()                       // site/content/news.json → { json, sha }
async saveNews(apply, message, files)  // один коммит: JSON + файлы обложки
```

Требования к `saveNews`:

- **Один коммит на сохранение.** Не «отдельно JSON, отдельно картинки»: иначе между коммитами сайт соберётся с битой ссылкой на обложку.
- Порядок как в `save()`: читаем `latest` → собираем `next` → берём `ref` → `git/blobs` для каждого файла → `git/trees` (`base_tree` = дерево родителя) → `git/commits` → `PATCH /git/refs/heads/preview%2Fgithub-pages`. Повтор один раз при `409/422`.
- `files` — массив `{ path, blob }` (`blob: null` — удаление). Пути обложки:
  - `site/public/media/news/<slug>/<base>-480.<ext>`
  - `…-960.<ext>`, `…-1600.<ext>`
  - `…-og.jpg`
- Сообщения коммитов: `Полезное: публикация «<заголовок>»`, `Полезное: черновик «<заголовок>»`, `Полезное: правка «<заголовок>»`, `Полезное: удалена «<заголовок>»`. Тема коммита — по-русски, как у цен и отзывов.
- При переименовании slug (доступно только до первой публикации) старые файлы обложки удаляются в том же коммите.
- `readNews` при 404 не выдумывает пустой документ: если файла нет — ошибка «Не удалось прочитать статьи. Обратитесь к разработчику.» (в отличие от `cases.json`, файл обязан существовать после круга 89).

## 3. Список статей

- Заголовок, дата, категория, статус (`Опубликована` / `Черновик`), наличие обложки.
- Фильтр: «Все», «Опубликованные», «Черновики» — счётчики.
- Сортировка по дате (новые выше).
- Кнопки: «+ Новая статья», у каждой — «Изменить», «Скрыть/Опубликовать», «Удалить».
- Удаление — подтверждение словом `удалить` (как у работ) или `confirm` с заголовком; при удалении статьи её папка `media/news/<slug>/` удаляется тем же коммитом.
- Внизу — «Сохранить», счётчик изменений (как у отзывов) либо сохранение сразу после «Опубликовать» — выбери одну модель и не смешивай. Рекомендуется модель отзывов: изменения копятся, одна кнопка «Сохранить».

## 4. Редактор статьи

Поля и проверки:

| Поле | Правило | Подсказка в интерфейсе |
|---|---|---|
| Заголовок | 6–120 | так статья будет называться на сайте |
| Заголовок для поиска (`seo_title`) | ≤ 60, может быть пустым | «как статья будет выглядеть в Яндексе и Google; если пусто — возьмём заголовок» |
| Описание (`excerpt`) | 120–300, счётчик | «1–2 предложения для карточки и для поиска» |
| Категория | `sovety` / `sezonnoe` / `servis` | три варианта, новых категорий не добавлять |
| Текст | Markdown, 200–40000 | подсказка по разметке: `#` заголовок, `-` список, `**жирный**`, `[ссылка](/prices)` |
| Адрес (`slug`) | `^[a-z0-9-]{3,80}$`, генерируется из заголовка | **редактируется только до первой публикации**; после — показан серым с пояснением «адрес статьи не меняется, иначе сломаются ссылки и поиск» |
| Обложка | фото, до 15 МБ | «появится на карточке и в начале статьи» |
| Дата | `YYYY-MM-DD`, по умолчанию сегодня | ставится автоматически |

Поведение:

- Заголовок → автогенерация slug **до первой публикации** (транслитерация — взять существующий `slugify` из `store.js`, он уже умеет кириллицу).
- Живой предпросмотр Markdown рядом с полем текста. Дублируй минимальный безопасный рендерер в `site/public/manage/md-preview.js` (заголовки `#`–`###`, списки, цитата, `**жирный**`, `*курсив*`, `` `код` ``, ссылки только `http(s)`, `/`, `mailto:`, `tel:`), **весь ввод экранируется** — сырой HTML в предпросмотре не исполняется. В шапке блока подпись: «Предпросмотр; итоговый вид делает сайт».
- В тексте поддерживаются плейсхолдеры цен `{{price:КЛЮЧ}}`. Перед сохранением сверить ключи с `site/content/prices.json` (загружать через `readPrices`): неизвестный ключ — **блокер** с текстом «Цена «…» не найдена в прайсе. Проверьте ключ.». Причина: `check-prices-sync.mjs --refs-only` в CI уронит сборку, и сайт останется на предыдущей версии.
- Предупреждения (не блокеры): нет ни одной ссылки в тексте («добавьте ссылку на услугу или прайс — так статья лучше находит читателя»); нет обложки («статья уйдёт с картинкой по умолчанию»); `excerpt` короче 120.
- Обложка: загрузка файла → браузерный конвейер из `editor.js`. Для статьи нужен кадр **16:9**: вызвать `editPhoto(blob)` с предустановленным соотношением 16:9 (добавь в `editor.js` необязательный аргумент `{ratio: 16/9, label: 'Обложка статьи'}` — фото работ это поведение не меняет), получить 3 варианта, и дополнительно собрать `og.jpg` 1200×630 из того же кадра (canvas → `toBlob('image/jpeg', 0.82)`).
- Превью обложки в редакторе — как будет на карточке (380 px) и как в статье (760 px).
- «Сохранить черновик» → `status: 'draft'`; «Опубликовать» → `status: 'published'` и `published_at` = сегодня, если ещё не стояла. Повторная публикация дату не меняет, `updated_at` — меняет.
- После сохранения — блок успеха как у работ: ссылка на статью (`../news/<slug>/`) для опубликованной, «Сборка идёт 1–2 минуты», кнопка «Обновить статус» через `publicRuns()` и `head_sha`.
