## 1. Блокер 1: машин нет на десктопе

### 1.1 Что происходит

`.hero{min-height:clamp(560px,calc(100svh - 150px),860px)}`, `.slide-bg img{object-fit:cover;object-position:50% 24%}`.
Мастер: 2767×2160 (1,281). Машины: BMW — от 0,62, Camry — от 0,73 высоты кадра.

| Вьюпорт | герой, px | видимая полоса мастера | BMW видно | Camry видно |
|---|---|---|---|---|
| 1024×768 | 618 | 0,054…0,828 | 55 % высоты | 33 % |
| 1280×800 | 650 | 0,084…0,734 | 30 % | **0 %** |
| 1366×768 | 618 | 0,101…0,681 | 16 % | **0 %** |
| 1440×900 | 750 | 0,080…0,747 | **0 %** | **0 %** |
| 1536×864 | 714 | 0,097…0,693 | 19 % | **0 %** |
| 1920×1080 | 860 | 0,102…0,676 | **0 %** | **0 %** |
| 2560×1440 | 860 | 0,137…0,567 | 0 % | 0 % |

При 1440×900 видно до **0,747**, машины начинаются с **0,753** — не хватает 0,6 % кадра.
На мобильном (3:4) и на 768×1024 кадр по высоте влезает целиком, поэтому там всё видно.

### 1.2 Почему `object-position` не выход

Вывеска с названием и тремя телефонами занимает верхние **25 %** мастера. Сдвиг кадра вниз (`50% 100%`) срезает её целиком: на 1440×900 видно 0,333…1,0 — вывески нет. Компромиссного значения нет: в кадре 1,281 просто не помещаются одновременно 0,25 вывески и 0,75 машины внутри полосы 0,67.

### 1.3 Что собрать вместо

**Desktop-мастер: 2560×1440 (16:9).** Источник — `docs/photos-source/original-front-wide-3840x2160.jpg`, кроп `x 488…3255` (2767).

| Слой | Откуда | Куда в кадре 1556 px |
|---|---|---|
| Вывеска + ворота | оригинал, `y 0…1556` (после кропа по x) | сверху, без изменений |
| Асфальт | оригинал, `y 1750…2160` (410 px), по x — тот же кроп | вниз, с 1330 до 1556, по ширине — тайл/растяжка с сохранением рисунка плитки |
| BMW G60 | `docs/photos-source/r9-gen/car-bmw.png` (1240×820) | вниз слева, `y ≈ 950…1550` |
| Camry XSE | `docs/photos-source/r9-gen/car-camry.png` (1250×920) | вниз справа, `y ≈ 940…1556` |

Требования к композиции:

* машины **не перекрывают** название и строку телефонов (верхние 26 % кадра) и не вылезают за края;
* машины перекрывают **низ ворот**, а не висят в воздухе — контактные тени на асфальте, отражения тёплых ламп;
* между машинами виден низ NGN-стойки — как на референсе;
* пустой асфальт перед машинами — 2–4 % высоты, не больше: кадр не «подиум»;
* пропорции машин не тянуть: BMW ≈ 0,40 высоты кадра, Camry ≈ 0,42;
* та же цветокоррекция, что в раунде 9 (`linear 0.62/0.6324/0.5952`, saturation 0.93, виньетка 0.30).

`object-position` для десктопа — `50% 50%`. Проверить на 1366×768 (самый узкий по высоте): видно 80 % кадра — обе машины попадают, вывеска целиком.

Мобильный мастер 3:4 остаётся, но с правкой §4.

### 1.4 Обязательная проверка: safe zone

Новый шаг в `site/scripts/build-images.mjs` (и отдельный `site/scripts/check-safe-zone.mjs`, вызываемый из `npm test`).

Алгоритм — ровно как в браузере:

```
для каждой пары (W, H) из таблицы:
  hero   = clamp(560, H − 150, 860)          // .hero min-height
  s      = max(W / IW, hero / IH)             // object-fit: cover
  visH   = hero / s                           // сколько пикселей мастера видно
  top    = (IH − visH) * posY                 // posY = 0.5 на десктопе
  полоса = [top, top + visH]
  УПАСТЬ, если bbox(cars)   ⊄ [top + 1 %, top + visH − 1 %]
  УПАСТЬ, если bbox(title)  ⊄ [top, top + visH]        // название и телефоны
  УПАСТЬ, если bbox(cars) пересекает bbox(title)
```

Таблица вьюпортов (ширина × высота окна): 1024×768, 1180×800, 1280×800, 1366×768, 1440×900, 1536×864, 1600×900, 1920×1080, 2560×1440. Плюс мобильные 360×640, 390×844, 414×896 — для мобильного мастера (там полоса `[0, IH]`, проверяется только горизонталь: машины и название внутри ширины).

Скрипт печатает таблицу «вьюпорт → полоса → машины (ok/нет) → название (ok/нет)» и завершается с кодом 1 при любом «нет». Эту таблицу — в отчёт.

`bbox(cars)` и `bbox(title)` задаются в сборщике константами рядом с координатами вставки, а не «на глаз»: машины вставляются их же кодом, название — по замеру ярких пикселей полосы вывески.

## 2. Блокер 2: кнопки первого экрана на мобильных (A6)

### 2.1 Факт

Причина — `.hero{min-height:max(420px,58svh)}` на ≤640 при панели ~466 px:

| Вьюпорт | герой | панель ниже героя | «Записаться» | «Все услуги» |
|---|---|---|---|---|
| 320×568 | 420 | +71 | 1 из 25 | 0 из 25 |
| 360×640 | 420 | +59 | **0 из 25** | 5 из 25 |
| 375×667 | 420 | +59 | **0 из 25** | 5 из 25 |
| 390×844 | 490 | +11 | 25 из 25 | 10 из 25 (остальное — стрелки) |
| 640×800 | 464 | −31 | 15 из 25 | 15 из 25 |

Кликом мыши A6 воспроизвёл: на 360×640 и 640×800 `elementFromPoint` = `DIV.container` — панель карусели перехватывает клик, URL не меняется.

### 2.2 Что сделать

1. **Убрать наложение физически**, а не `pointer-events`. На ≤640 герой должен быть выше панели с запасом: `min-height: max(600px, calc(100svh - 60px))` — либо `.hero-ui` перевести в поток под контент (`position:static`, отдельная строка после `.hero-track`).
2. **Ужать панель** на ≤480: `h1` до `clamp(1.55rem, 7.2vw, 1.9rem)`, `.slide-sub` до 3 строк (`max-width: 30ch`), кнопки — в одну строку (`font-size:13.5px; padding:11px 18px`), отступы панели 14 px.
3. **Проверить сумму**: высота панели + 2×26 px панели карусели ≤ высоты героя. Посчитать по метрикам шрифта и вывести в отчёт числом, как в таблице §2.1.
4. Если выбран вариант «в поток» — `.hero-ui` не должна перекрывать контент при скролле и не должна ломать свайп на слайдере.

### 2.3 Критерий приёмки

На 360×640, 375×667, 390×844, 414×896: **25 из 25** точек каждой кнопки попадают в неё (`elementFromPoint === сама кнопка или её потомок`), «Все услуги» целиком внутри `.hero`, клик ведёт на `/appointment` и `/services` соответственно. Замер — A6, но A5 обязан приложить расчёт, который это предсказывает.
