## 3. Запуск — по шагам

```bash
git clone https://github.com/sledovatel61/avtotehservis.git
cd avtotehservis
git checkout arena/099a14c5-avtotehservis
git log --oneline -3          # в истории должны быть "Этап 6 принят: smoke, docs/13, демо-сид"
cd site
npm ci
```

**Важно:** приложение **не читает `.env`** — переменные задаются только в окружении процесса.
`PUBLIC_SITE_URL` фиксируется **на сборке** (canonical, OG, ссылки в письмах), поэтому он должен быть
выставлен **до** `npm run build`.

Linux / macOS / Git Bash:

```bash
export PUBLIC_SITE_URL=http://localhost:4321
export DATA_DIR="$PWD/data"
export MEDIA_DIR="$PWD/data/media"

npm run migrate                                   # схема БД
npm run seed                                      # услуги, кейсы-заглушки, марки
npm run seed:demo                                 # 3 демо-новости + 3 демо-отзыва (помечены)
npm run admin:create -- owner "LocalReview-123456"
npm run build
npm start                                         # http://localhost:4321
```

Windows PowerShell вместо `export`:

```powershell
$env:PUBLIC_SITE_URL="http://localhost:4321"
$env:DATA_DIR="$PWD\data"
$env:MEDIA_DIR="$PWD\data\media"
```

Проверка, что всё поднялось:

```bash
npm run smoke -- http://localhost:4321    # ожидание: 14 строк ok, код выхода 0
```

Если одна проверка `canonical` падает с подсказкой — пересоберите с `PUBLIC_SITE_URL` и перезапустите.

Админка: **http://localhost:4321/admin/login**, логин `owner`, пароль `LocalReview-123456`.

Альтернатива для быстрого просмотра: `npm run dev` (без сборки), но для Lighthouse и проверки
canonical нужен именно прод-режим (`build` + `start`).

## 4. Визуальное ревью

Открывайте в браузере и снимайте скриншоты. Ширины: **1440, 1024, 860, 640, 390 (iPhone), 360**.

Проверить на каждой:

- нет горизонтального скролла на 360–390 px;
- шапка и бургер-меню работают, меню закрывается, фокус не уезжает;
- читаемость текста на тёмном фоне (контраст ≥ 4.5:1 для основного текста), видимые `:focus-visible`;
- кнопки и поля не «прыгают», тап-зоны ≥ 44 px;
- анимации (появление блоков, слайдер на главной) не дёргаются и не блокируют скролл;
  при `prefers-reduced-motion: reduce` анимации отключаются;
- формы: подписи связаны с полями, ошибки видны и понятны, маска телефона не мешает вводу.

Страницы: `/`, `/about`, `/services`, 2–3 карточки услуг, `/appointment`, `/news` + демо-новость,
`/contacts`, `/privacy`, `/404` (открыть заведомо несуществующий адрес).

## 8. Отчёт

Файл `local-review.md` в корне своего клона (не коммитить) + краткое резюме в чат.
Структура:

1. **Вердикт:** PASS / PASS c замечаниями / FAIL. Одной строкой — можно ли показывать заказчику.
2. **Окружение:** ОС, версия Node, SHA ветки, браузер, дата.
3. **Дефекты** — таблица: `ID | severity (blocker/major/minor/nit) | страница/сценарий | шаги |
   ожидание | факт | скриншот`. Блокер = нельзя запускать; major = ломает сценарий или грубо
   выглядит на телефоне; minor = косметика/неудобство; nit = придирка.
4. **Сверка с контрактом** — таблица 8 требований: есть / частично / нет + чем подтверждено.
5. **Lighthouse** — таблица цифр по двум страницам.
6. **Что не проверено и почему** (например, реальная доставка письма/Telegram, загрузка с телефона).
7. **Топ-5 приоритетов** на исправление, если бы времени было мало.
