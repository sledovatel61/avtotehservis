## 2. Жёсткие ограничения

1. **Никаких внешних запросов.** Без CDN, без Google Fonts, без `<script src="http…">`, без iframe-карт, без внешних картинок. Страницы должны открываться двойным кликом с диска.
2. **Библиотек нет.** Только нативный HTML/CSS/JS.
3. **Вес:** вся папка ≤ 900 КБ, отдельная страница ≤ 250 КБ, `style.css` + `app.js` вместе ≤ 150 КБ.
4. **Шрифты:** либо системный стек, либо **вложенный woff2-сабсет** (кириллица + латиница), ≤ 120 КБ на гарнитуру, лицензия OFL/Apache. Файл лицензии или ссылка — в записке.
5. **Изображения** — только SVG-заглушки, CSS-градиенты, инлайн-иконки. Никаких стоков и чужих фото.
6. **Горизонтального скролла нет** ни на 320 px, ни на 1440 px.
7. **Тексты — свои.** Абзацы референса не копируем: у него рыба про «специализированный автотехцентр». Берём структуру и приёмы, содержание — из досье и своих концепций.
8. **Факты — только из §7.** Ничего не выдумываем: ни года основания, ни числа заказов, ни «лучших в городе», ни цен.

## 4. Форма записи — главное улучшение

У референса форма слабая: свободные поля без валидации, время в 12-часовом формате, обязательный e-mail, нет подтверждения. **Делаем сильнее — 5 экранов:**

| Экран | Поля | Обязательность |
|---|---|---|
| 1. Авто | Марка (поиск с подсказками, топ-20 + свободный ввод), модель, год, VIN, пробег | марка — да; остальное — нет |
| 2. Что нужно | Чипы услуг по группам, «не знаю — нужна диагностика», фото до 3 файлов с превью и удалением | минимум 1 услуга или «не знаю» |
| 3. Когда | Календарь на 14 дней, слоты 09:00–19:00 шагом 1 час, кнопка «как можно раньше» | дата или «как можно раньше» |
| 4. Контакты | Имя, телефон с маской, канал связи (звонок / Telegram / WhatsApp), согласие | телефон и согласие |
| 5. Сводка | Всё выбранное, кнопка «Отправить», состояния: отправка → успех → ошибка | — |

Требования:

- VIN: 17 символов, буквы **I, O, Q запрещены**, кнопка «Не знаю VIN»;
- «Не помню год», «Не знаю пробег» — не блокируют;
- прогресс «шаг N из 5», кнопки «Назад / Далее», «Далее» неактивна, пока шаг невалиден;
- ошибки — текстом под полем, фокус на первую ошибку;
- «занятые» слоты видны, но недоступны;
- экран успеха: номер заявки, что дальше, «что взять с собой», кнопка «Позвонить»;
- отправка **имитируется** 700–1200 мс, без `fetch`, XHR и `sendBeacon`;
- под кнопкой мелко: «Демо: данные никуда не отправляются»;
- кнопка **«Что уйдёт на сервер»** открывает панель с JSON payload (см. §5).

Форма на `contacts.html` — короткая: имя, телефон, сообщение, согласие. Валидация та же.

## 5. Заявки: как они будут падать реально

Заказчик требует, чтобы заявки реально доходили. В мокапе сети нет, поэтому показываем контракт и проверяем, что payload полный.

**Payload, который форма собирает уже сейчас:**

```json
{
  "name": "Имя",
  "phone": "+79289065700",
  "contact_method": "call | telegram | whatsapp",
  "car": {"brand": "Лада", "model": "Vesta", "year": 2019, "vin": null, "mileage": 84000},
  "services": ["shinomontazh", "balansirovka"],
  "preferred": {"date": "2026-10-24", "slot": "10:00", "asap": false},
  "photos_count": 2,
  "consent": true,
  "page": "appointment",
  "idempotency_key": "uuid-v4"
}
```

**Что описать в `mockup-notes.md`:**

1. Эндпоинт: `POST /api/leads` → `201 {ticket, status:"accepted"}`.
2. Серверная цепочка: валидация → запись в БД → `outbox` → Telegram `sendMessage` владельцу → письмо на `avtotehservis439@mail.ru` (SMTP) → ретраи с интервалом → статус в админке.
3. Если Telegram упал — письмо всё равно уходит; если упало и то и другое — заявка в БД, пользователь видит «принято, номер такой-то».
4. Токен бота и пароль почты — только в переменных окружения, не в репозитории.

Никаких реальных токенов и вызовов в мокапе быть не должно.

## 6. Дизайн: своя палитра у каждого

Заказчик прямо сказал: цвета у шаблона ему не нравятся, **пусть каждый агент попробует свои**. Ниже — направления, чтобы пять мокапов не оказались одинаковыми. Отступать от своего направления можно только с обоснованием в записке.

| Агент | Направление | Ориентир |
|---|---|---|
| **A1** | Тёмная, техничная | Графит/чёрный фон, один кислотный акцент (лайм, электро, циан) |
| **A2** | Светлая, тёплая, «бумажная» | Песок/тёплый белый, чернильный синий, коралловый акцент |
| **A4** | Индустриальная светлая | Бетон/сталь, графит, сигнальный оранжевый |
| **A5** | Глубокая тёмная, «премиум» | Ночь/тёмно-изумрудный, медь или латунь, тёплый свет |
| **A6** | Плакатная, высококонтрастная | Белый + две крупные насыщенные плоскости, большие цветовые блоки |

Обязательно в записке:

- палитра 6–8 цветов с ролями (фон, поверхность, текст, вторичный текст, акцент, успех, ошибка);
- **контраст каждой пары текста посчитан** по WCAG, с числами; ниже 4,5:1 — не годится для обычного текста;
- белый текст на насыщенном акценте проверяется отдельно — часто не проходит;
- тёмная тема не должна быть «серым по чёрному»: нужна внятная иерархия поверхностей.

**Шрифты.** Заказчик назвал шрифты шаблона топорными. Нужна пара: дисплейный/акцидентный + текстовый, оба с **подтверждённой кириллицей**. Проверить наличие кириллицы в файле/сабсете, а не «на глаз». Разрешённые варианты (OFL): Manrope, Onest, Inter Tight, Golos Text, Unbounded, Oswald, Rubik, Commissioner. Один-два варианта — вложить сабсетом, остальное — системный стек с описанием продакшн-пары в записке.

**Типографика:** крупные заголовки (clamp), плотный отрицательный трекинг у дисплея, аккуратная шкала, не больше 4 начертаний.

## 7. Анимация: сильнее, но по-прежнему лёгкая

Заказчик сказал «слабая анимация». Нужна система движения, а не гифка. **8–12 эффектов**, только `transform` и `opacity`, 150–600 мс, `cubic-bezier(.2,.8,.2,1)` или похожий.

Минимум:

1. слайдер-герой: плавная смена слайдов (fade + лёгкий сдвиг), без «дёрганья»;
2. появление секций при скролле (IntersectionObserver), каскад с задержками 0/80/160 мс;
3. hover карточек услуг: подъём на 2–4 px + смена границы/фона;
4. карусель галереи и отзывов: сдвиг по transform, без layout-скачков;
5. лайтбокс: масштаб 0.98 → 1 + прозрачность;
6. переход между шагами формы: сдвиг по X и fade;
7. прогресс-бар формы: `scaleX`;
8. появление/скрытие шапки при скролле (compact-состояние);
9. счётчики цифр (опыт, работы) — если цифра подтверждена, иначе не выводим;
10. «бегущая строка» марок — только CSS, пауза при hover;
11. переход между страницами: View Transitions API там, где поддерживается, с мгновенным fallback;
12. экран успеха: отрисовка галочки/талона.

Запрещено: parallax, scroll-jacking, WebGL, 3D, автоплей видео со звуком, бесконечные анимации, анимация `top/left/width/height`, тяжёлые тени в движении.

`prefers-reduced-motion: reduce` отключает всё движение, оставляет смену состояний.

В записке — таблица: эффект, триггер, длительность, стоимость (КБ), поведение при reduced-motion.

## 8. Мобайл

- База 390×844, проверка **320 / 390 / 768 / 1024 / 1440**.
- Тапы ≥ 44×44, поля ≥ 16 px (иначе iOS зумит), `env(safe-area-inset-bottom)`.
- На мобиле: бургер-меню на весь экран, sticky-панель снизу («Позвонить» + «Записаться»), она не перекрывает контент и футер.
- Форма — одна колонка, крупные чипы, календарь горизонтальной лентой, слоты сеткой 3×.
- Карусели — свайпом, без горизонтального скролла страницы.
- Клавиатура: таб-порядок, `:focus-visible`, Esc закрывает меню, лайтбокс и модалки.

## 11. Git-протокол

1. Работаешь в своей ветке, выданной платформой (`arena/…`), имя не меняешь.
2. Файлы — **только** в `mockups/agent-NN/`. Старый одностраничный мокап в этой папке заменяется новым: он больше не участвует.
3. Коммит: `agent-NN: этап 3 — многостраничный мокап по референсу`.
4. Пуш в свою ветку, PR в `main`. В описании: что взято у референса, что переделано, результаты самопроверки.
5. Чужие файлы не правишь, `main` в свою ветку не мержишь.
