## 5. Форма записи: чиним всё, что сломано в референсе

У шаблона форма слабая — заказчик это заметил. Вот её реальные дефекты (проверено по коду `Запись/_files/car-7.html`), и каждый должен быть закрыт:

| Дефект референса | Как надо у нас |
|---|---|
| Год — слайдер 1987–2025 (попасть невозможно) | Поле года с валидацией 1980–2026 или список; «не помню» |
| Марка — селект из 9 марок | Поиск по марке (топ-20 + свободный ввод), «другая» |
| Пробег — свободный текст | Числовое поле с подсказкой «км», необязательное |
| Дата — поле с плейсхолдером `MM/DD/YYYY` | Русский календарь, формат `ДД.ММ.ГГГГ`, 14 дней |
| Время — `09:00 AM – 10:00 AM`, 9 слотов, до 18:00 | Слоты 09:00–19:00, шаг 1 час, 24-часовой формат, «занято» видно и недоступно |
| Услуги — чекбоксы, значения собираются из текста `li` | Чипы с явными значениями (slug), минимум одна или «не знаю» |
| E-mail обязателен | E-mail не спрашиваем; телефон и имя — да |
| Валидация только «пусто / не пусто» | Проверка телефона, VIN, года; ошибки под полем, фокус на первую |
| Нет согласия на обработку ПД | Отдельный чекбокс, не предустановлен, ссылка на политику |
| Модалка «Отправлено», без номера | Экран с номером заявки, «что дальше», «что взять с собой» |
| Поля чистятся до ответа сервера | Данные сохраняются при ошибке; повторная отправка не дублирует заявку |

**Пять экранов:**

| Экран | Поля | Обязательность |
|---|---|---|
| 1. Авто | Марка (поиск), модель, год, VIN, пробег | марка — да, остальное — нет |
| 2. Что нужно | Чипы услуг по группам, «не знаю — нужна диагностика», фото до 3 файлов с превью и удалением | минимум одна услуга или «не знаю» |
| 3. Когда | Календарь на 14 дней, слоты 09:00–19:00, кнопка «как можно раньше» | дата или «как можно раньше» |
| 4. Контакты | Имя, телефон с маской, канал связи (звонок / Telegram), согласие | телефон и согласие |
| 5. Сводка | Всё выбранное, «Отправить», состояния: отправка → успех → ошибка | — |

Дополнительно:

- VIN: 17 символов, **I, O, Q запрещены**, кнопка «Не знаю VIN»;
- «Не помню год», «Не знаю пробег» не блокируют;
- прогресс «шаг N из 5», «Назад / Далее», «Далее» неактивна, пока шаг невалиден;
- черновик сохраняется в `localStorage`, если он доступен; при ошибке (приватный режим, `file://`) форма продолжает работать, а не падает;
- отправка имитируется 700–1200 мс, **без `fetch`, XHR и `sendBeacon`**;
- телефон проверяется по длине и цифрам, маска `+7 (999) 999-99-99`, вставка из буфера не ломает поле;
- ссылка на политику обработки ПД открывает модальное окно с коротким текстом: отдельной страницы в референсе нет, выдумывать её не надо;
- под кнопкой мелко: «Демо: данные никуда не отправляются»;
- кнопка **«Что уйдёт на сервер»** открывает панель с JSON payload.

Форма на `contacts.html` — короткая, валидация та же.

## 6. Заявки: реальная доставка

Заказчик требует, чтобы заявки реально приходили. В мокапе сети нет — показываем контракт и проверяем полноту данных.

**Payload:**

```json
{
  "name": "Имя",
  "phone": "+79289065700",
  "contact_method": "call | telegram",
  "car": {"brand": "Лада", "model": "Vesta", "year": 2019, "vin": null, "mileage": 84000},
  "services": ["shinomontazh", "balansirovka"],
  "preferred": {"date": "2026-10-24", "slot": "10:00", "asap": false},
  "photos_count": 2,
  "consent": true,
  "page": "appointment",
  "idempotency_key": "uuid-v4"
}
```

**В `mockup-notes.md` описать:**

1. `POST /api/leads` → `201 {ticket, status:"accepted"}`.
2. Сервер: валидация → запись в БД → `outbox` → Telegram `sendMessage` владельцу → письмо на `avtotehservis439@mail.ru` (SMTP) → ретраи → статус в админке.
3. Telegram упал — письмо уходит; упало всё — заявка в БД, клиент видит «принято, номер такой-то».
4. Токен бота, `chat_id` и пароль почты — только в переменных окружения. В мокапе никаких токенов и вызовов.

### 7.2. Типографика

Заказчик назвал шрифты шаблона топорными — значит, пара должна быть заметно лучше Open Sans + Montserrat под капс.

- Дисплейный + текстовый, оба с **подтверждённой кириллицей**;
- можно вложить woff2-сабсет (кириллица + латиница) ≤ 120 КБ на гарнитуру, лицензия OFL/Apache;
- CDN и Google Fonts запрещены;
- варианты: Manrope, Onest, Inter Tight, Golos Text, Unbounded, Oswald, Rubik, Commissioner, Steppe;
- крупные заголовки через `clamp`, плотный отрицательный трекинг у дисплея, не больше 4 начертаний;
- капс — дозированно: надзаголовки и кнопки, не всё подряд.

В notes: пара, лицензия, чем подтверждена кириллица (наличие глифов в файле), продакшн-альтернатива, если сабсет не влез.

## 8. Анимация

«Слабая анимация» — вторая претензия. Нужна система, а не гифка: **8–12 эффектов**, только `transform` и `opacity`, 150–600 мс, общий easing.

Минимум:

1. слайдер-герой: плавная смена (fade + сдвиг), без дёрганья;
2. появление секций при скролле, каскад 0/80/160 мс;
3. hover карточек услуг: подъём 2–4 px, смена границы;
4. карусель галереи и отзывов: сдвиг на `transform`;
5. лайтбокс: масштаб 0.98 → 1 + прозрачность;
6. переход шагов формы: сдвиг по X + fade;
7. прогресс-бар формы: `scaleX`;
8. компактная шапка при скролле;
9. счётчики — только по подтверждённым цифрам;
10. бегущая строка марок — CSS, пауза при hover;
11. переход между страницами — View Transitions API с мгновенным fallback;
12. экран успеха: появление талона/галочки.

Запрещено: parallax, scroll-jacking, WebGL, 3D, автоплей видео со звуком, бесконечные анимации, анимация `top/left/width/height`.

`prefers-reduced-motion: reduce` отключает движение, оставляет смену состояний.

В notes — таблица: эффект, триггер, длительность, стоимость в КБ, поведение при reduced-motion.
