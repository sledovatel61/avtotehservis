## 2. Блокер: лимиты и блокировка входа обходятся заголовком `X-Forwarded-For`

### Как воспроизводится (проверено, в том числе через имитацию nginx из `deploy/`)

```
# 30 заявок с XFF: 1.1.1.1 → 30 × 201
# 31-я, тот же XFF         → 429
# 32-я, XFF: 2.2.2.2       → 201     ← новый бакет, лимита нет

# 10 попыток входа с ротацией XFF → 401 × 10, ни одной блокировки
# контроль: 6 попыток с одного адреса → на 6-й «Слишком много попыток»
```

### Причина

```ts
// src/server/http.ts:19
const xff = ctx.request.headers.get('x-forwarded-for');
if (xff) return xff.split(',')[0].trim();   // ← ПЕРВЫЙ элемент = то, что прислал клиент
```

```ts
// src/server/admin-auth.ts:19 и :31 — тот же разбор, продублирован дважды
const ip = ctx.request.headers.get('x-forwarded-for')?.split(',')[0]?.trim() ?? 'local';
```

```nginx
# deploy/nginx.conf:76
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # "<клиентский XFF>, <реальный IP>"
```

`$proxy_add_x_forwarded_for` **дописывает** реальный адрес в конец; приложение читает **первый** — то есть клиентский. От этого значения зависят: жёсткая квота заявок (`leads-ip`), жёсткий антифлуд (`af-ip`), лимит загрузок, ключ блокировки входа и `ip_hash` в карточке заявки.

Это не регресс третьего круга: код такой же с первого коммита (`b8cb474`). Но теперь IP — единственный жёсткий ключ, поэтому дефект стал дырой: заявки льются в Telegram без ограничения, пароль админки перебирается бесконечно.

## 3. Как чинить — важно: два изменения, не одно

Наивные варианты **не работают**, я проверил оба. Не трать на них круг.

### ❌ Не делать: заменить на `Astro.clientAddress`

Разобрал `@astrojs/node`: адрес = `forwardedClientIp || socket.remoteAddress`, причём заголовку доверяют только при валидном Host из `security.allowedDomains`.

| Что настроено | Результат |
|---|---|
| `allowedDomains` нет (сейчас) | за nginx все клиенты = `127.0.0.1` → **один бакет на весь сайт**: 5 заявок/час и блокировка входа после 5 чужих попыток |
| `allowedDomains` есть | `getFirstForwardedValue` берёт **первый** элемент → подделка проходит, дыра та же |

### ❌ Не делать: только правку nginx

Если оставить `split(',')[0]`, приложение всё равно прочитает клиентское значение, пока nginx его не перезапишет. А если перезапишет — код продолжит работать случайно, а при смене прокси снова сломается.

### ✅ Делать: оба уровня

**1. `deploy/nginx.conf`** — перезапись вместо дописывания, во всех местах, где стоит `$proxy_add_x_forwarded_for` (строки 67 и 76):

```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_set_header X-Forwarded-For $remote_addr;    # было $proxy_add_x_forwarded_for
```

Добавь комментарий, почему: единственный прокси на хосте — доверенный, клиентский заголовок не наследуем. Если позже появится второй прокси/CDN, это место придётся пересмотреть.

**2. `src/server/http.ts`** — один хелпер, которым пользуются **все** места:

```ts
/** Адрес клиента. Доверяем только тому, что ставит наш nginx:
 *  X-Real-IP (перезаписывается $remote_addr), иначе — ПОСЛЕДНИЙ элемент XFF
 *  (ближайший к приложению хоп), иначе заглушка для локального запуска. */
export function clientIp(ctx: APIContext | { request: Request }): string {
  const real = ctx.request.headers.get('x-real-ip')?.trim();
  if (real) return real;
  const xff = ctx.request.headers.get('x-forwarded-for');
  if (xff) {
    const parts = xff.split(',').map((s) => s.trim()).filter(Boolean);
    if (parts.length) return parts[parts.length - 1];
  }
  return 'local';
}
```

**3. `src/server/admin-auth.ts`** — убрать оба дублирующих разбора (`:19` в `loginRateKey`, `:31` там же) и вызывать `clientIp(ctx)`. Импорт из `./http.ts`, чтобы логика была одна.

**4. Тесты** (`tests/admin.test.ts`, `tests/integration.test.ts`):

- лимит заявок: при `RATE_LIMIT_LEADS_IP=3` — 10 запросов с **разными** `X-Forwarded-For` от одного и того же сокета → **429 уже на 4-м**;
- вход: 6 попыток с ротацией `X-Forwarded-For` → на 6-й блокировка;
- и обратное: два клиента с разными `X-Real-IP` **не** мешают друг другу (мягкий уровень продолжает работать).

Тесты должны идти через HTTP с заголовками — сервер в тестах уже поднимается, добавь параметры запроса.
