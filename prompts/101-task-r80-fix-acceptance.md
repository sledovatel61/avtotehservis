## B1 (блокер). Сервер всё ещё отклоняет заявку из-за «занятого» часа

A9 воспроизвёл вживую: заявка на прошедший час или третья заявка в один час возвращает
`409 slot_taken` → «Выбранное время только что заняли. Выберите, пожалуйста, другой слот.»,
пользователя выкидывает на шаг 3. Слово «занято» остаётся в `site/src` и в бандле мастера.
Это прямо противоречит решению владельца: **сервис работает в порядке живой очереди, время —
пожелание, мастер согласует его звонком**. Сайт не имеет права отказывать из-за часа.

Владелец подтвердил: **переходим на чистую живую очередь, серверный контроль часов из приёма
заявки убираем.**

Что сделать:

1. `site/src/server/leads.ts` — убрать проверку `if (!isSlotAvailable(...)) throw new SlotTakenError(...)`
   из `createBooking`. Класс `SlotTakenError` и `getSlots`-импорт, если больше не нужны, удалить.
2. `site/src/pages/api/leads.ts` — убрать обработчик `409 slot_taken` и его текст. Валидация
   даты/слота остаётся как есть (`bookingSchema`: `date` в пределах 14 дней, `slot` из `SLOT_TIMES`),
   то есть мусор по-прежнему не пройдёт, но «в этом часу уже двое» — больше не повод для отказа.
3. `site/src/server/slots.ts` — `getSlots()` больше не считает ёмкость и ручные блокировки:
   возвращать `available: false, reason: 'past'` только для прошедших часов сегодняшнего дня.
   Слово «занято» из файла убрать. `slot_capacity`/`slot_blocks` — не удалять из БД (миграции
   не трогаем), просто не использовать при приёме заявок; в комментарии написать, что сервис
   работает в порядке живой очереди и блокировки оставлены на будущее.
4. `site/src/client/wizard.ts` — убрать запасной текст «Выбранное время занято — выберите другой
   слот» и ветку разбора 409, если она есть. После правки `git grep -n "занят" -- site/src`
   по клиентским и серверным файлам должен давать только безобидные вхождения (например
   `tokens.css` — цветовая переменная или подпись в интерфейсе админки; если это текст для
   клиента, переформулировать).
5. Тесты: `site/tests/integration.test.ts:518` («слоты API: дата обязательна, 14 дней, занятость
   из БД») сейчас ждёт, что забронированные часы недоступны. Переписать под живую очередь:
   десять слотов, единственная недоступность — `reason: 'past'` для прошедшего часа сегодня.
   Добавить тест: **три заявки на один и тот же час подряд проходят** (все три `201`), и заявка
   на прошедший час сегодня тоже проходит. Ищи существующий тест про `slot_taken` и удали его.

Проверка после правки: `git grep -rn "занят" -- site/src site/pages-dist` → ни одного текста для
клиента; `grep -rl "занято" pages-dist` → пусто; третий POST в один час → `201`.
