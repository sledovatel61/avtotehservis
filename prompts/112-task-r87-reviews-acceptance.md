## Что проверять (после мержа A13, A14, A15)

- `site/content/reviews.json` соответствует схеме из `prompts/109` §A.
- Битый файл, отсутствующий файл, `rating: 9`, дубль `id` — сайт не падает; в отчёте — что именно отброшено.
- `hidden` не виден на сайте; `demo: true` виден только с `PUBLIC_DEMO_REVIEWS=1` и всегда с чипом «пример».

### 2. Страница `/otzyvy`

- 1440 / 768 / 390: сетка не ломается, ничего не вылезает по горизонтали, звёзды и чипы читаемы.
- Фраза «Читайте отзывы на Яндекс.Картах — там же оценки и схема проезда.» **дословно** на месте (главная, пустое состояние) — сверить с `origin/preview/github-pages`.

- Клавиатура: форма проходится Tab, звёзды работают стрелками, ошибки объявляются `aria-live`.
- Контраст: чип «пример», подписи, звёзды ≥ 4.5:1 (замерить, не на глаз).

### 3. Форма

- Пустая отправка → ошибки у всех обязательных полей, фокус на первом.
- 19 знаков → ошибка; 20 → уходит.
- Оценка не выбрана → ошибка (по умолчанию не 5).
- Без согласия → ошибка.
- Успешная отправка → сообщение «ушёл на проверку», поля очищены, повторная отправка не дублирует (в течение 10 минут тот же текст → `429` или тихий дубль-фильтр, описать фактическое поведение).
- Ссылка в тексте (`http://…`) → отказ с понятным текстом.
- Honeypot: заполнить скрытое поле через devtools → 201, но **ничего** не пришло в Telegram (проверить по логу воркера/`wrangler tail`).

### 4. Воркер

- `POST /reviews` по контракту `prompts/110`: коды 201/400/403/429.
- Уведомление реально приходит в группу Telegram: скрин сообщения в отчёт.
- Письмо на `Pavel.yakovenko@mail.ru` (если ключ почты уже стоит) — приложить факт; если `email:null` — отметить «не проверено, почта ещё не подключена», это не дефект.

## Формат отчёта `promts/r87-acceptance.md`

1. Итог: **принимаю / не принимаю** + одна строка почему.
2. Таблица проверок: пункт → результат → чем подтверждено (скрин/лог/команда).
3. Блокирующие дефекты (файл:строка, воспроизведение, ожидаемое/фактическое).
4. Некритичные замечания.
5. Цифры тестов и гейтов до/после.
6. Отдельный раздел **«Что должен сделать владелец перед запуском»**: заменить демо-отзывы настоящими, прогнать `check-reviews.mjs --strict`, добавить домен в `ALLOWED_ORIGINS`.
