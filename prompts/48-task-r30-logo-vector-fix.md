## 2. Блокер 1: `vy-mark.svg` обрезан — в файле половина знака

`viewBox="0 0 441 622"`, а контуры знака занимают **x 162.6…631.9**. Правая лопасть (`blade-right`,
x 443.7…631.9) целиком за правой границей кадра → **в файле рисуется левая лопасть и игла, правой нет**.
Проверь сам:

```sh
node -e "require('@resvg/resvg-js')" # у тебя стоит
# отрендери vy-mark.svg в PNG и посмотри глазами: правой лопасти нет
```

Почему гейт это пропустил — три слепых пятна, их надо закрыть:

1. Все пиксельные метрики (IoU, покрытие, габариты, карта ошибки) считаются по **`vy-logo.svg`**,
   а `vy-mark.svg` проверяется только на «3 контура» и «лейбл не входит» — геометрия не рендерится.
2. `compare.png` показывает **локап**, а не тот файл, который пойдёт на страницу. Владелец видит
   в отчёте полный знак, а в проекте оказывается половинка — ровно та ошибка, за которую он уже
   дважды заворачивал работу («на скрине одно, в файле другое»).
3. Проверка bbox сравнивает подпути с bbox локапа, а не с bbox знака в эталоне.

**Что сделать:**

- `viewBox` для знака — **плотный bbox по всем трём контурам** с отступом 0.5 px:
  по твоим же данным это `viewBox="162.1 0.3 470.3 621.2"` (пересчитай сам, не копируй слепо).
  Лейбл в файл знака не включать.
- Новый блок гейта **`M1`..`M4` для `vy-mark.svg` отдельно**: рендер → маска → bbox (допуск ±2 px
  к bbox знака в эталоне), площадь (±1.5 %), IoU ≥0.96, «ни одного пикселя контура вне кадра».
  Плюс мутант `--self-test`: подрежь `viewBox` на 40 px — гейт **должен упасть**. Без этого мутанта
  пункт не принимается.
- `compare.png`: панель 1–4 оставить, но рендерить **`vy-mark.svg`** (то, что пойдёт в проект),
  локап — отдельной строкой ниже.

## 3. Блокер 2: цвет невидим на сайте

Ты честно взял `#1B1F3C` из файла владельца. Но на странице знак стоит на почти чёрном фоне
(`#070b12` в первом экране, `#0b0f16` в панели прайса). Контраст посчитан:

| Пара | Контраст |
|---|---|
| `#1B1F3C` на `#070b12` | **1.23 : 1** |
| `#1B1F3C` на `#0b0f16` | **1.20 : 1** |
| `#ffffff` на `#070b12` | 19.71 : 1 |

То есть твой SVG на сайте практически исчезнет. Норма для знака — как у текста, не ниже 3:1.

**Что сделать — три файла вместо одного:**

| Файл | Заливка | Где |
|---|---|---|
| `vy-mark.svg` | `fill="currentColor"` | инлайн в разметке (только так наследуется цвет) |
| `vy-mark-light.svg` | `#FFFFFF` | `<img>` и CSS-фоны на тёмном |
| `vy-mark-dark.svg` | `#1B1F3C` | светлые подложки, печать, документы |
| `vy-mark-ghost.svg` | `#FFFFFF` + `fill-opacity=".13"` | водяные знаки вместо `vy-mark-ghost.png` |

Почему так: `currentColor` **не работает** ни в `<img src="…svg">`, ни в `background-image: url(…)` —
там SVG изолирован. Поэтому для страницы — инлайн, для фонов — файл с явной заливкой.
`vy-logo.svg` (локап) — тоже два варианта по тому же принципу.

В гейт добавь **`M5`: контраст заливки к обоим фонам страницы ≥ 3:1** (посчитай формулой WCAG,
как это делают `scripts/measure-contrast.mjs`).
