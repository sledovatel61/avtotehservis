## W1. ««Сохранить» сохраняет её без публикации» — не всегда

`docs/16`, §3, шаг 7:

> Нажмите **«Опубликовать»**, чтобы разместить запись на сайте. **«Сохранить»** сохраняет
> её без публикации.

На самом деле кнопка «Сохранить» не трогает статус: что выбрано в поле «Статус», то и уйдёт
в `cases.json` (`app.js`: `if(action==='publish')` принудительно ставит `published`, ветка
обычного сохранения значение не меняет). То есть «Новая работа» → статус «На сайте» →
«Сохранить» **публикует** запись, хотя инструкция обещает обратное. Владелец может
опубликовать недоделанную работу, считая, что она в черновиках.

**Что сделать:** переписать шаг, чтобы правило было видно без оговорок. Смысл:
статус задаёт поле «Статус» («Черновик» / «На сайте»); «Опубликовать» = сохранить сразу
опубликованной; «Сохранить» = сохранить с тем статусом, что выбран, — при «Черновике»
записи на сайте не будет. Подписи в кавычках — ровно как в интерфейсе:
**«Опубликовать»**, **«Сохранить»**, **«Черновик»**, **«На сайте»**.

Заодно проверь §6, пункт «Запись не появилась на сайте» — он должен отправлять владельца
именно к полю «Статус», а не к кнопке.

## W2. «Ход сборки ↗» открывает список, а не запуск

`docs/16`, §4:

> Ссылка **«Ход сборки ↗»** открывает запуск GitHub Actions.

Ссылка ведёт на `https://github.com/sledovatel61/avtotehservis/actions` — это **список**
сборок; конкретный запуск владелец выбирает сам (обычно верхний). В §6 при этом правильно
сказано «откройте самый новый запуск» — то есть §4 обещает больше, чем есть.

**Что сделать:** «открывает список сборок сайта в GitHub Actions — откройте самый новый
запуск». Формулировку в §6 согласуй с §4, чтобы шаги читались как один путь.
