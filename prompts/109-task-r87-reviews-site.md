4. Блок на главной **остаётся** и работает: если отзывов нет — прежняя карточка «Читайте отзывы на Яндекс.Картах — там же оценки и схема проезда.», эту формулировку **НЕ менять** (решение владельца).
5. 6 демо-отзывов, помеченных как демо, — чтобы раздел не был пустым на превью.

## A. Файл данных `site/content/reviews.json`

Схема (строго):

```json
{
  "updated_at": "2026-11-19",
  "items": [
    {
      "id": "r-2026-11-19-001",
      "author": "Имя И.",
      "text": "Текст отзыва, 20–1500 знаков.",
      "rating": 5,
      "source": "site",
      "source_url": null,
      "published_at": "2026-11-19",
      "status": "published",
      "demo": false
    }
  ]
}
```

- `source`: `site` | `yandex` | `2gis` | `demo`.
- `status`: `published` | `hidden`.
- `rating`: целое 1–5.
- `id`: стабильный, `r-YYYY-MM-DD-NNN`, уникальный; менять нельзя (админка ссылается по `id`).
- `demo: true` — отзыв-пример. Рендерится **только** при `PUBLIC_DEMO_REVIEWS=1` и **всегда** с видимой пометкой «пример».

Сделай по образцу `site/src/shared/cases-schema.ts` + `site/src/server/cases-store.ts`:

- `site/src/shared/reviews-schema.ts` — типы, `parseReviewsFile(json)` с мягкой валидацией (битая запись отбрасывается, остальное читается; собирается список `errors`);
- `site/src/server/reviews-store.ts` — чтение файла, кэш по mtime, переменная окружения `REVIEWS_FILE` для тестов, диагностика `{count, demoCount, errors, path}`;
- сайт **не падает** при отсутствии/порче файла: пусто → `[]` и прежние заглушки.

Правило публикации в выдачу: `status === 'published'` и (`demo === false` или `PUBLIC_DEMO_REVIEWS === '1'`). Сортировка: новые выше (`published_at` desc).

## C. Форма отзыва

Поля:
- **Имя** (2–40 знаков, обязательно). Подсказка: «Как к вам обращаться. Можно только имя и первую букву фамилии — «Павел И.»
- **Оценка** — 5 звёзд-радиокнопок, обязательно, по умолчанию пусто (не 5 — иначе это накрутка).
- **Отзыв** (20–1500 знаков, обязательно), счётчик знаков.
- **Согласие на обработку персональных данных** — чекбокс со ссылкой на `/consent`, обязателен, версия `CONSENT_VERSION` из настроек (как в форме заявки, `site/src/client/wizard.ts` — переиспользуй подход).
- Скрытое поле-ловушка `company` (honeypot): если заполнено — форма «успешно» отправляется, но запрос никуда не идёт.

Поведение:
- `POST {LEADS_ENDPOINT}/reviews` с JSON `{author, text, rating, consent, consentVersion, honeypot, page}`; адрес прослойки берётся из того же механизма, что и у формы заявки (`site/src/shared/leads-endpoint.ts`), **не хардкодить**.
- В демо-сборке без адреса прослойки (`npm run build` без `PUBLIC_LEADS_ENDPOINT`) — форма показывает плашку «Отправка отзывов сейчас недоступна» и **не** отправляет (как у заявок).
- Состояния: отправка → успех («Спасибо! Отзыв ушёл на проверку. Опубликуем после проверки — обычно в течение дня») → ошибка (сеть/429/400) с понятным текстом, без потери введённого.
- Доступность: `label` у всех полей, `aria-live` для статуса, фокус на первое поле с ошибкой, звёзды работают с клавиатуры.
- CSP: форма шлёт `fetch` на другой origin — убедись, что `connect-src` в `site/src/middleware.ts` это разрешает для адреса прослойки (или что экспорт это не ломает).

## D. Демо-отзывы (чтобы не было пусто)

Добавь в `reviews.json` **6 демо-записей**: `demo: true`, `source: "demo"`, `status: "published"`, разные оценки 4–5, живые по тону, про работы, которые сервис реально делает (шиномонтаж, тормоза, подвеска, ТО, развал, диагностика). Имена — «Павел И.», «Марина С.», «Дмитрий К.», «Ольга В.», «Артём Л.», «Сергей Н.» (без фамилий целиком).

Требования к демо:
- на карточке видимый чип **«пример»** (не мельче 12 px, контраст ≥ 4.5:1);
- на странице под сеткой, если показан хотя бы один демо-отзыв, — плашка: «Отзывы с пометкой «пример» — образец оформления. Перед запуском на своём домене их нужно заменить настоящими: админка → Отзывы.»
- `site/scripts/check-reviews.mjs` — новый гейт: с `--strict` падает, если в файле остался хотя бы один `demo: true` (этот режим включим при переезде на домен); без флага — предупреждение в лог.

Публичный список **не должен** попадать в поиск как «отзывы клиентов» с фейками: на демо-сборке ставим `<meta name="robots" content="noindex">` только для страницы `/otzyvy`, если показаны демо? — **Нет**: превью и так закрыто от индексации, не усложняй.
