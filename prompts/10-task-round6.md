## 2. Что сделать сейчас (доступы не нужны)

### 2.1 `npm run smoke <url>` — проверка живого сервера одной командой

Скрипт `scripts/smoke.mjs`, запуск: `npm run smoke -- https://домен` (по умолчанию `http://localhost:4321`).
Проверки, каждая — строка `ok/FAIL` и итоговый код выхода:

| Проверка | Ожидание |
|---|---|
| `/`, `/about`, `/services`, `/appointment`, `/news`, `/contacts`, `/privacy` | 200, `content-type: text/html` |
| `/api/health` | 200 и `db:true`, `schema:true` |
| `/api/slots?date=<завтра>` | 200, в `slots` есть хотя бы один `available:true` |
| `/robots.txt`, `/sitemap.xml` | 200, в sitemap перечислены страницы |
| `/admin` без сессии | 302 на `/admin/login` |
| `/media/<несуществующий>` | 404, не 500 |
| канонический адрес на `/` | содержит переданный `url`, а не `localhost` |

Заявку **не отправлять** (не засорять боевую базу) — только чтение и health. Форму проверим руками
при приёмке.

### 2.2 `docs/13-launch-checklist.md` — запуск по шагам для владельца

Один документ, по которому заказчик или подрядчик запускает сайт без нас. Обязательные разделы:

1. **Домен** — что регистрировать (`avtotehservis439.ru` как рабочий вариант), где, сколько, как
   направить A-запись.
2. **Сервер** — минимальная конфигурация (2 ГБ RAM / 2 vCPU / 20 ГБ SSD хватает?), Node 22.18+,
   как проверить версию.
3. **Почта для заявок** — что нужно от владельца: SMTP-хост, порт, логин, пароль приложения
   (не пароль от ящика), адрес получателя. Как проверить, что письмо уходит, **не отправляя заявку
   в боевую базу** (тестовая команда из `deploy.md`).
4. **Telegram** — создать бота у `@BotFather`, узнать `chat_id`, добавить бота в чат, что писать
   в `env`, как убедиться, что дубль дошёл.
5. **Первый деплой** — по `deploy.md`, с явными «стоп-точками»: миграция, `admin:create`, `build`,
   systemd, nginx, сертификат.
6. **Что заменить после запуска** — ссылка на `docs/12-content-checklist.md`: демо-отзывы, демо-новости,
   фото работ, телефоны, реквизиты.
7. **Бэкапы и восстановление** — расписание `backup.sh`, проверка `restore.sh` на копии.
8. **Чек-лист «сайт жив»** — `npm run smoke`, вход в админку, тестовая заявка с пометкой «тест»,
   письмо, дубль в Telegram, удаление тестовой заявки.

Пиши так, чтобы человек без DevOps мог пройти по шагам; всё, что требует нас, помечай «нужен оркестратор».

### 2.3 Демо-контент отдельной командой — по желанию, но аккуратно

Сейчас для показа заполняем базу руками. Если делать сид — то только так:

- `npm run seed:demo` — **отдельная** команда, не часть `db:seed`; в прод-сиде демо нет;
- все демо-записи помечены (`reviews.source = 'demo'`, у новостей `slug` начинается с `demo-`),
  чтобы их можно было найти и удалить одним запросом;
- `npm run seed:demo:clear` — удаляет только помеченное;
- в README — предупреждение: **демо-отзывы нельзя оставлять на боевом сайте**, это вымышленные люди;
- фото в демо — только те, что лежат в репозитории как заглушки, без выдачи за реальные работы сервиса.

Если решишь, что команда лишняя, — напиши почему, вместо того чтобы молча пропустить.
