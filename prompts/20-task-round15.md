## 1. Дефект №1 (P1, блокирующий) — герой не занимает ширину окна

### 1.1. Что измерено (не гипотеза)

Пиксельные замеры по четырём скринам (`ImageMagick`, `-format %[pixel:p{x,y}]`):

| скрин | окно | правый край кадра | правый край полосы/разделов | заливка справа |
|---|---|---|---|---|
| a | 1217×598 | **890** | — | `rgb(11,20,17)` = `--night` |
| b | 1212×603 | **890** | — | `--night` |
| c | 1223×604 | **893** | картинка полосы тянется до 1200+, `h2` — до ~1190 | `--night` в герое, `--deep` ниже |
| d | 1221×602 | (раздел «О компании» — во всю ширину) | 1190 | — |

То есть **сжат только герой**. Шапка, полоса из трёх кадров, заголовок «Чем сервис занимается
каждый день» и карточка «О компании» — во всю ширину окна. Это не кроп фотографии и не мобильная
панель: кадр режется ровной вертикальной кромкой на 73 % ширины.

### 1.2. Причина (установлена по числам, A5 обязана подтвердить рендером)

`site/src/styles/hero.css`, блок `@media (min-width:1024px)`:

```css
.hero{ ...; min-height:0; aspect-ratio:16/9; max-height:calc(100svh - 96px) }
```

`96px` — высота шапки. На окне 1217×598: `max-height` = 598 − 96 = **502 px**. Браузер считает
высоту из `aspect-ratio` (1217 × 9/16 = 684), упирается в `max-height` → 502, и **переносит
ужатую высоту обратно в ширину**: 502 × 16/9 = **892,4 px**. Замер: 890–893. Совпадение в пределах
1–2 px на трёх разных скринах — это и есть механизм.

Проверка на других окнах (та же формула, `heroW = (vh − 96) × 16/9`):

| окно | ожидаемая высота героя | «ширина» героя | пустая полоса справа |
|---|---|---|---|
| 1217×598 (скрин заказчика) | 502 | 892 | **325 px** |
| 1366×768 | 672 | 1195 | 171 px |
| 1440×900 | 804 | 1429 | 11 px (не видно — поэтому и не поймали) |
| 1920×950 | 854 | 1518 | **402 px** |
| 2560×1080 | 984 | 1749 | **811 px** |
| 2560×1440 | 1344 | 2389 | 171 px |

Дефект не «мобильный»: он бьёт по **любому окну, которое шире, чем 16:9 с учётом шапки**. На
2560×1080 в пустоту уходит треть экрана. Мобильный браузер в ландшафте — просто самый наглядный случай.

Оркестратор **не прогонял браузер** (в песочнице нет `libnss3`), поэтому причина установлена
расчётом и пиксельными замерами. Первое, что делает A5 — **рендерит и снимает замер**
(`document.querySelector('.hero').getBoundingClientRect()`), пишет число в отчёт. Если ширина
всё-таки 100 %, значит виновато что-то другое — и это надо назвать, а не «поправить на глаз».

### 1.3. Что сделать

1. Сделать ширину героя **определённой**, чтобы `aspect-ratio` не мог её пересчитать:

   ```css
   @media (min-width:1024px){
     .hero{ width:100%; aspect-ratio:16/9; max-height:calc(100svh - 96px); }
   }
   ```

   Кадр остаётся фулл-блид (`object-fit:cover`, `object-position:50% 50%`), высота — как сейчас
   (на 16:9-экранах 2560×1440 герой остаётся 1344 px — принятый вид круга 14 **не менять**).

2. Если замер после `width:100%` всё равно даёт < 100 % (значит перенос ширины остался) — убрать
   `aspect-ratio` и задать высоту явно:

   ```css
   .hero{ width:100%; aspect-ratio:auto; height:min(calc(100svh - 96px), calc(100vw * 9 / 16));
          max-height:860px; min-height:420px }
   ```

3. Заголовок и текст остаются в левой трети (это принято и нравится заказчику) — **двигать текст
   не нужно**, нужно вернуть кадр на всю ширину. Фраза «прижалась к левой стороне» — про кадр,
   а не про типографику.

### 1.4. Чем закрыть навсегда (обязательно)

`site/scripts/check-hero-layout.mjs` **считает формулы и не проверяет ширину** — поэтому дефект
и проехал три круга. Добавить числовую проверку по списку окон, включая проблемные:

```
[1217,598] [1366,768] [1440,900] [1920,950] [2560,1080] [2560,1440] [1024,600]
```

Правила (падать с `exit 1`, как остальные проверки):

- `heroW = min(vw, (vh − 96) × 16/9)` — **`heroW` обязан быть равен `vw`** (допуск 0 px);
- `heroH = min((vh − 96), vw × 9/16)` и `heroH ≤ vh − 96`;
- `document.documentElement.scrollWidth ≤ document.documentElement.clientWidth` (нет
  горизонтального переполнения);
- в отчёте — строка на каждое окно: `1217×598 → герой 1217×502, полоса справа 0 px`.

## 2. Дефект №2 (P1) — «О компании»: кусок забора висит в воздухе

`about-service-1600.webp` (он же в карточке «О компании» на главной — скрин `d`). Над правым
концом кромки кровли в белёсое небо торчат **две тонкие светлые «спицы»** — остатки забора за
домом; в кадре они не связаны ни с чем и читаются как мусор. Координаты в `about-service-1600.webp`
(1600×1000): **x 1500–1540, y 168–196** (кроп `f` снят с +1420+130, ×5).

В исходнике `docs/photos-source/r13-clean/master-clean.jpg` (3840×2160) это же место:
**x ≈ 3192–3268, y ≈ 395–446** (окно «О компании» = `extract{380, 80, 3000, 1875}`, масштаб 1,875).
Рядом, правее кромки кровли (x ≈ 3300–3380, y ≈ 450–560), тянется тонкая проволока — если в кадре
она тоже «висит в воздухе», убрать заодно.

### Что сделать

1. **Ретушировать мастер до кропа**, а не готовый webp: убрать обе «спицы» (и, по желанию,
   проволоку) клонированием соседнего неба/кровли. Небо там ровное, шов не должен читаться.
2. **Не трогать остальное**: вывеска, логотипы (NGN, BARDAHL, KORSON, PROMATIX, LYNX, SUFIX,
   ICHIRO), телефоны на баннере, оба бокса, машины в боксах, кирпич, роллеты. Разница с исходником
   вне зоны ретуши — ноль (`compare -metric RMSE` ≤ 2/65535 на маске вне прямоугольника ретуши).
3. Пересобрать `about-service-{1600,960,640}` в `webp` **и** `avif` (6 файлов), лимиты веса —
   как в `LIMITS` (`build-images.mjs`): 160/80, 70/70, 70/70 КБ.
4. Проверка «на глаз» — кроп ×5 того же места, приложить в отчёт: **в небе ничего не торчит**.

## 3. Дефект №3 (P1) — слой неона с разорванными буквами

`hero-neon-*` — отдельная RGBA-маска вывески, наложенная через `mix-blend-mode:screen`. В маске
**битые глифы**: «KORSON» → «Кu ОN», «SUFIX» → «SU ITIX», «BARDAHL» → «BARDANL», плюс контур фары
Camry и лишнее пятно. Поверх настоящей вывески это читается как грязный двойной текст.

**Решение: слой убрать.** Зелёный неон уже есть в самом фото (`hero-service-*`) — он никуда не
денется. Мерцание, если хочется сохранить, делается на самом фото, без масок:

```css
@keyframes neon-breathe{0%,100%{filter:none}50%{filter:brightness(1.04) saturate(1.06)}}
@media (prefers-reduced-motion:reduce){ .slide.is-active .slide-bg img{animation:none} }
```

Удалить: `<picture>` с неоном из `index.astro` (слайд 1), CSS `.slide-bg .neon`,
`.slide-bg .neon.f16`, `@keyframes neon-flicker`, правило в `prefers-reduced-motion`, функцию
`neon()` и `encodeSet` неона в `build-images.mjs`, 8 файлов `site/public/img/hero-neon*`,
упоминания в чекерах (`grep -rn "neon" site/`). В отчёте — `grep` на выходе: ноль вхождений.

Альтернатива (если очень хочется отдельного слоя) — **перегенерировать маску без текста**: только
свечение вывески и витрин по яркости самого фото, без букв. Тогда в отчёте — кроп ×3, где на
вывеске не появляется ни одной «лишней» буквы.

## 5. Дефект №5 (P2) — короткий экран (ландшафт телефона, `svh ≤ 600`)

На скринах заказчика высота окна ~600 px. Кроме ширины героя это даёт вторую проблему: **первый
экран перестаёт быть первым**.

- `≥1024`: `max-height:calc(100svh − 96px)` уже режет кадр — после фикса №1 надо убедиться, что
  при 1024×600 и 1217×598 заголовок, подзаголовок и обе кнопки видны без прокрутки.
- `641–1023`: `.hero{height:clamp(480px,72svh,780px)}` — при окне 844×390 герой **480 px выше самого
  окна** (390). Заменить на `height:clamp(320px, calc(100svh - 54px), 780px)` и добавить
  `@media (max-height:560px)`: скрыть `.slide-eyebrow` и `.hero-note`, `h1` —
  `font-size:clamp(1.35rem,4.6vw,1.9rem)`, `.slide-sub` — 3 строки максимум, `.slide-cta` в одну строку.
- `≤640`: `.hero-track{min-height:max(460px,76svh)}` — при 390×390 (телефон боком, узкий) трек
  больше экрана; предусмотреть `min-height:min(460px, calc(100svh - 120px))`.

Норма: на 844×390, 926×428, 1024×600, 1217×598 **герой + шапка ≤ высоты окна**, и обе кнопки
видны без прокрутки.
