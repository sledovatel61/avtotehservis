# Задание 79 · Агент 7 — админка фото `/manage/` прямо на GitHub Pages

Ты **Агент 7** («фотомастерская») на сайте автосервиса «АвтоТехСервис» (Ростов-на-Дону).
Сайт — Astro, публикуется статикой на GitHub Pages (`https://sledovatel61.github.io/avtotehservis/`).
Владелец сервиса будет грузить фото работ **сам, с телефона**, и ничего не должен устанавливать.

Ты один из трёх агентов круга 79: Агент 5 (витрина и страницы кейсов), Агент 7 (этот файл),
Агент 8 (гейты и инструкция). Зоны файлов не пересекаются.

## 1. Задача

Сделать страницу **`/manage/`** — фотоадминку, которая живёт как обычная статика в
`site/public/manage/` и поэтому попадает на Pages без единой правки экспортёра
(`export-pages.mjs` копирует `dist/client` целиком и публикует только маршруты из sitemap;
`/manage/` нам в sitemap не нужен — из sitemap он бы попал в индекс, а нам нужен `noindex`).

Что она делает:

1. Вход по личному токену GitHub (fine-grained, только репозиторий `sledovatel61/avtotehservis`,
   `Contents: Read and write`). Токен хранится в `localStorage`, никуда кроме `api.github.com`
   не уходит.
2. Читает `site/content/cases.json` из ветки `preview/github-pages`.
3. Даёт завести кейс: название, описание, услуга, дата, режим **«До и после»** или **«Одно фото»**.
4. Принимает фото перетаскиванием и через выбор с камеры, с мини-редактором (§4).
5. Собирает варианты 480 / 960 / 1600 WebP и **одним коммитом** кладёт
   `site/content/cases.json` + файлы в `site/public/media/cases/<slug>/`.
6. Показывает, что происходит: отправка → GitHub Actions собирает → сайт обновился (ссылки).

## 2. Жёсткие технические рамки

- **Никакой сборки.** Только `site/public/manage/index.html`, `manage.css` и ES-модули рядом
  (`app.js`, `editor.js`, `github.js`, `store.js`). Подключать через `<script type="module" src="./app.js">`.
  Никаких npm-зависимостей, CDN, шрифтов и аналитики: страница должна работать офлайн по коду
  и не тянуть сторонние запросы (CSP-заголовков нет, поэтому соблюдаем руками).
- **Относительные пути** (`./manage.css`, `<a href="../">`): сайт живёт под префиксом
  `/avtotehservis/manage/`, поэтому `/manage/app.js` даст 404.
- `index.html`: `<meta name="robots" content="noindex, nofollow">`, `<meta name="viewport" …>`,
  `lang="ru"`, заголовок «Фото работ — АвтоТехСервис». Никаких ссылок на `/admin`.
- Мобильный приоритет: сначала 360 px, потом десктоп. Крупные кнопки (≥ 44 px), без hover-only действий.
- Работает в Chrome / Safari / Firefox последних версий (и в Safari на iOS 16+).

### 2.1 Доступ к GitHub API

- Репозиторий: `sledovatel61/avtotehservis`, ветка: `preview/github-pages`.
- Чтение `cases.json`: `GET /repos/:o/:r/contents/site/content/cases.json?ref=preview/github-pages`
  (ответ base64), `sha` сохрани для последующей записи.
- Запись — **один коммит** через Git Data API:
  1. `GET /repos/:o/:r/git/ref/heads/preview%2Fgithub-pages` → `object.sha` (родитель);
  2. `GET /repos/:o/:r/git/commits/:sha` → `tree.sha` (base tree);
  3. `POST /repos/:o/:r/git/blobs` для каждого файла (`content: base64`, `encoding: 'base64'`);
  4. `POST /repos/:o/:r/git/trees` с `base_tree` и списком `{ path, mode: '100644', type: 'blob', sha }`;
     удалённые фото — `{ path, mode: '100644', type: 'blob', sha: null }`;
  5. `POST /repos/:o/:r/git/commits` (`message`, `tree`, `parents: [parentSha]`);
  6. `PATCH /repos/:o/:r/git/refs/heads/preview%2Fgithub-pages` (`sha`, `force: false`).
- Конфликт (422/409 на шаге 6 или `sha` файла не совпал): перечитать `cases.json`, повторить
  попытку один раз, показать понятное сообщение «кто-то сохранил изменения, повторите».
- Все ошибки — человеческим языком: 401 «токен не принят, проверьте срок и права»,
  403 «у токена нет права Contents: Read and write», 404 «репозиторий или ветка не найдены»,
  сеть «нет связи с GitHub».
- Токен: поле `type="password"` + кнопка «Проверить» (`GET /user`), «Выйти» стирает из
  `localStorage`. Показывать срок годности токена, если GitHub его отдаёт (`github-authentication-token-expiration`).
- В `localStorage` только токен (ключ `ats-gh-token`). Черновики несохранённых кейсов держи в памяти
  и предупреждай `beforeunload`.

## 3. Экраны

### 3.1 Первый вход

Короткая инструкция по-русски (сворачиваемая `<details>`): как выпустить fine-grained token
(Settings → Developer settings → Fine-grained tokens → Only select repositories → `avtotehservis` →
Repository permissions → Contents: Read and write → Expiration 90 days), куда его вставить.
Предупреждение: «токен = доступ к фото и текстам сайта; не пересылайте его и не вставляйте
на чужих устройствах».

### 3.2 Список кейсов

Карточки: обложка (480), название, чип статуса («черновик» / «на сайте»), число фото, дата,
кнопки «Открыть», «Дублировать», «Удалить» (удаление — с подтверждением вводом слова «удалить»).
Сверху: «+ Новый кейс», счётчик «в репозитории: N фото, M МБ», предупреждение при > 400 МБ
(бюджет репозитория ограничен, см. `docs/15-photo-pipeline.md`).

### 3.3 Карточка кейса

Поля: название (обязательно), слаг (авто из названия, латиница/цифры/дефис, можно поправить),
описание (одна строка), услуга (выпадающий список слагов — возьми актуальный список из
`site/src/server/services.ts` и **захардкодь копию** в `store.js`: статика не может импортировать
серверный код; услуга `kondicioner` в списке запрещена), дата работы, статус
(«черновик» / «на сайте»).

Переключатель режима — крупный, с двумя подписями:

- **«До и после»** → две зоны: «Как было» и «Как стало».
- **«Одно фото работы»** → одна зона «Фотография работы».

Зоны: drag&drop на десктопе, кнопка «Добавить фото» (с `accept="image/*"`, `capture` не ставить —
владелец может выбрать из галереи), превью 4:3, номер по порядку, стрелки «раньше/позже»
(работают и мышью, и тапом), крестик «убрать», «сделать обложкой» (звёздочка).
Между зонами — кнопка «перенести в „как стало“» у каждого кадра «до».
Лимиты: ≤ 10 фото на кейс, ≤ 15 МБ на файл, только `image/jpeg|png|webp|heic|heif`
(HEIC в Safari декодируется браузером; если не декодировался — сообщение «сохраните фото как JPEG»).

Подпись (alt) — обязательна у каждого кадра: поле с подсказкой «Что видно на снимке: узел, деталь,
машина». Кнопка «Заполнить по названию» подставляет `«<название кейса> — как было»`,
`«… — как стало»`. Без alt публикация блокируется.

Внизу: «Сохранить черновик» и «Опубликовать на сайте» (status = published; у черновика
`status: 'draft'` и он не виден на сайте). После успеха — панель: «Отправлено. GitHub собирает
сайт — 1–2 минуты», ссылки «страница кейса» (`../cases/<slug>/`), «ход сборки»
(`https://github.com/sledovatel61/avtotehservis/actions`), «обновить статус».

## 4. Мини-редактор (обязательный минимум)

Открывается по тапу на кадр. Всё на canvas, без библиотек.

1. **Автоповорот по EXIF** — применять сразу при загрузке (`createImageBitmap(file, { imageOrientation: 'from-image' })`,
   фолбэк `new Image()` + `URL.createObjectURL`).
2. **Кроп**: рамка с восемью ручками + перетаскивание внутри; пресеты `4:3`, `1:1`, `3:4`, `16:9`,
   `Свободно`; сетка третей; кнопка «Сбросить кроп». На телефоне рамка двигается одним пальцем,
   масштабирование фото — двумя.
3. **Поворот** на 90° влево/вправо (кнопки).
4. **Горизонт**: ползунок −15…+15°.
5. **Яркость** −30…+30 (и всё; контраст/насыщенность не делаем).
6. **Масштаб** фото внутри кропа (ползунок + «Сбросить»).
7. Предпросмотр результата в трёх ширинах и подпись «в репозиторий уйдёт ≈ N КБ».
8. «Готово» применяет правки, «Отмена» возвращает исходник.

Кодирование:

- варианты 480 / 960 / 1600 по **длинной стороне** (не апскейлить: если исходник меньше 1600,
  делай 1600-вариант равным исходнику, а `w`/`h` в JSON — реальные);
- `canvas.toBlob(cb, 'image/webp', 0.82)`; проверь поддержку
  (`canvas.toDataURL('image/webp').startsWith('data:image/webp')`);
  если WebP не кодируется — `image/jpeg` 0.85 и `ext: 'jpg'` в JSON;
- EXIF/GPS не сохраняются автоматически (в canvas их нет) — это требование, не ломай;
- имена: `<id>-<phase>-<width>.<ext>`, где `id` — 6 символов `[a-z0-9]` (криптостойкий
  `crypto.getRandomValues`), `phase` — `before` / `after` / `single`;
- `w`/`h` в JSON — размеры варианта 1600.

## 5. Контракт `cases.json` (согласован с Агентом 5, не менять)

```json
{
  "version": 1,
  "updated_at": "2026-11-17T16:00:00Z",
  "cases": [{
    "slug": "pores-po-bokovine",
    "title": "Порез по боковине: осмотрели и сказали прямо",
    "description": "Колёса · ремонт колеса R17 — 800 ₽ или замена шины",
    "service_slug": "balansirovka",
    "mode": "before_after",
    "status": "published",
    "published_at": "2026-11-17",
    "sort": 10,
    "cover": { "base": "ab12cd-after", "alt": "…", "w": 1600, "h": 1200, "ext": "webp" },
    "before": [ { "base": "ab12cd-before", "alt": "…", "w": 1600, "h": 1200, "ext": "webp" } ],
    "after":  [ { "base": "ab12cd-after",  "alt": "…", "w": 1600, "h": 1200, "ext": "webp" } ],
    "photos": []
  }]
}
```

- `mode: 'single'` → всё в `photos`, `before`/`after` — пустые массивы.
- `cover` — ссылка на один из уже перечисленных кадров (тот же `base`), иначе `null`.
- Файлы обязаны лежать по пути `site/public/media/cases/<slug>/<base>-<width>.<ext>`
  для всех трёх ширин.
- `sort` = max(sort) + 10 для нового кейса; при сохранении порядок не переписывай у соседей.
- Перед записью валидируй: слаг уникален, alt не пуст, есть хотя бы один кадр, режим и кадры
  согласованы, `updated_at` = текущее время UTC.

## 9. Гейты и проверки

```bash
cd site
npm run typecheck                     # твой код не в TS-сборке, но не должен ничего ломать
BG3D=off npm run build:pages
node scripts/check-pages.mjs
ls pages-dist/manage/index.html pages-dist/manage/app.js   # страница попала в публикацию
grep -c "noindex" pages-dist/manage/index.html
```

Проверь руками (и приложи скриншоты):

1. Открыть `/manage/` локально **через собранную статику** (`npx serve pages-dist` или
   `python3 -m http.server` в `pages-dist`), не через dev-сервер — именно так её увидит владелец.
2. Вставить заведомо неверный токен → понятная ошибка, ничего не «висит».
3. Без токена кнопки сохранения недоступны, инструкция видна.
4. Загрузить 3 фото (одно большое ~5 МБ), покрутить кроп/поворот, увидеть три варианта
   и оценку веса.
5. Прогнать сценарий «сухой прогон»: подставь мок `fetch` (в консоли) и убедись, что при
   422 конфликте показывается сообщение и повтор, а не молчаливый сбой.
