# Задание 85-3 · Агент 7 «мастерская» — вкладка «Цены и услуги» на `/manage/`

Это ты уже делал фотомастерскую `/manage/` в круге 79 (`site/public/manage/`): вход по
личному токену GitHub, чтение файла из ветки `preview/github-pages`, запись одним коммитом
через Git Data API, мобильный приоритет, никакой сборки и зависимостей.

Теперь та же страница должна уметь второе: **править цены**. Владелец сервиса устал сам
менять цифры, а мастер (Паша) будет заходить с телефона и делать это сам.

**Ветка:** `agent/85-prices-manage` от `origin/preview/github-pages`.
**PR:** в `preview/github-pages`. Не мержить — публикует оркестратор.

---

## 1. Что должно получиться

На `/manage/` появляется переключатель разделов: **«Фото работ»** (то, что есть) и
**«Цены и услуги»** (новое). Вход по токену общий, токен уже хранится в `localStorage`.
Обе вкладки — одна страница, без перезагрузки между разделами.

Во вкладке «Цены и услуги»:

1. **Список цен по категориям**, как на сайте: восемь групп прайса (ТО и жидкости, Тормоза,
   Подвеска и рулевое, Двигатель/ГРМ/сцепление, Диагностика, Автокондиционеры, Сварочные
   работы, Шины и колёса), прайс Voyah Free, три плашки на главной.
2. В каждой строке: название работы, **текущая цена** (серым, помельче), поле «Новая цена»
   и кнопка «Сохранить» — на категорию. Общая кнопка «Сохранить всё» на липкой панели.
3. **Добавление услуги в категорию**: «Название работы» + «Цена» + «Добавить». Строка
   встаёт в конец категории.
4. **Скрыть строку** (корзина) с подтверждением: не удаляем, а помечаем `hidden: true` —
   на сайте строка исчезает, вернуть можно там же («Показать обратно»).
5. По кнопке «Сохранить» изменения уходят на сайт **одним коммитом** в
   `site/content/prices.json`; после сохранения показывается: «Сохранено. Сайт обновится
   через 1–2 минуты» + ссылка «Открыть прайс на сайте» (`../prices/`) и статус сборки
   (через публичный Actions API, как уже сделано в `github.js`).
6. Дата «Цифры подтверждены …» на сайте обязана обновиться на дату сохранения — это
   `updated_at` в файле, который ты пишешь.

## 2. Источник правды и контракт файла (менять нельзя)

Файл: `site/content/prices.json` в ветке `preview/github-pages`.
Схема зафиксирована в `prompts/100-task-r85-prices-store.md` §3 и в
`site/src/shared/prices-schema.ts` (его пишет Агент 10, читай файл в своей ветке; если его
ещё нет — работай по §3 задания 85-1). Кратко:

```json
{ "version": 1, "updated_at": "2026-11-21",
  "groups": [ { "id": "to", "title": "ТО и жидкости", "service": "to-maslo",
                "items": [ { "id": "oil-sedan", "name": "Замена масла в двигателе, седан",
                             "price": "1000–1300 ₽", "hidden": false } ] } ],
  "tyres": { "set": [ { "id": "set-r13", "radius": "R13", "passenger": "1800 ₽", "crossover": "2000 ₽" } ],
             "repair": [ { "id": "rep-r13", "range": "R13–R15", "price": "600 ₽" } ],
             "extra":  [ { "id": "extra-set", "name": "Смена колёс, седан", "price": "1000 ₽" } ] },
  "voyah": [ { "id": "voyah-oil", "name": "…", "note": "…", "price": "2000 ₽" } ],
  "featured": [ { "id": "voyah-oil-chip", "ref": "voyah-oil", "title": "Масло ДВС", "note": "+ все фильтры" } ] }
```

Правила, которые ты обязан соблюсти:

- **id** позиций — латиница, цифры, дефис; уникальны по всему файлу. Новые — транслит
  названия (`slugifyRu`), при совпадении суффикс `-2`, `-3`.
- **price** — строка как её видит клиент: `1200 ₽`, `от 1500 ₽ за место`, `2200–4000 ₽`.
  Проверяй: 1–40 символов, есть цифра. Сообщение по-русски: «Похоже, это не цена.
  Напишите, например: 1200 ₽».
- **updated_at** — `ГГГГ-ММ-ДД` на сегодняшнюю дату при каждом сохранении.
- `featured[]` цену не хранит: она берётся из позиции `ref` в `voyah` — в интерфейсе
  покажи это текстом, поля ввода нет.
- Никаких других полей: если в файле появились незнакомые поля (их добавит Агент 10 или
  будущие круги) — **сохраняй их как есть**, не выкидывай.

## 3. Запись и конфликты

Повторяй то, что уже работает для `cases.json` (`github.js`, `store.js`), но с поправкой
на «чужие» правки:

1. `GET contents?ref=preview/github-pages` → объект + `sha`.
2. При сохранении: перечитать файл **заново**; если `sha` изменился — не затирай молча,
   а примени свои изменения к свежей версии по id позиций (строки, которых уже нет, —
   покажи списком: «эту строку кто-то удалил, пока вы правили»), и только потом пиши.
3. Коммит — Git Data API, одним коммитом: blob → tree (`base_tree`) → commit → ref.
   Сообщение коммита: `Цены: правка из админки (N позиций)`.
4. 409/422 → одна повторная попытка, дальше понятное сообщение «Кто-то сохранил изменения
   одновременно. Нажмите „Сохранить“ ещё раз — мы повторим».
5. Никаких `force: true` в `PATCH refs`.

## 4. Интерфейс: требования к тексту и виду

- Всё по-русски, без слов «JSON», «API», «коммит», «репозиторий», «ветка», «токен»
  (кроме блока подключения, где он и так есть) — мастер не должен этого видеть.
- Ошибки — человеческие: «Не удалось сохранить: нет связи. Попробуйте ещё раз».
- 360 px — первичный размер: строки цены превращаются в карточку (название, «сейчас:
  1200 ₽», поле, «Сохранить»), кнопки ≥ 44 px, без hover-only действий.
- Экономь движения: у каждой категории свой `<details open>`, счётчик «изменено: 2»
  в заголовке, липкая панель «Изменений: N · Сохранить всё».
- Пустые состояния: «Прайс пока пустой», «Нет подключения — введите ключ доступа в
  разделе выше».
- Стиль — тот же `manage.css` (тёмный, крупный, «дорого»), новые классы добавляй туда же,
  без внешних шрифтов и CDN.
- `index.html`: добавь `lang`, `noindex, nofollow` (уже есть), заголовок страницы
  «Управление сайтом — АвтоТехСервис». Ссылки на `/admin` не добавляй.

## 5. Проверка схемы в двух местах — обязательный тест

Валидация нужна и в браузере (`manage/prices-schema.js`), и на сервере
(`src/shared/prices-schema.ts`, Агент 10). Дубль допустим (как с `cases-schema.ts`), но
он обязан совпадать — иначе админка сохранит то, что сайт потом не прочитает:

- `site/public/manage/prices-schema.js` экспортирует `LIMITS`, `validate`, `slugifyRu`,
  `parse` (терпимый разбор), `serialize` (2 пробела, `\n` в конце, UTF-8 без BOM).
- `site/tests/manage-prices.test.ts`: импортирует **оба** модуля, гоняет одни и те же
  8–10 фикстур (валидная, пустая цена, цена без цифры, дубль id, лишние поля, битый
  `updated_at`, 200 позиций) и падает, если вердикты расходятся. Этот тест — единственная
  защита от расхождения, не пропускай его.

Плюс живой сценарий (опиши в PR со скриншотами или шагами): открыть `…/manage/#prices`,
вставить токен, увидеть 8 групп с текущими ценами, поменять «Замена передних тормозных
колодок» с 1200 на 1300 ₽, нажать «Сохранить», дождаться «Сайт обновится через 1–2 минуты»,
открыть `../prices/` — новая цена и новая дата; добавить «Развал-схождение — 1500 ₽» в
«Подвеску», сохранить, увидеть строку на прайсе; скрыть её — исчезла; обновить страницу —
состояние сохранилось. Проверить на 360 px и на десктопе, в Safari iOS (если есть) или
хотя бы в мобильной эмуляции.

Фото-часть после твоих правок обязана работать как раньше: вход, список работ, добавление
фото, сохранение кейса.

## 8. Чего делать нельзя

- Сборки, npm-зависимостей, CDN, шрифтов, аналитики.
- Абсолютных путей (`/manage/app.js`): сайт живёт под `/avtotehservis/manage/`.
- Хранить цены в `localStorage` как источник правды — только GitHub, локально можно
  черновик несохранённых правок.
- Писать в интерфейсе технические слова и обещать мгновенное обновление сайта.
- Ломать существующие проверки: `node scripts/check-cases.mjs`, `check-pages.mjs`,
  `check-media-budget.mjs` должны остаться зелёными.
