## D3 (minor). Гейты не подключены к публикации

`.github/workflows/pages.yml` (строки 40–47) делает только `npm run build:pages`,
`check-pages.mjs` и `check-intro-3d-off.mjs`. `check-cases`, `check-media-budget`,
`typecheck` и тесты в CI не запускаются — то есть публикация с фотографией на 900 КБ
или с обложкой, не совпадающей с кадром, пройдёт молча, а гейты ловят это только руками.

**Что сделать:**

1. Добавь шаги **после** `build:pages` и **до** `upload-pages-artifact` (гейты читают
   `pages-dist`), с `working-directory: site`:
   - `node scripts/check-cases.mjs`;
   - `node scripts/check-media-budget.mjs`;
   - `node --test tests/photo-pipeline.test.ts` — тесты схемы и лимитов, `sharp` в CI
     уже ставится через `npm ci`;
   - `npm run typecheck` — если он проходит в CI-окружении без лишних зависимостей;
     если нет — не добавляй и напиши почему.
2. Порядок и `name:` у шагов — по-человечески, чтобы в красном ране было видно, какой гейт
   упал («Проверить данные работ», «Проверить вес фотографий»).
3. Убедись, что гейты **не требуют сети** и не падают на пустом `cases.json`
   (в проде работ ноль — это нормальное состояние, сборка не должна краснеть).
4. Проверь локально ровно ту последовательность, что в workflow, в пустом состоянии:
   `npm ci` → `npm run build:pages` → `check-cases` → `check-media-budget` →
   `node --test tests/photo-pipeline.test.ts` → `typecheck`. Все шаги должны быть зелёными.
5. Проверь, что гейт действительно валит шаг: временно положи в `site/public/media/cases/x/`
   файл на 900 КБ (и/или испорть `cover` в тестовой работе) — `check-media-budget` должен
   выйти с кодом 1. Убери за собой.
6. Не трогай существующие шаги и комментарии про 3D/заставку (круг 74) — они объясняют,
   почему `BG3D` не выставляется.
