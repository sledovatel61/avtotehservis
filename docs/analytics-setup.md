# Аналитика на сайте: Метрика, GA4 и согласие на cookies

Инструкция для владельца. Всё, что нужно сделать руками, — создать счётчики и вписать два
идентификатора в переменные репозитория. Код уже готов и работает так: **пока человек не нажал
«Принять все» в баннере, ни один запрос к Яндексу и Google не уходит**.

Коротко о том, почему так:

- политика (§6) обещает, что аналитика грузится только после согласия, — код это выполняет;
- баннер выбора показывается один раз, повторно открывается кнопкой «Настройки cookies» в подвале;
- «Только необходимые» — законный выбор: сайт работает полностью, счётчиков нет;
- `<noscript>`-пиксель Метрики мы не ставим намеренно: он грузился бы без согласия.

---

## 1. Яндекс.Метрика

1. Открыть <https://metrika.yandex.ru> → **«Добавить счётчик»**.
2. Имя — «АвтоТехСервис, сайт». Адрес сайта — боевой домен (`ats-rostov.ru` либо тот, что
   указан в `PUBLIC_ORIGIN`).
3. Включить **«Клик по телефону»** (цель), часовой пояс — Москва.
4. **«Вебвизор» и «Карту скроллинга» не включать:** в коде стоит `webvisor: false`, политика
   прямо говорит, что Вебвизора нет. Включите — политика станет неправдой.
5. Сохранить и скопировать **номер счётчика** (8 цифр).
6. GitHub → репозиторий → **Settings → Secrets and variables → Actions → вкладка Variables** →
   **New repository variable**: имя `PUBLIC_YM_ID`, значение — номер счётчика.

## 2. Google Analytics 4

1. Открыть <https://analytics.google.com> → **«Администратор»**.
2. Создать **ресурс** (аккаунт уже есть или создать) → **поток «Веб»** с адресом сайта
   `https://ats-rostov.ru` (или текущий публичный адрес).
3. Скопировать **идентификатор потока** вида `G-XXXXXXXXXX`.
4. GitHub → **Settings → Secrets and variables → Actions → Variables** → **New repository
   variable**: имя `PUBLIC_GA_ID`, значение — `G-…`.

После добавления переменных перезапустить сборку: **Actions → Pages → Run workflow**. Сайт
пересоберётся за 1–3 минуты.

## 3. Google Search Console

1. <https://search.google.com/search-console> → **«Добавить ресурс» → «Префикс URL»** с адресом сайта.
2. Подтверждение — **мета-тег**. Скопировать только значение `content="…"` и положить в
   переменную репозитория `PUBLIC_GOOGLE_SITE_VERIFICATION`. Тег появится в `<head>` сам.
   Пустое значение = тега нет (и это не ошибка, просто подтверждение не настроено).
3. После сборки — **«Проверить»**, затем **«Индексирование → Файлы Sitemap»** →
   добавить `https://ats-rostov.ru/sitemap.xml`.
4. **«Проверка URL»** → главная и 3 статьи «Полезного» → **«Запросить индексирование»**.

## 4. Яндекс.Вебмастер

1. <https://webmaster.yandex.ru> → **«Добавить сайт»**.
2. Подтверждение — **мета-тег**: значение из `content="…"` в переменную
   `PUBLIC_YANDEX_VERIFICATION`.
3. **«Регион»** — Ростов-на-Дону (влияет на геозависимую выдачу).
4. **«Индексирование → Файлы Sitemap»** → добавить `https://ats-rostov.ru/sitemap.xml`.

## 5. Как проверить, что всё работает

1. Открыть сайт в **приватном окне** (чтобы не было старого выбора).
2. Внизу появится панель «Cookies». Нажать **«Только необходимые»**.
3. DevTools → **Network** → фильтр `mc.yandex` / `google` — запросов быть **не должно**.
   Обновить страницу — панели больше нет, запросов по-прежнему нет.
4. Подвал → **«Настройки cookies»** → **«Принять все»** → в Network появляются
   `mc.yandex.ru/metrika/tag.js` и `googletagmanager.com/gtag/js`.
5. **«Отозвать согласие»** → cookie `_ym_*` и `_ga*` удаляются; сами скрипты до перезагрузки
   страницы остаются в памяти (в панели так и написано: «изменения применятся после
   обновления страницы»).

Через сутки в Метрике и GA4 должны появиться визиты. Если нет — проверить, что переменные
репозитория заданы и сборка после их добавления прошла успешно (в `pages-dist` атрибут
`data-ym` на `<html>` непустой).

## 6. Что не делать

- **Не вставлять сниппеты руками в `Base.astro`** (`<script src="mc.yandex.ru/…">` и подобное).
  Счётчики ставит `site/src/client/consent.ts` после согласия; статический тег = обработка
  данных без согласия и падение гейта `check-analytics.mjs` в CI.
- **Не добавлять `<noscript>`-пиксель Метрики** — он обходит согласие.
- **Не включать** рекламные пиксели (VK, MyTarget, Google Ads), «Вебвизор», карты тепла и
  социальные виджеты без отдельного согласия и правки политики.
- **Не менять `consent_version`** в `site/src/server/settings.ts`: она сверяется с
  `relay/wrangler.toml`, и её смена ломает отправку заявок (`400 consent_version`).
  Версия политики — отдельное поле `policy_version`.
- **Не ослаблять** баннер и гейт: «на время» отключённый баннер — это уже наружу.

## 7. Где что лежит

| Что | Файл |
|---|---|
| Модель согласия, загрузка счётчиков, CSP-хелперы | `site/src/client/consent.ts` |
| Разметка панели | `site/src/components/CookieConsent.astro` |
| Подключение панели и `data-ym`/`data-ga` | `site/src/layouts/Base.astro` |
| Условная CSP | `site/src/middleware.ts` |
| §6 политики и версия | `site/src/pages/privacy.astro`, `site/src/server/settings.ts` |
| Гейт | `site/scripts/check-analytics.mjs` (+ `--self-test`) |
| Тесты | `site/tests/analytics-consent.test.ts` |

Проверка локально:

```bash
cd site
node scripts/check-analytics.mjs && node scripts/check-analytics.mjs --self-test
node --test tests/analytics-consent.test.ts
```
