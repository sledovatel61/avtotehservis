## 4. Процедура переезда — по шагам

Сейчас сайт живёт на **подпути** `https://sledovatel61.github.io/avtotehservis/`. На своём домене он будет в **корне** `https://avtotehservis439.ru/`. Это не «просто прикрутить домен»: путь меняется, и код об этом должен знать — иначе стили, картинки и ссылки уедут в 404. Поэтому шаги идут в таком порядке.

### Шаг 1. Купить домен (5 минут, владелец)

Регистратор: reg.ru, timeweb, nic.ru, domeny.ru — любой. Нужен паспорт/ЕСИА (для физлица в `.ru` это обязательное подтверждение). Цена 200–400 ₽/год.

### Шаг 2. DNS у регистратора

Для корня (`avtotehservis439.ru`):

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | `185.199.108.153` |
| A | `@` | `185.199.109.153` |
| A | `@` | `185.199.110.153` |
| A | `@` | `185.199.111.153` |
| CNAME | `www` | `sledovatel61.github.io` |

Это официальные адреса GitHub Pages. TTL можно оставить по умолчанию.

### Шаг 3. Прописать домен в GitHub Pages

Репозиторий → Settings → Pages → Custom domain → вписать домен → Save → дождаться галочки «DNS check successful» → включить **Enforce HTTPS** (сертификат GitHub выпустит сам, обычно 15–60 минут).

После этого в ветке публикации (`preview/github-pages`) должен появиться файл `CNAME` с доменом — его кладём в артефакт сборки (`site/public/CNAME`), иначе следующая сборка домен не увидит.

### Шаг 4. Правка кода: корень вместо подпути (делает агент)

В `site/scripts/export-pages.mjs` зашиты две константы:

```js
const base = '/avtotehservis';
const publicOrigin = 'https://sledovatel61.github.io';
```

Их нужно вынести в переменные окружения (`PUBLIC_BASE_PATH`, `PUBLIC_ORIGIN`) с текущими значениями по умолчанию, а сборке для домена передавать `PUBLIC_BASE_PATH=""` и `PUBLIC_ORIGIN=https://avtotehservis439.ru`. От них зависят: префиксы CSS/JS/картинок/шрифтов, canonical, `og:url`, `sitemap.xml`, страницы-редиректы и проверки в `site/scripts/check-pages.mjs`.

Пока домена нет — ничего не меняется: по умолчанию остаётся `/avtotehservis`, превью работает как сейчас. Переключение — одна переменная в workflow публикации.

### Шаг 5. Воркер заявок: разрешить новый адрес

Формы отправляются в Cloudflare Worker, у него белый список источников. В `relay/wrangler.toml`:

```toml
ALLOWED_ORIGINS = "https://sledovatel61.github.io,https://avtotehservis439.ru,https://www.avtotehservis439.ru,http://localhost:4321,http://127.0.0.1:4321"
```

Затем Actions → «Deploy leads relay» → Run workflow. Старый адрес из списка пока не убираем — пусть работает, пока переезд не подтверждён.

### Шаг 6. Проверка (приёмка переезда)

- [ ] `https://avtotehservis439.ru/` открывается, стили и картинки на месте (не «голый» HTML);
- [ ] `https://www.avtotehservis439.ru/` открывается;
- [ ] замок в браузере, `http://` сам уходит на `https://`;
- [ ] главная, «Услуги», «Цены», «Работы», «Контакты» — все ссылки ходят внутри нового домена;
- [ ] тестовая заявка с сайта приходит и в Telegram, и на почту;
- [ ] `/health` воркера: `telegram: true`, `email` — как настроено;
- [ ] админка `/manage/` открывается и сохраняет правку (одна тестовая правка цены);
