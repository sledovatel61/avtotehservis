# Как занести чат в песочницу (задание №67, разблокировка)

Дата: 12.11.2026, вторая редакция. Проверено командами и через коннектор, не на словах.

## 1. Почему A13 «не видит папку» — это не доступ

Права папки `1CkjWyWDn7ok2EUI8KwNkjacvkib6U-OG`, проверено `list_permissions`:

| кто | роль |
|---|---|
| `anyoneWithLink` (тип `anyone`) | **writer** — то есть доступ по ссылке есть у кого угодно |
| `_stasik_@mail.ru` | owner |

Папка открыта по ссылке, аккаунт агента тут ни при чём. Причина другая:
**`search_files` ищет по имени в своём Drive, а папка лежит в чужом аккаунте.**
Поиск по строке «Экспорт чата» её не находит, и агент делает вывод «доступа нет».

Правильный вызов — сразу по ID, без поиска:

```
list_files  q="'1CkjWyWDn7ok2EUI8KwNkjacvkib6U-OG' in parents", page_size=100
get_file    file_id="1dRMrbYqq-UExEG34M6TZNa8e0xWSPsEL"   # messages.html, 854 450 б
read_file_text file_id="..." max_chars=200000
```

Если и это не сработает — коннектор подключён не к тому Google-аккаунту
(папка принадлежит `_stasik_@mail.ru`).

## 2. Но доступа мало: коннектор не умеет писать на диск

Проверено в этой песочнице:

| проверка | результат |
|---|---|
| `curl https://drive.google.com` | `000`, SSL reset — канала к Drive нет |
| `curl https://www.googleapis.com` | `000`, SSL reset |
| `curl https://codeload.github.com` | `301` — GitHub открыт |
| `gh api repos/sledovatel61/avtotehservis` | `public` |

Коннектор отдаёт содержимое файла **в контекст модели**; инструмента «Drive → файл на диске»
нет. `read_file_text` читает только с начала файла (смещения нет), поэтому 76 файлов
по 850 КБ так не пройти — это ~15 млн знаков и никакого grep.

## 3. Приватность больше не ограничение

Чат «Воя клуб» — публичный канал, любой может его открыть; владелец подтвердил,
что персональные данные участников не являются проблемой. Значит подходят и вложения
в чат, и публичный репозиторий. Ограничение снято — путь Б ниже упрощается.

## 4. Что нужно сделать: один файл на диск

Нужен **один** архив в рабочей папке — дальше всё делает код.

### Путь А — вложение в сообщение (самый быстрый)

1. В Telegram Desktop: правый клик по теме «Обслуживание и ремонт» →
   **Export chat history** → снять галочки со всех медиа → формат **JSON**.
   JSON хранит кириллицу как есть (в текущем HTML она записана `\uXXXX` и файл втрое
   толще), поэтому лучше именно JSON.
2. Запаковать `result.json` (или 76 файлов `messages*.html`, если JSON не выходит) в zip.
3. **Приложить архив к следующему сообщению в этом чате** — вложение попадает
   в рабочую папку.

Ориентир: текст без медиа — 15–25 МБ, в zip 4–6 МБ. Если больше 20 МБ — двумя частями.

### Путь Б — через GitHub

1. Создать репозиторий (можно публичный, приватность снята) и загрузить туда zip
   через веб-интерфейс.
2. Дать ссылку — песочница склонирует: канал к GitHub открыт и проверен.

## 5. Что происходит после получения

```bash
node site/tools/chat-import/import.mjs --in chat-export --out /tmp/chat/txt
node site/tools/chat-import/probe.mjs --corpus /tmp/chat/txt/corpus.txt --topics
node site/tools/chat-import/probe.mjs --corpus /tmp/chat/txt/corpus.txt \
  --pattern "редуктор" --from 01.03.2025 --limit 20
node site/tools/chat-import/probe.mjs --corpus /tmp/chat/txt/corpus.txt --msg 612345
```

`import.mjs` — HTML/JSON → `corpus.txt` (строка = сообщение, кириллица раскодирована),
`corpus.jsonl` и `stats.json`. `probe.mjs` — счётчики по 12 темам и узкие выборки:
не больше 20 строк по 220 знаков, полный текст только по `--msg`. Оба с `--self-test`,
оба проверены на синтетическом экспорте того же формата.

В контекст попадают только попадания, а не 20 МБ. Именно поэтому «куча глупых вопросов»
в чате не мешает: модель видит 20 строк про редуктор, а не 20 тысяч сообщений.

Каталоги `chat-export/`, `/tmp/chat/` и `*.chat.zip` — в `.gitignore`.
