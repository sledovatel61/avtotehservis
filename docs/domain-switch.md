# Переезд на домен `ats-rostov.ru` — порядок для владельца

Домен куплен и оплачен (Рег.ру, до 19.11.2027), DNS настроен и проверен:

| Запись | Значение |
|---|---|
| `A @` | `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153` |
| `CNAME www` | `sledovatel61.github.io` |

Сайт пока живёт на `https://sledovatel61.github.io/avtotehservis/` и собран с префиксом `/avtotehservis`.
Если включить домен **до** пересборки, страницы откроются без стилей и картинок: браузер будет искать `/avtotehservis/_astro/…` на корне домена.

Поэтому порядок строгий: **сначала переменные и пересборка, только потом Custom domain.**
Между шагом 2 и шагом 3 проходит 2–4 минуты — в это время старый адрес работает как раньше.

## Шаг 1. Переменные сборки (ты, ~1 минута)

GitHub → репозиторий `sledovatel61/avtotehservis` → **Settings** → **Secrets and variables** → **Actions** → вкладка **Variables** → **New repository variable**. Добавить три:

| Name | Value |
|---|---|
| `PUBLIC_ORIGIN` | `https://ats-rostov.ru` |
| `PUBLIC_BASE_PATH` | `/` |
| `PUBLIC_DEMO_REVIEWS` | `0` |

`PUBLIC_DEMO_REVIEWS=0` — потому что шесть отзывов «пример» на боевом сайте не нужны: раздел `/otzyvy` покажет «Пока на сайте нет опубликованных отзывов — будьте первым» и форму. Как только появятся настоящие отзывы (через `/manage/` → вкладка «Отзывы»), их будет видно всем.

Если хочешь наоборот — оставить примеры на боевом сайте, поставь `1`; но тогда на домене висит средняя оценка 4,8 из выдуманных отзывов. Рекомендую `0`.

## Шаг 2. Пересборка (ты, 1 клик + 3 минуты)

**Actions** → слева **Publish client preview** → справа **Run workflow** → ветка `preview/github-pages` → **Run workflow**.
Дождаться зелёной галочки (3–4 минуты). Если сборка упала — домен **не включать**, прислать мне лог.
Если `PUBLIC_DEMO_REVIEWS` забыть, сборка упадёт на гейте `check-reviews-artifact` — это защита, а не поломка.

## Если кнопки «Run workflow» нет

Так и должно быть на этом репозитории: по правилам GitHub кнопка ручного запуска показывается
только для workflow, файл которого лежит **в ветке по умолчанию** (`main`). В `main` каталога
`.github/workflows/` нет — вся сборка живёт в `preview/github-pages`, поэтому в Actions видна
история запусков, но не кнопка.

Пересборку в таком случае запускает **любой push в `preview/github-pages`** — например, слияние
любого PR в эту ветку. Так же её запускаю я, когда нужно. Кнопка появится, если когда-нибудь
перенести `.github/workflows/` в `main`; для переезда на домен это не нужно.

## Шаг 3. Проверка, что сборка уже под домен (я, до включения)

Мне нужно 30 секунд: я проверяю, что в опубликованном артефакте есть `CNAME` = `ats-rostov.ru` и нет ссылок с `/avtotehservis/`. Скажи «собралось» — проверю и дам отмашку. Пока отмашки нет, шаг 4 не делай.

## Шаг 4. Включение домена (ты, ~2 минуты)

**Settings** → **Pages** → блок **Custom domain** → вписать `ats-rostov.ru` → **Save**.
Подождать 1–2 минуты, пока появится **DNS check successful** (если написано «DNS check unsuccessful» — подождать ещё пару минут и обновить страницу; DNS у тебя уже верный).
Затем поставить галочку **Enforce HTTPS** (может стать доступна через 5–15 минут после проверки DNS).

## Шаг 5. Проверка (я)

Проверяю снаружи:

1. `https://ats-rostov.ru/` — открывается, стили и картинки на месте (в исходнике страницы нет `/avtotehservis/`).
2. `https://ats-rostov.ru/otzyvy/` — заголовок «Отзывы клиентов», форма, кнопка «Отправить отзыв» активна.
3. `https://ats-rostov.ru/prices/`, `/appointment/`, `/contacts/` — открываются.
4. Старый адрес `https://sledovatel61.github.io/avtotehservis/` редиректит на домен.
5. `https://ats-leads.ats439.workers.dev/health` → `"reviews":true`.
6. Тестовая заявка с домена: приходит в Telegram-группу и на `Pavel.yakovenko@mail.ru`.
7. Тестовый отзыв с домена: ошибки 403 нет, приходит в Telegram с пометкой «на модерации», на сайте не появляется.

## Если что-то сломалось

Откат в одну сторону, без потери данных:

1. **Settings** → **Pages** → Custom domain → очистить поле → **Save** (сайт снова на `sledovatel61.github.io/avtotehservis/`).
2. **Settings** → **Secrets and variables** → **Actions** → **Variables**: `PUBLIC_ORIGIN` и `PUBLIC_BASE_PATH` — очистить (пустое значение = старый адрес), `PUBLIC_DEMO_REVIEWS` — `1`.
3. **Actions** → **Publish client preview** → **Run workflow**.
4. Написать мне — разберёмся, домен подключим повторно.

DNS у Рег.ру при этом трогать не нужно — записи уже правильные.

## Что делает воркер (без тебя)

`relay/wrangler.toml` уже содержит домен в `ALLOWED_ORIGINS`, деплой воркера идёт сам при изменении `relay/**`.
Если после шага 4 форма отзыва отвечает `403 {"error":"origin"}` — значит воркер ещё не передеплоился: подождать следующий прогон «Deploy leads relay» или сказать мне.
