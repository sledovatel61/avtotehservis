# Ресёрч: рынок, дизайн, технологический стек

Дата: 2026-10-21. Цель — дать 5 агентам общую фактуру, чтобы идеи были не «в вакууме».

---

## 1. Как устроены сильные сайты автосервисов

**Что работает (сводка по отраслевым кейсам и конкурентам):**

1. **Вход через симптом, а не через услугу.** Клиент ищет не «ремонт подвески», а «стучит спереди».
   Сильные сайты группируют услуги по симптомам/узлам и дают быстрый выбор в первом экране.
2. **Цена — главный страх.** Прозрачные «ориентиры от», калькулятор/квиз с вилкой, обещание «согласуем до работ».
3. **Доказательства вместо обещаний.** Фото/видео реальных работ, кейсы «до/после», рейтинг с карт, гарантия.
4. **Запись в 2–3 шага.** Услуга → время → контакт. Каждое лишнее поле режет конверсию.
5. **Мобильный сценарий = звонок/мессенджер.** Sticky-CTA, tel:-ссылка, WhatsApp/Telegram, кликабельный адрес.
6. **Локальное SEO.** «Автосервис на Портовой», «развал-схождение Ростов», карточки NAP, отзывы, schema.org AutoRepair.

Источники: `5th.ru/portfolio/auto-service` (структура «симптом → услуга»), `lead.media` (тренд на прозрачные цены,
фото работ, отзывы с карт), `uremont.com` (выбор авто → проблема → предварительная стоимость), `proffcto.ru`,
`bestway61.ru` (прайс-таблицы и запись), `akpp61.agregatka.ru` (специализация + гарантия как оффер).

**Слабые места типового сайта СТО (наши точки отрыва):**
- стоковые фото улыбающихся механиков и «гаечный ключ на синем градиенте»;
- прайс-простыня без группировки;
- форма «имя/телефон» без квалификации заявки → менеджер тратит время на пустышки;
- нет видео — а именно видео разборки агрегата снимает страх «развода»;
- нет мобильной версии квиза (горизонтальные шаги, мелкие кнопки).

**Референсные механики (не копировать визуал, брать логику):**
- step-by-step калькулятор с прогрессом и «осталось 30 секунд»;
- «до/после» слайдер-шторка для кузовных/дисков;
- видео-кейсы с таймкодом и подписью «что было / что сделали / сколько заняло»;
- sticky-бар снизу на мобиле: «Позвонить · Заявка · Маршрут»;
- блок «мастера» с реальными именами и специализацией (доверие к людям);
- отзывы как карточки с источником (Яндекс, 2ГИС) — прозрачно, без выдумок.

## 2. Визуальные тренды 2025–2026, которые уместны здесь

- **Dark industrial / «гараж премиум»**: графит, тёплый металл, янтарный свет лампы, крупная типографика.
- **Bento-сетки** для услуг и кейсов: плотно, информативно, отлично живёт на мобиле.
- **Крупный шрифт + короткие фразы**, «инженерные» подписи, моноширинные цифры для цен и характеристик.
- **Scroll-driven анимации** (CSS `animation-timeline`, `IntersectionObserver`, GSAP ScrollTrigger):
  мягкое проявление, параллакс 3–5 %, счётчики, «сборка» карточек.
- **View Transitions / shared element** — дорого выглядит, дёшево по весу.
- **Тактильные детали**: шум/зерно (SVG feTurbulence или data-URI), тонкие линии-схемы, штампы «РАБОТА ВЫПОЛНЕНА».
- **Видео — вертикальное, autoplay-muted-loop**, poster-first, вес ≤ 2–3 МБ на клип, lazy.
- Антитренд для нас: неоновые градиенты «киберпанк», 3D-конфигураторы машин, тяжёлые WebGL-сцены.

## 3. Технологический стек: сравнение

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| **Astro 5 + Tailwind 4 + TS** (острова React/Svelte) | 0 JS по умолчанию, Lighthouse 95–100, view transitions, контент-коллекции, удобно отдавать статикой | админку надо прикручивать отдельно | **рекомендуемый для сайта** |
| **Next.js 15/16 (App Router) + Payload CMS 3** | один проект = сайт + админка + API; Server Actions; удобно для заявок | 85–150 КБ JS, тяжелее в поддержке, дороже хостинг | сильный вариант «всё в одном» |
| **Nuxt 3/4 + Directus** | Vue-экосистема, SSR, гибкая админка | тот же вес JS, две системы | альтернатива |
| **SvelteKit + Strapi/Directus** | лёгкий рантайм, отличный DX | меньше специалистов на рынке РФ | альтернатива |
| WordPress + ACF | дешёвая поддержка, знакомый админ | перф и безопасность требуют работы, «тяжело» для wow-анимаций | только если клиент сам хочет WP |
| Tilda/Readymag | быстро | не тот уровень «крутости», ограничения кастомного квиза | не берём |

Данные по весу JS и Core Web Vitals: Astro ~0–12 КБ против ~85–150 КБ у Next.js, LCP 0,8–1,2 с против 1,4–2,1 с
(несколько независимых сравнений 2026: `wppoland.com`, `pkgpulse.com`, `tech-insider.org`, `verlua.com`).

**Рекомендация оркестратора (агенты могут оспорить с обоснованием):**
Astro 5 (static) + Tailwind CSS 4 + TypeScript; интерактив — острова на React (`client:visible`) только для квиза,
галереи и админ-виджетов; анимации — CSS + GSAP ScrollTrigger (≈ 30 КБ gzip, грузится после LCP) либо чистый CSS
scroll-driven, если хватает; шрифты — 2 гарнитуры, self-hosted, `font-display: swap`, подмножество latin+cyrillic;
медиа — AVIF/WebP + MP4 (H.264) с poster, хостинг медиа на РФ-хранилище (Yandex Object Storage / Selectel).

**Бэкенд для заявок**: Node-сервис (Fastify/Hono) или serverless-функция: валидация (Zod), honeypot, rate-limit,
SmartCaptcha от Яндекса, запись в БД (Postgres/SQLite), отправка письма (Nodemailer + Яндекс 360 SMTP),
дубль в Telegram (`sendMessage`, `parse_mode: HTML`, inline-кнопка «Позвонить»), ретраи + лог.

**Админка (фото/видео/отзывы/кейсы)**: три реальных пути
1. **Payload CMS 3** — встроенная в Next.js, лучший UX, версии, роли, доступ с телефона, S3-адаптер. Требует Node+БД.
2. **Directus 11** — админка «из коробки» поверх Postgres, отличные права и файлы, сайт может быть на Astro.
3. **Git-based (Decap/Sveltia CMS)** — бесплатно, ноль серверов, но правки идут через коммиты; медиа в репозитории/бакете.
   Для «просто и бесплатно» — ок; для владельца без технаря — риск.
Для СТО с 1–3 сотрудниками, которые будут заливать фото с телефона, ставка — **Directus или Payload** на VPS в РФ.

**Хостинг/инфраструктура (РФ)**: VPS Timeweb/Beget/Selectel (2–4 ГБ RAM), Docker Compose (app + cms + postgres + caddy),
Caddy с авто-TLS, бэкапы БД и медиа в S3, Sentry-совместимый мониторинг (GlitchTip), uptime-монитор.
Альтернатива: Cloudflare/Vercel для статики — но проверить доступность и требования 152-ФЗ (ПД на территории РФ).

## 4. Требования 152-ФЗ и доверие

- Чекбокс согласия на обработку ПД обязателен, ссылка на политику, отдельная страница.
- Минимизация: не собираем лишнего (VIN — по желанию, с пояснением «для подбора запчастей»).
- Данные — в РФ; SMTP/боты — не выгружают ПД за рубеж без основания; журнал доступа.
- Cookie-баннер — только если реально есть аналитика/трекеры; лучше Яндекс.Метрика с анонимизацией.
- На сайте: реальные реквизиты, адрес, телефон, режим работы, гарантия — это и юридическая, и конверсионная база.

## 5. Метрики успеха

| Метрика | Цель |
|---|---|
| Конверсия в заявку (квиз) | ≥ 4–6 % от визитов на мобиле |
| Доля завершения квиза | ≥ 55 % от начавших |
| LCP (mobile 4G) | < 2,5 с |
| Lighthouse Mobile Perf | ≥ 90 (цель 95+) |
| Отказы на первом экране | < 45 % |
| Время ответа на заявку | < 15 мин (бот + письмо + алерт) |

## 6. Что измеряем и как

Яндекс.Метрика (цели: старт квиза, шаг 3, отправка, клик «позвонить», просмотр видео, открытие галереи),
события в dataLayer, UTM-метки в заявке (уходят в письмо и в бота — менеджер видит источник).
A/B на первом экране: «Рассчитать стоимость» vs «Записаться на диагностику».
