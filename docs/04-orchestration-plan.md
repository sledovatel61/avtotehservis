# 04. План оркестрации

## Роли

| Кто | Что делает | Чего не делает |
|---|---|---|
| **Заказчик** | запускает пять агентов, присылает ссылки на PR, выбирает мокап, подтверждает факты | не пересылает файлы вручную |
| **Оркестратор (я)** | бриф, промпт, фактчек, скоринг, замены, ревью кода, приёмка | **не пишу ответы за агентов и не начинаю разработку до выбора мокапа** |
| **Пять агентов** | полноценные концепции по 12 разделам, затем пять мокапов; победитель пишет код | не выдумывают факты, не копируют чужие сайты, не трогают чужие папки |

---

## Раунд 1. Концепции

**Вход:** один универсальный промпт (`prompts/00-universal-agent-prompt.md`) + сообщение «Ты Агент N, работай по промпту».

**Выход:** пять веток `agent/NN-<слаг>`, в каждой `agents/agent-NN/concept.md`, PR в `main`.

**Правила:**
- Все пять — полноценные концепции по 12 разделам. Специализация — только акцент.
- Агенты не видят работы друг друга.
- Я не вмешиваюсь в содержание и не пишу черновики.
- Импорт: `scripts/import-agent.sh` (проверяет структуру, размеры, отсутствие секретов и бинарников).

**Моя работа:** скоринг по `docs/03-evaluation-rubric.md`, таблица баллов, разбор каждого, решение о заменах.

**Замены:** два слабейших выбывают, приходят два новых. **В конкурсе остаётся пять полноценных участников.** Мандат замены — усилить провалившиеся критерии (чаще всего: стоимость владения и мобильная публикация), но структура та же: 12 разделов.

> Замены не «добирают» баллы выбывшим и не наследуют их идеи. Это новые независимые работы.

---

## Раунд 2. Мокапы

**Кто:** все пять участников (три оставшихся + две замены).

**Что сдают:** `agents/agent-NN/mockup.html` + `mockup-notes.md`, ветка та же, новый PR или обновление существующего.

**Требования:** в универсальном промпте, §9. Коротко: один файл, без сборки и внешних JS, ≤ 400 КБ, все 14 блоков, рабочий квиз, галерея с лайтбоксом, видео с постером, 320–1440, reduced-motion, реальные русские тексты.

**Проверка перед показом заказчику:** я открываю каждый мокап, прохожу квиз, проверяю 320 px, вес, доступность и отсутствие выдуманных фактов. Фиксирую результат в `evaluation/round2-mockups.md`.

**Выбор:** заказчик смотрит пять файлов (можно с телефона) и выбирает один. Я даю рекомендацию с плюсами, минусами и риском.

**Гейт:** без выбора мокапа разработка не начинается. Никаких «пока согласовываем, начнём каркас».

---

## Раунд 3. Продакшн-код

**Кто:** победитель мокапа. Если у второго участника сильнее техническая часть — он может стать соавтором по своей зоне, но ответственность и ветка — у победителя.

**Порядок:**
1. Каркас, дизайн-токены, CI, `.env.example`.
2. Главная по секциям.
3. Квиз + API + БД + антиспам.
4. Галерея, загрузка медиа, постеры видео.
5. Отзывы и модерация.
6. Админка (включая мобильную публикацию).
7. Интеграции: SMTP, Telegram, Outbox, ретраи.
8. SEO, аналитика, доступность, перф.
9. Деплой, бэкапы, документация, инструкция владельцу.

**Мой ревью на каждом PR:**

| Блок | Что проверяю |
|---|---|
| Архитектура | границы, дубли, типы, миграции |
| Безопасность | валидация, права, загрузки, секреты, rate limit |
| Перф | бандл, гидрация, изображения, шрифты, LCP/INP |
| Доступность | семантика, фокус, контраст, клавиатура |
| Контент | нет выдуманных фактов, тексты по брифу |
| Мобайл | 320–430 px, тапы, safe-area, липкие элементы |
| Надёжность | падение Telegram / SMTP / БД |
| Соответствие мокапу | визуал и сценарии не «упростили» без согласования |

PR не мержится, пока чек-лист не пройден. Правки — точечные, с причиной.

## Git-протокол (как я подтягиваю работы)

1. Агент пушит ветку `agent/NN-<слаг>` и открывает PR в `main`.
2. Заказчик присылает номер PR или ссылку.
3. Я выполняю:

```bash
scripts/import-agent.sh --branch agent/01-brand-concept
```

4. Скрипт:
   - находит ветку (или `origin/...`),
   - читает **только** `agents/agent-NN/`,
   - проверяет расширения, размеры, отсутствие секретов и внешних скриптов,
   - копирует в `agents-output/round1/agent-NN/` (или `mockups/agent-NN/` для этапа 2),
   - печатает отчёт: файлы, размеры, предупреждения, SHA коммита.

5. Я не мержу ветки агентов в свою: копирую содержимое и коммичу в `arena/099a14c5-avtotehservis`. Так история чистая, а работы сохраняются как есть.

Если PR нет, а есть только ссылка на ветку — скрипт работает с веткой. Если и ветки нет — агент нарушил протокол, работа возвращается на доработку.

## Календарь (ориентир)

| Этап | Длительность | Зависит от |
|---|---|---|
| Раунд 1: пять концепций | 1–2 дня | заказчик запускает агентов |
| Скоринг и решение по заменам | 2–4 часа | я |
| Раунд 2: пять мокапов | 2–3 дня | агенты |
| Проверка и выбор мокапа | 1 день | заказчик + я |
| Раунд 3: код | 10–14 дней | победитель, я на ревью |
| Контент (фото/видео/прайс) | параллельно | владелец |
| Деплой и приёмка | 2–3 дня | я + владелец |

Итого 3–4 недели при готовом контенте. Главный риск сроков — контент и доступы, а не код.

## Гейты (жёсткие)

| Гейт | Условие прохода |
|---|---|
| G1 | Пять концепций реально получены (не сгенерированы мной) |
| G2 | Все 12 разделов есть у каждой; дисквалификаций нет |
| G3 | Скоринг опубликован, замены утверждены |
| G4 | Пять мокапов сданы и проверены |
| G5 | **Заказчик выбрал мокап** — только после этого код |
| G6 | Тест загрузки фото/видео с телефона пройден |
| G7 | Приёмка: заявка проходит e-mail + Telegram + админку, Lighthouse ≥ 90 |

## Что мне нужно от заказчика

| Когда | Что |
|---|---|
| Сейчас | разослать промпт пяти агентам, прислать PR-ссылки |
| После скоринга | подтвердить замены |
| После мокапов | выбрать один |
| До кода | ответы на вопросы владельцу (юрлицо, часы, гарантия, e-mail, Telegram, прайс, фото) |
| До деплоя | домен, доступ к регистратору, VPS, SMTP, токен бота |

## Правила игры

1. Один источник фактов — `prompts/00-context-pack.md` и `docs/06-fact-check.md`. Всё остальное помечается.
2. Никаких фейковых отзывов, цен и кейсов. Лучше меньше блоков, но правда.
3. Конкуренция, а не кооперация в раунде 1: агенты не видят работы друг друга.
4. Всё в репозитории: концепции, мокапы, решения, ревью.
5. Заказчик решает вкус, я — качество. Я могу ветировать решение, которое ломает запуск (перф, безопасность, 152-ФЗ), и обязан объяснить почему.
6. Спор решается цифрами: вес, часы, стоимость, LCP.
