# 04. План оркестрации

## Роли

| Кто | Что делает | Что не делает |
|---|---|---|
| **Ты (заказчик)** | запускаешь агентов, приносишь их ответы, выбираешь мокап, принимаешь факты и контент | не пишешь код и не сводишь концепции вручную |
| **Я (оркестратор)** | бриф, промпты, скоринг, замена слабых, ревью кода, приёмка, тех-решения | не подменяю собой 5 независимых концепций — конкуренция должна быть честной |
| **5 агентов** | раунд 1: концепции; раунд 2: мокапы; раунд 3: продакшн-код у победителя | не выдумывают факты и не копируют чужие сайты |

---

## Раунд 1. Концепции (сейчас)

**Вход:** 5 промптов из `prompts/`, одинаковый фактический контекст, разные мандаты.

| № | Агент | Мандат |
|---|---|---|
| А1 | Бренд-стратег | позиционирование, нейминг, домен .ru, логотип, айдентика, tone of voice, репутация |
| А2 | Арт-директор | визуальная идея, 2 направления, анимация, мобильный дизайн, референсы |
| А3 | UX/CRO-архитектор | структура страницы, квиз, галерея, отзывы, аналитика, A/B-гипотезы |
| А4 | Технический архитектор | стек, модель данных, админка, интеграции, деплой, перф, 152-ФЗ |
| А5 | Копирайтер и контент | готовые тексты, кейсы, отзывы, FAQ, контент-план, гайд по съёмке |

**Выход:** 5 файлов `.md` по 8–15 КБ в `agents-output/round1/`.

**Моя работа:** оценка по рубрике из `docs/03-evaluation-rubric.md`, таблица баллов, разбор каждого, вердикт «финал / замена».

**Кого оставляю:** топ-3 по сумме баллов.
**Кого заменяю:** 2 худших → новые агенты с усиленным мандатом под слабые места проекта:
- **А6 — Growth / репутация / локальное SEO** (если проседает трафик и доверие);
- **А7 — Motion / интерактив / перф** (если проседает «вау» и лёгкость анимации).

Мандаты замен я формулирую после скоринга — под конкретные дыры, а не «ещё один дизайнер».

## Раунд 2. HTML-мокапы

**Кто:** 3 финалиста. Каждый делает **один самодостаточный HTML-файл**: вся вёрстка, стили и скрипты внутри, без сборки.

**Почему только 3:** пять мокапов — это 2–3 часа твоего времени на просмотр и риск выбрать «самый яркий» вместо «самого продающего». Три — управляемо, и они уже прошли отбор по мышлению.

**Что делают замены:** собирают сводный док «что забрать у выбывших» + список улучшений для мокапов. Их идеи не теряются, но ты не получаешь ещё два файла на сравнение.

> Если хочешь мокапы от всех пяти — скажи, я выдам задание на 5. Это единственное место, где я отступаю от твоего плана, и только ради твоего времени.

**Требования к мокапу** (полностью в `prompts/06-round2-mockup.md`):
- 1 файл, ≤ 400 КБ, без внешних JS-библиотек;
- обязательные блоки: hero, услуги, доказательства, квиз (3 экрана), галерея, отзывы, контакты, футер, липкий мобильный CTA;
- реальные русские тексты, никакого «Lorem ipsum»;
- рабочие интеракции: шаги квиза, лайтбокс, мобильное меню;
- 320 / 390 / 768 / 1440, без горизонтального скролла, `prefers-reduced-motion`;
- вес и поведение важнее количества эффектов.

**Твоя работа:** открыть три файла, пройти квиз на телефоне, выбрать один. Я дам рекомендацию с плюсами/минусами и рисками.

## Раунд 3. Продакшн-код

**Кто:** победитель мокапа с наивысшим суммарным баллом. Если это разные агенты — побеждает тот, у кого мокап лучше; второй становится соавтором по своей зоне (например, техархитектор — на интеграции).

**Как ведём работу:**
1. Каркас проекта, дизайн-токены, CI, `.env.example`.
2. Главная по секциям (каждая секция — отдельный PR).
3. Квиз + API + БД.
4. Галерея + загрузка медиа.
5. Отзывы.
6. Админка.
7. Интеграции: SMTP + Telegram + очередь + ретраи.
8. SEO, аналитика, доступность, перф.
9. Деплой, бэкапы, документация, инструкция владельцу.

**Мой ревью на каждом PR:**

| Блок | Что проверяю |
|---|---|
| Архитектура | границы компонентов, нет дублей, типы, миграции |
| Безопасность | валидация входа, права, загрузки, секреты, rate limit |
| Перф | вес бандла, гидрация, изображения, шрифты, LCP/INP |
| Доступность | семантика, фокус, контраст, клавиатура, скринридер |
| Контент | нет выдуманных фактов, тексты по брифу, ошибки не пугают |
| Мобайл | 320–430 px, тапы, safe-area, липкие элементы |
| Надёжность | что будет, если упал Telegram / SMTP / БД |

**Правило:** PR не мержится, пока не пройден чек-лист. Правки — не «перепиши всё», а точечные комментарии с причиной.

## Календарь (ориентир)

| Этап | Длительность | От кого зависит |
|---|---|---|
| Раунд 1: концепции | 1–2 дня | ты запускаешь 5 агентов параллельно |
| Скоринг и решение | 2–4 часа | я |
| Раунд 2: мокапы | 2–3 дня | 3 финалиста |
| Выбор мокапа | 1 день | ты |
| Раунд 3: код | 10–14 дней | победитель + я на ревью |
| Контент (фото/видео/цены) | параллельно | владелец |
| Деплой и приёмка | 2–3 дня | я + владелец |

Итого до запуска: **3–4 недели**, если контент не задержится. Контент — главный риск сроков, а не код.

## Правила игры

1. **Один источник фактов** — `docs/01-company-research.md` и контекст-пакет. Всё остальное помечается «уточнить».
2. **Никаких фейковых отзывов и цен.** Лучше меньше блоков, но правда.
3. **Конкуренция, а не кооперация** в раунде 1: агенты не видят ответы друг друга.
4. **Всё в репозитории.** Ответы, мокапы, решения, ревью — чтобы через месяц было понятно, почему сделано именно так.
5. **Ты решаешь вкус, я — качество.** Мокап выбираешь ты; за перф, безопасность и 152-ФЗ отвечаю я и могу ветировать решение, если оно ломает запуск.
6. **Спор решается цифрами.** Если агент предлагает «immersive 3D», он показывает вес, LCP и что выкинем взамен.
