# Почта для заявок — подключение (АвтоТехСервис)

Короткая инструкция: как включить копию каждой заявки на `Pavel.yakovenko@mail.ru`.
Всё делается в браузере, программировать ничего не нужно. Время — 5–10 минут.

**Что сейчас:** Telegram работает (`"telegram":true`), почта выключена (`"email":null`).
Проверить в любой момент: `https://ats-leads.ats439.workers.dev/health`

**Как это устроено.** Заявка с сайта уходит в Cloudflare Worker, а он — сразу в два места:
в группу Telegram и письмом на почту. Письмо отправляет не сам сервис «изнутри», а почтовый
сервис по API: у Cloudflare Worker нет SMTP. Поэтому нужен один ключ от одного из двух
сервисов — **Brevo** (советую) или **Resend** (альтернатива).

| | Brevo | Resend |
|---|---|---|
| Бесплатно | 300 писем в день | 100 писем в день |
| Кому можно писать | любому адресу | **только на адрес владельца аккаунта**, пока свой домен не подтверждён (см. вариант 3) |
| Что нужно подтвердить | адрес отправителя (1 письмо) | адрес аккаунта, затем домен |
| Ключ начинается с | `xkeysib-` | `re_` |
| Секрет в GitHub | `BREVO_API_KEY` | `RESEND_API_KEY` |

Если задать оба ключа, победит Brevo.

### Главное, из-за чего обычно всё встаёт

**Аккаунт Resend не обязан быть на ящике Паши.** Регистрируйтесь на свой — на тот, к которому
у вас есть доступ прямо сейчас. Ограничение Resend без своего домена звучит так: письма можно
слать **только на адрес владельца аккаунта**. То есть если аккаунт на ваш ящик, письма будут
приходить вам, а не Паше. Чтобы писать Паше — нужен подтверждённый домен (вариант 3), а не
«зарегистрироваться через Пашу» и не ждать, пока он подтвердит письмо.

## Вариант 1. Brevo — если нет доступа к DNS домена

### Шаг 1. Зарегистрироваться

1. Откройте `https://www.brevo.com` → кнопка **Sign up free**.
2. Заполните **свой** рабочий e-mail (тот, к которому есть доступ прямо сейчас), пароль, имя.
3. На почту придёт письмо от Brevo — нажмите в нём кнопку подтверждения и войдите в кабинет.

Brevo, в отличие от Resend, может отправлять на любой адрес. Поэтому аккаунт можно завести
на собственный ящик: его же подтвердите как адрес отправителя, а получателем останется
`Pavel.yakovenko@mail.ru` из `relay/wrangler.toml`.

### Шаг 1а. Анкета «Welcome! Nice to meet you» — что вписать

После подтверждения почты Brevo показывает форму из четырёх полей. Заполняйте ровно так:

| Поле в форме | Что вписать |
|---|---|
| **First name \*** | `Pavel` |
| **Last name \*** | `Yakovenko` |
| **Organization name \*** | `AvtoTehServis` |
| **Website \*** | `sledovatel61.github.io` — **без** `https://`, **без** `/avtotehservis` и **без** `/` в конце |
| ☐ I don't have a website | **галочку НЕ ставить** — сайт у нас есть |
| ☐ I don't want to receive product updates, marketing tips… | **галочку поставить** — меньше рекламы на почту; на отправку писем не влияет |

Латиницей — потому что Brevo европейский сервис и латиница избавляет от проблем с
кодировкой в письмах проверки. На работу отправки это не влияет.

**Про поле Website — ошибка `errorWrong website format`.** Brevo принимает только «голый»
домен в виде `www.mywebsite.com`. Нельзя: `https://`, путь после домена, `/` в конце.
Правильно — `sledovatel61.github.io`. Если Brevo упрётся и в такой вариант, поставьте
галочку **I don't have a website** — на отправку писем это поле не влияет вообще,
оно нужно Brevo только для подсказок в кабинете.

**Если Brevo спросит дальше** (следующие экраны онбординга):

| Вопрос | Ответ |
|---|---|
| Industry / отрасль | `Automotive` (или «Vehicle repair / auto service») |
| Company size | `1–10` / `Just me` |
| Role | `Owner` / `Founder` |
| What do you want to send | **Transactional emails** — это письма по заявкам, не рассылки |
| Phone number | свой номер, если попросит подтвердить |

Телефон Brevo иногда требует для SMS-подтверждения. Если SMS на российский номер не
приходит — скажите, переключимся на Resend (там телефон не нужен, но письма уходят
только на адрес владельца аккаунта, нам этого достаточно).

После анкеты Brevo спросит адрес организации — это следующий экран
«**What is your organization address?**». Заполняйте так:

| Поле в форме | Что вписать |
|---|---|
| **Address \*** | `Portovaya st., 439` (латиницей; можно и `ул. Портовая, 439` — но латиницей надёжнее) |
| **Postal code \*** | `344033` |
| **City \*** | `Rostov-on-Don` |
| **Country \*** | `Russia` (в выпадающем списке; если выбрать нельзя — `Russian Federation`) |

Почему именно так:
- **344033** — индекс дома Портовая, 439 (Западный жилищный массив, Железнодорожный
  район Ростова-на-Дону). Он же используется в наших документах по компании.
- Адрес попадает **в подвал каждого письма** («Every email you send will include your
  organization address»), поэтому пишем настоящий — это требование антиспам-законодательства
  и заодно бесплатная реклама адреса сервиса клиенту.
- Если Brevo будет ругаться на формат — попробуйте `Portovaya 439` без «st.» и без запятой.

Дальше кнопка **Select your plan** — выбирайте **бесплатный план** (в интерфейсе он может
называться `Free` или `Starter`, 300 писем в день). Карту и платёжные данные вводить
не нужно, ничего не оплачиваем.

### Шаг 2. Подтвердить адрес отправителя

Без этого Brevo письма не отправит (вернёт ошибку).

1. В кабинете слева/сверху откройте **Senders, Domains & Dedicated IPs** (или просто
   **Senders**).
2. Вкладка **Senders** → кнопка **Add a sender**.
3. Заполните:
   - **Sender's name**: `АвтоТехСервис`
   - **Sender's email**: `Pavel.yakovenko@mail.ru`
4. **Save** → Brevo пришлёт письмо «Please confirm your sender».
5. Откройте его и нажмите ссылку подтверждения. В списке Senders адрес станет
   **Verified**.

Домен покупать и настраивать не нужно.

### Шаг 3. Создать ключ API

1. В правом верхнем углу — иконка профиля → **SMTP & API**.
2. Вкладка **API Keys** → **Generate a new API key**.
3. **Name**: `avtotehservis` → **Generate**.
4. Скопируйте ключ целиком (начинается с `xkeysib-`) — он показывается один раз.

Ключ — это пароль от почтовой отправки. В переписку, в код и в админку сайта его
вставлять не нужно.

### Шаг 4. Положить ключ в GitHub

1. Откройте `https://github.com/sledovatel61/avtotehservis`.
2. Справа сверху — **Settings**.
3. Слева **Secrets and variables** → **Actions**.
4. Вкладка **Secrets** → зелёная кнопка **New repository secret**.
5. **Name**: `BREVO_API_KEY` (ровно так, заглавными).
6. **Secret**: вставьте ключ `xkeysib-…`.
7. **Add secret**.

Секрет после сохранения не показывается — это нормально, его можно только перезаписать.

### Шаг 5. Применить ключ к воркеру

Ключ попадёт в работу только после запуска публикации.

1. В репозитории сверху вкладка **Actions**.
2. Слева выберите workflow **Deploy leads relay**.
3. Справа **Run workflow** → ветка **preview/github-pages** → зелёная **Run workflow**.
4. Обновите страницу через 10 секунд, откройте новый запуск и дождитесь зелёной галочки
   (1–2 минуты).
5. В логе шага **Push secrets to worker** должно быть: `Почта: Brevo подключён`.
   Если там `::warning::Ключа почты нет` — секрет не сохранился или имя с опечаткой.

### Шаг 6. Проверить

1. Откройте `https://ats-leads.ats439.workers.dev/health`.
2. Должно быть так:

```json
{"ok":true,"service":"ats-leads","time":"…","telegram":true,"email":"brevo","emailTo":"Pavel.yakovenko@mail.ru","consentVersion":"2026-11-20","kv":false}
```

Главное — `"email":"brevo"` вместо `"email":null`.

3. Отправьте тестовую заявку с сайта:
   `https://sledovatel61.github.io/avtotehservis/appointment/`
4. Должно прийти **и** сообщение в группу Telegram, **и** письмо на
   `Pavel.yakovenko@mail.ru`. Первое письмо Brevo иногда кладёт в «Спам» — проверьте папку
   и нажмите «Не спам».

Готово. Дальше каждая заявка с сайта дублируется на почту автоматически.

## Вариант 2. Resend без домена — если Brevo не подошёл

Это самый быстрый путь: **5 минут, без DNS, без Паши**. Письма будут приходить на тот ящик,
на который зарегистрирован аккаунт. Если вам нужны копии у себя — этого достаточно.

1. `https://resend.com/signup` — регистрация **на свой ящик**, к которому есть доступ сразу.
   Письма отсюда смогут уходить только на этот же адрес.
   Если копии нужны именно Паше — сразу идите в вариант 3.
2. Подтвердите письмо, войдите в кабинет.
3. Слева **API Keys** → **Create API Key**.
4. **Name**: `avtotehservis`, **Permission**: **Sending access**, домен — оставьте
   предложенный `onboarding.resend.dev`.
5. **Create** → скопируйте ключ (начинается с `re_`), он показывается один раз.
6. GitHub → **Settings** → **Secrets and variables** → **Actions** → **Secrets** →
   **New repository secret**: **Name** `RESEND_API_KEY`, **Secret** — ключ → **Add secret**.
7. **Перезапустить деплой воркера.** Кнопки **Run workflow** в интерфейсе вы не увидите:
   этот воркфлоу есть только в ветке `preview/github-pages`, а GitHub показывает кнопку
   лишь для файлов из ветки по умолчанию (`main`). Поэтому: напишите в чат «секрет добавлен» —
   оркестратор запустит деплой одним коммитом в `relay/`. Секрет подхватится сам.
8. Проверка та же: в `/health` должно быть `"email":"resend"`.

## Вариант 3. Resend + свой домен — правильный финал

Даёт то, чего не дают варианты 1–2: письма уходят **любому адресу** (и Паше, и вам),
отправитель — `zayavka@ats-rostov.ru`, а не `onboarding@resend.dev`, и письма реже падают
в спам (SPF + DKIM). Нужен доступ к DNS домена — то есть туда, где `ats-rostov.ru` куплен.

1. Зарегистрируйте Resend **на свой ящик** (как в варианте 2) — это не мешает.
2. Слева **Domains** → **Add Domain** → `ats-rostov.ru`.
3. Resend покажет **три DNS-записи**. Внесите их у регистратора домена **один в один**,
   ничего не меняя: обычно это MX и TXT (SPF) для поддомена `send` и CNAME для DKIM
   (`resend._domainkey`). Ключевое — скопировать имена и значения буквально.
4. Дождитесь статуса **Verified** (от нескольких минут до нескольких часов) — нажмите
   **Verify DNS Records**.
5. `API Keys` → **Create API Key**, **Sending access**, домен — `ats-rostov.ru`. Ключ `re_…`
   → секрет `RESEND_API_KEY` (шаг 6 варианта 2).
6. В чат: «домен подтверждён». Оркестратор одним коммитом поставит отправителя
   `EMAIL_FROM = "АвтоТехСервис <zayavka@ats-rostov.ru>"` в `relay/wrangler.toml`;
   `EMAIL_TO` остаётся `Pavel.yakovenko@mail.ru`, при необходимости добавим и ваш адрес.
7. Проверка: `/health` → `"email":"resend"`, тестовая заявка приходит на почту.

**Если DNS-доступа нет** — вариант 3 откладывается, работает вариант 2 (письма вам),
Telegram продолжает работать у всех. Это не блокер сайта.

## Если что-то не так

| Что видите | Причина | Что делать |
|---|---|---|
| `/health` → `"email":null` | ключа нет в GitHub или воркер не перезапускали после добавления | добавить `RESEND_API_KEY` (или `BREVO_API_KEY`), попросить перезапуск в чате |
| В логе `::warning::Ключа почты нет` | то же самое; часто опечатка в имени секрета | имя ровно `BREVO_API_KEY`, без пробелов |
| Письмо не пришло, ошибок нет | Brevo: адрес отправителя не подтверждён; Resend без домена: получатель не совпадает с адресом аккаунта | Brevo — шаг 2 (Senders → Verified); Resend — слать на свой адрес либо подключить домен (вариант 3) |
| Письмо не пришло, в логе `403` | ключ без прав / отправитель не подтверждён | пересоздать ключ (Brevo: SMTP & API → API Keys) |
| Письмо в «Спаме» | обычное дело для нового отправителя | «Не спам» один раз, дальше будет в «Входящих» |
| `/health` → `"telegram":false` | это уже не почта: слетели `BOT_TOKEN` / `TELEGRAM_CHAT_ID` | написать мне, не перевыпускать токен бота |
| Заявка с сайта → `400 consent_version` | версия согласия на сайте и в воркере разошлись | написать мне: правится в коде, не в секретах |

---

## Что важно не делать

- **Не перевыпускать токен бота** (не нажимать Revoke у `@BotFather`) — Telegram уже работает.
- Не вставлять ключи Brevo/Resend в переписку, в код, в админку сайта и в скриншоты.
  Если ключ куда-то попал — в кабинете сервиса удалите его и создайте новый, затем обновите
  секрет в GitHub.
- Не менять `EMAIL_TO` в `relay/wrangler.toml` — там уже стоит `Pavel.yakovenko@mail.ru`.

## Что где лежит

- Список секретов, которые читает деплой: `.github/workflows/relay.yml`.
- Получатель копий писем: `relay/wrangler.toml` → `EMAIL_TO`.
- Отправитель (необязательно): `relay/wrangler.toml` → `EMAIL_FROM`. Пусто — для Brevo
  берётся `EMAIL_TO`, для Resend — `onboarding@resend.dev`.
- Код отправки письма: `relay/src/email.ts`.
- Общая инструкция по всем секретам (Telegram, Cloudflare, почта): `docs/secrets-setup.md`.
