# 13. Чек-лист запуска сайта «АвтоТехСервис» (Ростов-на-Дону, Портовая 439)

Документ для владельца или подрядчика: по нему сайт поднимается **без участия разработчиков**.
Все команды — копипаст; шаги, где нужны мы, помечены **«нужен оркестратор»**.
Технические подробности деплоя — в `site/deploy/deploy.md` (этот чек-лист ссылается на его разделы).

Порядок: **1 домен → 2 сервер → 3 почта → 4 Telegram → 5 первый деплой → 6 контент → 7 бэкапы → 8 проверка «сайт жив»**.
Пункты 3 и 4 можно менять местами; пункт 6 — после того, как сайт уже открывается.

Что нужно собрать до начала (без этого деплой встанет):
- [ ] оплаченный домен и IP-адрес сервера (п. 1–2);
- [ ] SMTP: хост, порт, логин, **пароль приложения** (п. 3);
- [ ] токен Telegram-бота и chat_id получателя (п. 4);
- [ ] пароль админки ≥12 символов — придумайте заранее, нигде не переиспользуйте (п. 5).

## 1. Домен

- **Что регистрировать:** `avtotehservis439.ru` — рабочий вариант (проверено: `avtotehservis.ru` занят с 2014 года).
- **Где:** любой аккредитованный регистратор `.ru` — reg.ru, nic.ru (RU-CENTER), beget.com. Домен в зоне `.ru` стоит ориентировочно 200–1000 ₽/год — цена зависит от регистратора и акций, проверьте на месте. **(делает владелец)**
- **Как направить:** в панели регистратора создайте две A-записи:
  | Хост | Тип | Значение | TTL |
  |---|---|---|---|
  | `@` (корень домена) | A | IP вашего сервера | 3600 |
  | `www` | A | тот же IP | 3600 |
  Обновление DNS — от нескольких минут до суток. Проверка: `ping avtotehservis439.ru` должен отвечать IP сервера.
- Дальше домен подставляется в два места: `PUBLIC_SITE_URL=https://avtotehservis439.ru` в env (п. 5) и `server_name` в `nginx.conf` (`deploy.md` §7).
- **Нужен оркестратор:** если домен регистрируем не мы — просто сообщите нам имя и IP, остальное вставим в конфиги.

## 2. Сервер

- **Минимальная конфигурация:** 2 vCPU / 2 ГБ RAM / 20 ГБ SSD — **хватает с запасом**. Сайт — один процесс Node (~150–250 МБ), nginx и SQLite в одном файле; медиа-архив растёт медленно (фото ≤15 МБ сжимаются в варианты WebP/AVIF). ОС: Debian 12 или Ubuntu 22.04/24.04, дата-центр — в РФ (152-ФЗ: данные хранятся в России).
- **Node.js:** нужен **22.18 или новее**; `deploy.md` §1 ставит 24.x LTS через NodeSource. Проверка версии:
  ```bash
  node -v    # ожидается v22.18+ или v24.x
  ```
- Покупка VPS и SSH-доступ — **(делает владелец)**; первичную настройку по `deploy.md` §1–§2 может выполнить подрядчик или **оркестратор**.

## 3. Почта для заявок (SMTP)

Нужно от владельца **(делает владелец)**:
1. Ящик на mail.ru (или другом хостинге с SMTP) — например `avtotehservis439@mail.ru`.
2. В настройках ящика: «Пароли для внешних приложений» → включить IMAP/SMTP → выпустить **пароль приложения**. Это НЕ пароль от ящика — в env идёт именно он.
3. Значения для `/etc/avtotehservis/env` (`deploy.md` §4):
   ```
   SMTP_HOST=smtp.mail.ru  SMTP_PORT=465  SMTP_SECURE=true
   SMTP_USER=avtotehservis439@mail.ru  SMTP_PASS=<пароль приложения>
   MAIL_FROM="АвтоТехСервис <avtotehservis439@mail.ru>"  MAIL_TO=avtotehservis439@mail.ru
   ```

**Как проверить, что письмо уходит, НЕ отправляя заявку в боевую базу** — прямой тест транспорта (БД не открывается, заявка не создаётся):

```bash
sudo -u avtotehservis bash -c 'set -a; . /etc/avtotehservis/env; set +a; cd /var/www/avtotehservis/repo/site && node -e "
const nodemailer = require(\"nodemailer\");
(async () => {
  const t = await nodemailer.createTransport({ host: process.env.SMTP_HOST, port: Number(process.env.SMTP_PORT), secure: process.env.SMTP_SECURE === \"true\", auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS } });
  const info = await t.sendMail({ from: process.env.MAIL_FROM, to: process.env.MAIL_TO, subject: \"Проверка SMTP — заявка НЕ создавалась\", text: \"Если вы видите это письмо, почта для заявок настроена верно.\" });
  console.log(\"ОТПРАВЛЕНО, messageId:\", info.messageId);
})().catch((e) => { console.error(\"ОШИБКА SMTP:\", e.message); process.exit(1); });
"'
```

Письмо должно прийти на `MAIL_TO` в течение минуты. Ошибка — проверьте пароль приложения и `SMTP_SECURE=true` для порта 465.

## 4. Telegram для дублей заявок

1. В Telegram откройте **@BotFather** → `/newbot` → имя («АвтоТехСервис заявки») и username (например `ats439_bot`) → получите **токен** вида `1234567890:AAA…`. **(делает владелец)**
2. Узнайте **chat_id** получателя:
   - личный чат: напишите боту `/start` со своего аккаунта, затем
     ```bash
     curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | head -c 600
     ```
     в ответе ищите `"chat":{"id":123456789,…}` — это и есть chat_id;
   - группа (рекомендуем: заявки увидят несколько человек): добавьте бота в группу, напишите в неё любое сообщение, повторите `getUpdates` — id группы отрицательный (`-100…`).
3. В `/etc/avtotehservis/env`:
   ```
   BOT_TOKEN=<токен от BotFather>
   TELEGRAM_CHAT_ID=<chat_id из шага 2>
   ```
4. **Как убедиться, что дубль дойдёт, без заявки в базу** — прямое сообщение через API:
   ```bash
   curl -s -X POST "https://api.telegram.org/bot<ТОКЕН>/sendMessage" \
     -d chat_id=<CHAT_ID> -d text="Проверка: бот заявок работает (заявка НЕ создавалась)"
   ```
   Ответ `"ok":true` + сообщение в чате = настроено. После деплоя контрольная проверка — тестовая заявка (п. 8): дубль приходит в чат автоматически, статус доставки виден в админке `/admin/leads`.

| Шаг | Раздел | Как проверить, что получилось |

## 6. Что заменить после запуска

Полный список — **`docs/12-content-checklist.md`** (блокеры запуска, фото, тексты, критерий «контент готов»). Коротко:

- **Демо-контент (если включали для показа):** `npm run seed:demo` добавляет помеченные демо-новости (`demo-*`) и демо-отзывы (`source='demo'`). **Демо-отзывы — вымышленные люди, на боевом сайте их быть не должно:** перед запуском `npm run seed:demo:clear` — удаляет только помеченное.
- **6 кейсов-заглушек** (SVG-плейсхолдеры) → реальные кейсы с фото «до/после» через `/admin/cases` (цель — публикация ≤60 с с телефона).
- **Фото hero и услуг** → реальные снимки сервиса (`/admin/media`, фото ≤15 МБ, видео ≤100 МБ).
- **Доп. телефоны** (Приёмная, Ремонтная зона) — по умолчанию СКРЫТЫ до подтверждения: заполните «Доп. 1/2 — показ и tel» в `/admin/settings`, они появятся в подвале и на `/contacts`. Номера из сторонних каталогов — сначала подтвердите, что они ваши (docs/12, п. 8).
- **Рейтинги** — скрыты, пока владелец не подтвердит цифры (`ratings_visible` в `/admin/settings`).
- **Реквизиты, гарантия, политика ПД** — сверить с документами (docs/12 §1, §3).

## 7. Бэкапы и восстановление

- **Расписание:** `cp deploy/backup.cron /etc/cron.d/avtotehservis-backup` — ежедневно в 03:15, хранение 14 дней, каждая копия проверяется `PRAGMA integrity_check` (`deploy.md` §8). Журнал: `/var/log/avtotehservis-backup.log`.
- **Проверить руками первый раз** (сразу после деплоя) — команда из `deploy.md` §8: бэкап должен появиться в `/var/backups/avtotehservis/<метка>` с `integrity_check=ok`.
- **Учение по восстановлению — раз в месяц на КОПИИ** (не на боевой базе!): восстановите последний бэкап во временный каталог по `deploy.md` §8 (`restore.sh` с `STOP_SERVICE=0` и временными `DATA_DIR`/`MEDIA_DIR`) и убедитесь, что заявки на месте. Полный цикл backup→restore проверялся разработчиками на копии (в т.ч. каталоги с пробелом и кириллицей) — содержимое возвращается побайтово.
- **Нужен оркестратор:** первая учебная реконструкция — вместе с нами.

## 8. Чек-лист «сайт жив» (после деплоя и после каждого обновления)

1. `cd /var/www/avtotehservis/repo/site && npm run smoke -- https://<домен>` — **все строки `ok`**, код выхода 0 (страницы 200, health ok, слоты на завтра есть, sitemap, /admin редиректит, /media 404 без 500, canonical — ваш домен). Заявку smoke не отправляет — базу не засоряет.
2. Войти в `/admin/login` под owner — дашборд открывается.
3. Отправить **тестовую заявку** с сайта: имя «ТЕСТ — удалить», телефон свой, сообщение «тест запуска». Ожидание: страница показала талон `A-ДДММ-XXXX`.
4. Письмо пришло на `MAIL_TO` (обычно ≤1 мин; ретраи доставки — 1/5/30 мин… до 8 попыток).
5. Дубль пришёл в Telegram-чат; в `/admin/leads` у заявки доставка `sent` в оба канала.
6. **Удалить тестовую заявку:** в `/admin/leads` — статус «отменена» (из базы и журналов заявка остаётся как служебная, на публичном сайте не видна; счётчики квот сбрасываются в течение часа).
7. Слоты записи на завтра видны на `/appointment` (09:00–18:00).
8. `systemctl status avtotehservis` → active, `journalctl -u avtotehservis -n 50` без ошибок.

Если хоть один пункт не прошёл — не «подкручивайте» конфиг наугад: сохраните вывод команд и обратитесь к оркестратору.
