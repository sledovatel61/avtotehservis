# Настройка секретов: пошагово, куда тыкать

Инструкция для владельца. Всё делается в браузере, ничего программировать не нужно.
Время: обязательная часть — 10 минут, почта — ещё 5.

Что мы настраиваем и зачем:

| Имя | Тип | Зачем | Обязательно? |
|---|---|---|---|
| `BOT_TOKEN` | секрет | бот, который присылает заявки в группу | да |
| `TELEGRAM_CHAT_ID` | секрет | номер группы, куда присылать | да |
| `CLOUDFLARE_API_TOKEN` | секрет | ключ, которым GitHub публикует воркер | да |
| `CLOUDFLARE_ACCOUNT_ID` | секрет | номер аккаунта Cloudflare | можно пропустить, но лучше задать |
| `RESEND_API_KEY` **или** `BREVO_API_KEY` | секрет | копия каждой заявки на `Pavel.yakovenko@mail.ru` | по желанию |
| `PUBLIC_LEADS_ENDPOINT` | переменная | адрес воркера для сайта | не нужно: адрес уже зашит по умолчанию |

Важно: **токен бота не перевыпускать** (не нажимать Revoke). Он уже работает.

---

## Шаг 1. Открыть нужную страницу GitHub

1. Зайдите на `https://github.com/sledovatel61/avtotehservis`.
2. Сверху, справа от названия репозитория, нажмите **Settings** (шестерёнка, последняя вкладка в строке).
3. В левом меню найдите **Secrets and variables** → нажмите на него → откроется подменю
   **Actions**.
4. Вы окажетесь на странице с двумя вкладками: **Secrets** и **Variables**. Работаем на вкладке
   **Secrets**.

Добавление любого секрета одинаковое:

1. Кнопка **New repository secret** (зелёная, справа).
2. Поле **Name** — имя из таблицы (ровно, без пробелов, заглавными).
3. Поле **Secret** — значение.
4. Кнопка **Add secret**.

Секрет после сохранения нельзя посмотреть — только перезаписать (Update) или удалить (Delete).
Это нормально.

## Шаг 2. `BOT_TOKEN` — токен бота

Если токена под рукой нет:

1. В Telegram откройте **@BotFather**.
2. Отправьте `/mybots` → выберите бота сервиса.
3. Нажмите **API Token** → бот пришлёт строку вида `123456789:AA...`.
4. Скопируйте её целиком (с цифрами и двоеточием) и вставьте в поле **Secret**.
5. **Add secret**.

Ничего не отзывайте и не создавайте нового бота: старый токен живой и уже прописан в Cloudflare.

## Шаг 3. `TELEGRAM_CHAT_ID` — номер группы заявок

Значение: `-5417579093` (минус в начале обязателен, это группа, а не личный чат).

1. **New repository secret** → **Name**: `TELEGRAM_CHAT_ID`.
2. **Secret**: `-5417579093`.
3. **Add secret**.

Проверить, что бот в группе: откройте группу «АвтоТехСервис» → в списке участников должен быть бот.

## Шаг 4. `CLOUDFLARE_API_TOKEN` — ключ для публикации воркера

1. Откройте `https://dash.cloudflare.com` и войдите.
2. Справа сверху — иконка профиля → **My Profile**.
3. Слева **API Tokens** → кнопка **Create Token**.
4. В списке шаблонов найдите **Edit Cloudflare Workers** → кнопка **Use template**.
5. Ничего в правах не меняйте, внизу **Continue to summary** → **Create Token**.
6. Cloudflare покажет токен **один раз** — скопируйте его сразу.
7. В GitHub: **New repository secret** → **Name**: `CLOUDFLARE_API_TOKEN` → **Secret**: вставленный
   токен → **Add secret**.

Если токен потеряли — вернитесь в Cloudflare, удалите старый и создайте новый (шаги 3–6), затем
обновите секрет в GitHub.

---

## Шаг 5. `CLOUDFLARE_ACCOUNT_ID` — номер аккаунта

1. В Cloudflare нажмите **Workers & Pages** (левое меню) или откройте
   `https://dash.cloudflare.com/?to=/:account/workers-and-pages`.
2. Справа на странице есть блок **Account ID** — длинная строка из 32 символов
   (`cf6a139e492f4cf18580b910c6a556f0` для вашего аккаунта). Нажмите **Click to copy**.
3. В GitHub: **New repository secret** → **Name**: `CLOUDFLARE_ACCOUNT_ID` → **Secret**: эта строка
   → **Add secret**.

Можно пропустить — workflow попробует определить номер сам, но с секретом надёжнее и быстрее.

## Шаг 6 (по желанию). Почта: `RESEND_API_KEY`

Без этого шага заявки идут только в Telegram. С ним — в Telegram **и** письмом на
`Pavel.yakovenko@mail.ru`.

1. Откройте `https://resend.com/signup`.
2. Зарегистрируйтесь **на тот же ящик** `Pavel.yakovenko@mail.ru` (важно: без своего домена Resend
   разрешает отправку только на адрес владельца аккаунта — нам это и нужно).
3. Подтвердите письмо от Resend, войдите в кабинет.
4. Слева **API Keys** → **Create API Key**.
5. **Name**: `avtotehservis`, **Permission**: **Sending access**, домен — оставьте предложенный
   `onboarding.resend.dev`.
6. **Create** → скопируйте ключ (начинается с `re_`), он показывается один раз.
7. В GitHub: **New repository secret** → **Name**: `RESEND_API_KEY` → **Secret**: ключ → **Add secret**.

Альтернатива — Brevo (`https://www.brevo.com`): создать ключ в **SMTP & API → API Keys**, добавить
секрет `BREVO_API_KEY`. Если заданы оба, победит Brevo. У Brevo сначала нужно подтвердить адрес
отправителя (**Senders**), иначе письма не уйдут.

## Шаг 8. Запустить публикацию воркера

Секреты применяются к воркеру только при запуске workflow.

1. В репозитории сверху вкладка **Actions**.
2. В левом списке выберите **Deploy leads relay**.
3. Справа кнопка **Run workflow** → в выпадающем списке ветка **preview/github-pages** →
   зелёная кнопка **Run workflow**.
4. Обновите страницу через 10 секунд — появится новый запуск. Откройте его, дождитесь зелёной
   галочки (1–2 минуты).

---

## Шаг 9. Проверить, что всё включилось

1. Откройте в браузере `https://ats-leads.ats439.workers.dev/health`.
2. Должно быть примерно так:

```json
{"ok":true,"service":"ats-leads","time":"...","telegram":true,"email":"resend","emailTo":"Pavel.yakovenko@mail.ru","kv":false}
```

Что означает:

- `"telegram":true` — бот и группа на месте;
- `"email":"resend"` — почта включена (без ключа тут будет `null`);
- `"emailTo":"Pavel.yakovenko@mail.ru"` — адрес получателя копий.

3. Отправьте тестовую заявку с сайта `https://sledovatel61.github.io/avtotehservis/appointment/`:
   должны прийти и сообщение в группу, и письмо на почту (проверьте папку «Спам»).

Можно и без сайта: **Actions** → **Проверка прослойки заявок (smoke)** → **Run workflow**. В логе
будет `health: ... "telegram":true ...`, а в группу придёт тестовая заявка.

## Если что-то не так

| Что видите | Причина | Что делать |
|---|---|---|
| `/health` показывает `"email":null` | секрет почты не добавлен или workflow не перезапускали | добавить `RESEND_API_KEY`, повторить шаг 8 |
| В логе `::warning::Ключа почты нет` | то же самое | то же самое |
| В логе `Не удалось определить Account ID` | нет секрета `CLOUDFLARE_ACCOUNT_ID` и токен без прав | добавить секрет по шагу 5 |
| В логе `Authentication error` / `10000` | токен Cloudflare скопирован не целиком или удалён | создать новый токен (шаг 4) и обновить секрет |
| Заявка с сайта → `400 consent_version` | версия согласия на сайте и в воркере разошлись | сообщите мне: это правится в коде, не в секретах |
| Заявка с сайта → `502` | упали оба канала доставки | проверить `/health`; если `telegram:false` — перепроверить `BOT_TOKEN` и `TELEGRAM_CHAT_ID` |
| Письмо не пришло, в логе `403` от Resend | ключ без прав Sending access или аккаунт не подтверждён | пересоздать ключ по шагу 6 |
| Письмо не пришло, но ошибок нет | Resend без домена шлёт только на адрес владельца аккаунта | проверить, что аккаунт Resend заведён на `Pavel.yakovenko@mail.ru`, и папку «Спам» |

## Что где лежит (чтобы не искать)

- Список секретов, которые читает деплой: `.github/workflows/relay.yml`.
- Адрес получателя копий писем: `relay/wrangler.toml` → `EMAIL_TO`.
- Версия согласия (должна совпадать с сайтом): `relay/wrangler.toml` → `CONSENT_VERSION`.
- Инструкция для разработчика по почте: `relay/README.md`.

Секреты хранятся только в GitHub (Settings → Secrets). В код, в чат и в переписку их вставлять
не нужно; если ключ попал в переписку — перевыпустите его и обновите секрет.
