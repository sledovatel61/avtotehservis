# Фото работ /manage/

Обычная статика, файлы загружаются относительными путями; сборка и сторонние библиотеки не нужны. Вход — fine-grained GitHub PAT (только Contents: Read and write); в localStorage хранится только `ats-gh-token`. Несохранённые данные и исходные фото живут только в памяти вкладки.

- `app.js` — экраны, состояние черновика, проверки, операции с кадрами.
- `store.js` — контракт и копия списка услуг из `site/src/server/seed-data.ts` (на сервере `services.ts` читает их из БД; `kondicioner` исключён).
- `editor.js` — canvas-редактор, кодирование трёх вариантов с удалением метаданных.
- `github.js` — API GitHub, проверка версии JSON, Git Data API и один повтор при конфликте ref.

Если `site/content/cases.json` в `preview/github-pages` отсутствует, интерфейс показывает пустой список после проверки доступа к ветке. При первом сохранении JSON версии 1 создаётся вместе с фотографиями одним коммитом. Публикация всегда идёт в эту ветку; при одновременном изменении редактируемого кейса автоматическое перезаписывание запрещено. Исходники ранее сохранённых кадров недоступны: при повторном редактировании используется вариант 1600. URL обложек и ссылка на сайт относительные, для Pages с префиксом.

Данные проверяются в `store.js` по ограничениям `site/src/shared/cases-schema.ts`; при изменении схемы обновите и эти ограничения. Варианты кадров и JSON отправляются blob-ами, затем создаются дерево от текущего base tree, один commit с текущим родителем и нефорсированное обновление ref. При конфликте данные перечитываются, одна повторная попытка не перезаписывает изменённый кейс. Статус Actions читается отдельно, без токена.

Не добавляйте зависимости, CDN или запросы на сторонние хосты; не храните токен вне `ats-gh-token` в localStorage и не меняйте контракт JSON без согласования с витриной. Не публикуйте этот файл из `public/manage/`. Атрибут `data-preview` оставлен в HTML, поскольку текущий `check-pages.mjs` требует его у всех страниц.
