# 02. Техническое направление

Документ фиксирует **рекомендуемый** стек и архитектуру. Агент №4 вправе аргументированно оспорить любое решение — но не «потому что модно», а с цифрами: вес, скорость разработки, стоимость владения, риски в РФ.

Версии проверены по npm registry 21.10.2026.

**Альтернативы и почему не они:**

| Вариант | Плюсы | Минусы | Вердикт |
|---|---|---|---|
| Astro 7 + React-острова | Лучший статический вес | Нужен отдельный бэкенд для админки и заявок, два деплоя | Запасной вариант, если перф станет критичнее скорости разработки |
| WordPress + ACF | Знаком владельцу, дешёвый контент | Плагины, безопасность, тяжёлый фронт, кастомная анимация через костыли | Нет |

| Nuxt/Vue | Хороший SSR | Нет выгоды для этой команды, экосистема Radix/Motion беднее | Нет |

**Почему не «просто HTML+PHP»:** админка, миграции, загрузка медиа, роли и очереди — это уже приложение; самописный PHP-бэкенд дороже в поддержке и рискованнее по безопасности.

## 4. API

| Метод | Путь | Назначение | Защита |
|---|---|---|---|
| POST | `/api/leads` | создать заявку из квиза | Zod, honeypot, time-trap, rate limit 5/10 мин на IP, SmartCaptcha по флагу |
| GET | `/api/health` | health-check | — |
| POST | `/api/upload` | загрузка медиа | сессия, MIME + magic bytes, лимиты |
| PATCH | `/api/media/:id` | порядок/публикация/подписи | сессия |
| POST | `/api/reviews/:id/moderate` | модерация | сессия |
| POST | `/api/auth/*` | вход, 2FA | Auth.js, rate limit 10/15 мин |

Правила:
- Идемпотентность: `publicId` (nanoid) генерируется на клиенте один раз за попытку; повторная отправка не создаёт дубль.
- Ответ API: `{ ok: true, leadId }` или `{ ok: false, code, fieldErrors }` — без стектрейсов.
- Все входные данные проходят Zod; никаких `any` в контрактах.
- Логи без ПД: телефон маскируется, VIN хэшируется в логах.

## 5. Квиз: технические детали

- Состояние — в `useReducer` + `localStorage` (черновик), сброс после успеха.
- Шаги — массив конфигов, ветвление через `next(step, answers)`, а не хардкод.
- Прогресс: «Шаг 3 из 6», без процентов, которые скачут при ветвлении.
- Валидация на шаг, не на всю форму; ошибка — под полем + `aria-describedby`.
- VIN: 17 символов, латиница без I/O/Q, маска, uppercase, «не знаю VIN» — валидный выбор.
- Марка: поиск по локальному списку (~60 популярных в РФ) + «другая» + свободный ввод.
- Телефон: маска `+7 (___) ___-__-__`, валидация по 10–11 цифрам, нормализация в E.164.
- Отправка: `fetch` с `AbortController` 15 с, повтор по кнопке, статус «Отправляем… / Готово / Не ушло — позвоните».
- Доступность: `fieldset`/`legend`, `role="group"`, фокус на заголовке шага, клавиатура, скринридер.
- Аналитика: `quiz_start`, `quiz_step_{n}`, `quiz_branch_{type}`, `quiz_submit`, `quiz_success`, `quiz_error` + время шага.

## 6. Медиа-пайплайн

**Загрузка (админка):**
1. Drag&drop или выбор файла, превью, прогресс.
2. Лимиты: фото jpg/png/webp/heic ≤ 20 МБ, видео mp4/mov ≤ 150 МБ (или ссылка на VK Video).
3. Проверка magic bytes, а не расширения.
4. `sharp`: авто-поворот по EXIF, strip метаданных, 3 размера (480/960/1600 по длинной стороне), AVIF + WebP.
5. Видео: ffmpeg извлекает кадр на 1-й секунде → постер, и сохраняет длительность; транскодинга нет.
6. Оригинал сохраняется на диск, варианты — рядом; в БД — ключи.
7. Публикация: обязательные поля — тип, услуга, заголовок; alt генерируется автоматически из заголовка, но редактируется.

**Отдача:** Nginx, `Cache-Control: public, max-age=31536000, immutable` для хэшированных имён, `Accept`-негоциация AVIF/WebP, `Content-Disposition: inline`.

**Ограничения:** суммарный объём — 20 ГБ, после — миграция на S3 (Timeweb Object Storage) без изменения кода (абстракция `storage`).

## 7. Админка

Экраны:
1. **Дашборд** — новые заявки, доставка уведомлений, последние публикации, быстрые действия.
2. **Заявки** — таблица (дата, имя, телефон, авто, услуга, статус), фильтры, поиск, карточка, заметки, смена статуса, экспорт CSV, повторная отправка уведомления.
3. **Галерея** — сетка, загрузка, drag&drop сортировка, мультивыбор, публикация/скрытие, подписи, привязка к услуге.
4. **Отзывы** — очередь модерации, публикация, закрепление, ответ владельца.
5. **Услуги** — заголовки, описания, «от», порядок.
6. **Настройки** — телефоны, часы, мессенджеры, сезонный баннер, SMTP, Telegram, ID Метрики.
7. **Пользователи** — приглашение редактора, роли, 2FA.

UX-требования: работает с телефона, крупные кнопки, «Сохранить» всегда внизу экрана, автосохранение черновика, подтверждение удаления, undo для сортировки, пустые состояния с подсказкой.

## 8. Интеграции

### E-mail
- Провайдер: **Unisender Go** (РФ, хорошая доставляемость) или **Яндекс 360 для бизнеса**; резерв — SMTP хостера.
- Настройки домена: SPF, DKIM, DMARC (`p=quarantine`), обратный DNS.
- Письмо: тема `[Заявка] {услуга} — {марка} — {имя}`, HTML-шаблон + plain-text, Reply-To клиента (если указан e-mail), кнопка «Позвонить», ссылка на заявку в админке.
- Получатели: 1–3 адреса, настраиваются в админке.

### Telegram
- Бот через @BotFather, токен в `.env`, `chat_id` — из `getUpdates` после `/start`.
- Сообщение: HTML, до 8 строк, кнопки «Открыть заявку», «Позвонить».
- **Минимизация ПД:** в Telegram уходит имя (сокращённое), авто, услуга, срочность и ссылка в админку; телефон — маскированный (`+7 *** 123-45-67`). Полные данные — в письме и админке. Это снижает риски по трансграничной передаче.
- Ретраи: 3 попытки с backoff (10 с, 60 с, 5 мин), затем `Outbox.status=failed` + письмо админу.
- Если Telegram недоступен — заявка всё равно в БД и на почте.

### Антиспам
1. Honeypot-поле (скрыто от людей, не `display:none` для ботов — лучше `position:absolute;left:-9999px`).
2. Время заполнения < 4 с → спам.
3. Rate limit: 5 заявок / 10 мин / IP, 20 / час.
4. Яндекс SmartCaptcha — включается флагом в настройках, если спам пошёл.
5. Дубликат по `(phoneHash, hourBucket)` — мягкий баннер «Мы уже получили заявку».

### Карты и мессенджеры
- Яндекс.Карты (iframe-конструктор или JS API с ключом), кнопка «Построить маршрут» (`yandex.ru/maps/?rtext=~47.193068,39.648295`).
- WhatsApp `https://wa.me/79289065700`, Telegram `https://t.me/...` — номера и ссылки в настройках.
- VK Video — для длинных роликов.

## 9. Инфраструктура и деплой

**Хостинг:** VPS в РФ — Timeweb Cloud / Beget / Reg.ru, 2 vCPU, 4 ГБ RAM, 80 ГБ NVMe (~800–1500 ₽/мес). Причина: 152-ФЗ, скорость в РФ, отсутствие проблем с оплатой.

```
docker-compose.yml
  app      (Next standalone, 3000)
  db       (postgres:17, volume pgdata)
  nginx    (80/443, volumes: certs, uploads, static)
  certbot  (renew)
  backup   (cron: pg_dump + tar uploads → S3/локально)
```

- CI: GitHub Actions — `typecheck`, `lint`, `test`, `build`; деплой по тегу через SSH (`docker compose pull && up -d`) или `git pull` + rebuild.
- Домен: A-запись на IP, `www` → редирект на apex, HSTS.
- `.env.example` в репозитории, реальные секреты — только на сервере.
- Бэкапы: ежедневно, хранение 30 дней, раз в месяц — проверка восстановления.
- Мониторинг: Uptime Kuma (или healthcheck-бот) → алерт в Telegram; Sentry/GlitchTip — ошибки; `docker logs` с ротацией.
- Деплой без простоя: `docker compose up -d --no-deps app` + health-check, откат на предыдущий тег.

**Ориентир по работам:**

| Этап | Часы |
|---|---|
| Дизайн-система и мокап → компоненты | 16–24 |
| Главная (секции, анимации) | 24–32 |
| Квиз (логика, валидация, аналитика) | 12–16 |
| Галерея + лайтбокс + видео | 10–14 |
| Отзывы | 6–8 |
| Админка (CRUD, загрузка, роли) | 24–32 |
| Интеграции (SMTP, TG, очередь, антиспам) | 10–14 |
| SEO, метрика, доступность, перф | 10–14 |
| Деплой, бэкапы, документация | 8–12 |
| **Итого** | **120–166 ч** |

## 10. Перф-бюджет

| Метрика | Бюджет | Как контролируем |
|---|---|---|
| JS (initial, gzip) | ≤ 250 КБ | `@next/bundle-analyzer`, запрет тяжёлых библиотек |
| CSS | ≤ 40 КБ | Tailwind purge, без UI-китов целиком |
| Шрифты | ≤ 120 КБ | 2 гарнитуры, 4 начертания, woff2, subset cyrillic+latin |
| LCP | < 2,2 с (4G) | Приоритет hero-изображения, без видео на первом экране |
| INP | < 200 мс | Минимум клиентских компонентов, `startTransition` |
| CLS | < 0,05 | Явные размеры медиа, резерв под шрифты |
| TBT | < 200 мс | Без гидрации лишнего |
| Lighthouse mobile | ≥ 90 | CI-проверка на превью |

Если не влезаем: сначала убираем анимации на скролле, потом карусели, потом тяжёлые шрифты. Видео на первом экране — никогда.

## 11. SEO

- `metadata` API: title/description на каждую страницу, canonical, OG/Twitter, `lang="ru"`.
- JSON-LD: `AutoRepair` (адрес, гео, часы, телефон, услуги, `aggregateRating` — только с реальным источником), `FAQPage`, `Service`, `ImageObject`, `BreadcrumbList`.

- Яндекс.Вебмастер + Метрика, Google Search Console.
- Локальное SEO: единый NAP, ссылки на карточки, отзывы, микроразметка часов.

- Тексты — 800–1200 слов осмысленного контента на главной (без «SEO-воды»).

## 12. Безопасность и 152-ФЗ

| Риск | Мера |
|---|---|
| Утечка ПД | HTTPS, шифрование бэкапов, доступ по SSH-ключам, минимум данных |
| Брутфорс админки | rate limit, argon2id, 2FA TOTP, блокировка после 10 попыток |
| XSS | React-экранирование, санитайз HTML в отзывах, CSP |
| Загрузка вредоносных файлов | проверка magic bytes, переименование, отдача с `Content-Type` из белого списка, без исполнения |
| CSRF | SameSite=Lax + проверка Origin в Server Actions |
| Спам | honeypot, time-trap, rate limit, SmartCaptcha |
| Потеря заявок | БД + Outbox + ретраи + алерт |

**152-ФЗ:**
- Чекбокс согласия — обязательный, со ссылкой на политику, без предустановки.
- Политика обработки ПД — отдельная страница, реквизиты оператора.
- Цели: обработка заявки и связь; срок хранения — 12 месяцев; удаление по запросу.
- Хостинг в РФ; Google Analytics не используем (трансграничная передача) — только Яндекс.Метрика.
- Telegram: минимизация (см. выше), в политике — упоминание канала уведомлений.
- Уведомление в Роскомнадзор об обработке ПД — задача владельца, добавляем в чек-лист запуска.
